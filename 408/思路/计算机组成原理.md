# 2 存储系统
## 2.1 Cache
### 2.1.1 Cache 行组成
- **有效位**
- **脏位**
- **替换算法控制位**
- **标记位**：位数 = 地址位数 - Cache组位数 - Cache块内偏移位数
- **数据位**

### 2.1.2 物理地址组成

| 标记  | 组号  | 块内偏移 |
| :-- | :-- | :--- |

- 当标记 / 组号 位数不为 4 的倍数时，通过高位补 0，表示为 16 进制数。

## 2.2 SRAM 和 DRAM
1. **SRAM**：只要不断电，信息就不会消失，因此读操作无需再生。
2. **DRAM**：需要定时刷新以维持数据，读操作为破坏性读出，读取后需要立即再生。
	1. **刷新**：
		1. 以**行**为单位。
		2. 不需要 CPU 控制，但影响访存。
		3. 占用**1个访问周期**。
	2. **地址复用**：将地址拆分为行地址和列地址，地址引脚总数仅需地址总位数的一半。

## 2.3 非易失性存储器
1. **ROM**
	1. **MROM**：掩模式ROM，用户不可修改。
	2. **PROM**：一次可编程ROM，允许用户进行一次编程。
	3. **EPROM**：可擦除可编程ROM，支持多次编程
2. **Flash** 存储器/闪存：可多次擦除，写入速度慢。
3. **SSD**：固态硬盘

# 4 CPU
## 4.1 指令周期阶段
### 4.1.1 RISC

| 阶段名称        | 核心操作                          |
| :---------- | :---------------------------- |
| **取指**      | 从主存取出指令代码放入 IR，同时 PC 自动加 "1"。 |
| **译码/读寄存器** | 识别操作码和寻址方式，从寄存器中读取操作数，提取立即数。  |
| **执行**      | 根据操作码和操作数进行相应的运算处理。           |
| **访存**      | 若需访问主存，则通过**Cache**或**主存**。   |
| **写回**      | 将结果写回通用寄存器堆                   |
| **中断响应**    | 检查中断请求，保存程序断点（压栈）。            |

### 4.1.2 CISC
CISC 各个阶段都能进行访存和写回，故通常仅分为四个阶段

| 阶段名称        | 核心操作                          |
| :---------- | :---------------------------- |
| **取指**      | 从主存取出指令代码放入 IR，同时 PC 自动加 "1"。 |
| **译码/读寄存器** | 识别操作码和寻址方式，从寄存器中读取操作数，提取立即数。  |
| **执行**      | 根据操作码和操作数进行相应的运算处理。           |
| **中断响应**    | 检查中断请求，保存程序断点（压栈）。            |

## 4.2 中断处理流程
1. **中断隐指令**（由**硬件**自动完成）：  
   * **关中断**：将中断允许标志置0，防止在保存断点和现场时被新中断打断。  
   * **保存断点**：将程序计数器和程序状态字压入堆栈保存，以便后续恢复。  
   * **引出中断服务程序**：识别中断源，将服务程序的入口地址送入程序计数器。  
2. **中断服务程序**（由**软件**执行完成）：  
   * **保存现场和屏蔽字**：将通用寄存器中的重要数据压栈。  
   * **开中断**（仅多重中断存在此步）：允许响应更高优先级的中断请求。  
   * **执行真正的服务逻辑**：处理具体的中断事件。  
   * **关中断**（仅多重中断存在此步）：防止恢复现场的过程中被再次打断。  
   * **恢复现场和屏蔽字**：从栈中弹出原先保存的通用寄存器内容。  
   * **开中断并返回**：执行中断返回指令，恢复断点，回到原程序继续执行。

## 4.3 微程序控制器
### 4.3.1 微程序数量的计算
* 如果某指令系统中有 $n$ 条机器指令，则 CM 中微程序的个数**至少是 $n+1$ 个**。
    * $n$ 个不同指令的执行周期微程序段 + $1$ 个公用的取指周期微程序段。
    * **间接寻址**和**中断周期**也是公用的，但不是必须的。

### 4.3.2 微指令地址的形成方式
1.  **断定法(下地址法)**：当前执行的微指令中的**下地址字段**为下一条微指令地址。
2.  **增量计数法**：通过 $PC + 1$ 的方式找到下一条微指令。
3.  **微程序入口地址**：将指令操作码送入微地址形成部件，由其指明对应微程序的首地址。

## 4.4 流水线冒险
1. **数据冒险**：后续指令必须等待前一条指令 `WB` 后，才能 `ID`。
2. **控制冒险**：遇到条件转移指令等改变程序计数器值的指令，导致原有的指令执行流断裂。
3. **资源冒险**：多条指令在同一时刻争用同一个硬件资源。

# 5 总线
## 5.1 类型
1. **内部总线**：连接寄存器和 ALU。
2. **系统总线**：连接功能部件。
	1. **数据总线**：传输指令、操作数、状态字和中断类型号等
	2. **地址总线**：单向。
	3. **控制总线**：传输协调与控制信号。
3. **I/O 总线**：连接主机与内部的 I/O 控制器。
4. **通信总线**：连接主机与外部 I/O 设备，或不同计算机。

# 6 I / O
## 6.1 DMA
### 6.1.1 传送方式

| 传送方式            | 工作原理                                             | 优点                             | 缺点                           | 适用场景                |
| :-------------- | :----------------------------------------------- | :----------------------------- | :--------------------------- | :------------------ |
| **停止CPU访存**     | I/O设备发出请求时，CPU放弃总线控制权，直到整块数据传送完成。                | 控制逻辑简单。                        | DMA访存期间，CPU基本处于空闲状态，资源利用率较低。 | 数据传输速率极高的大批量成组数据传送。 |
| **周期挪用**        | I/O设备挪用一个主存周期进行数据传送。当I/O与CPU同时请求访存，CPU暂时放弃总线控制权。 | 既满足I/O数据传送需求，又较好地发挥了CPU与主存的效率。 | 每次挪用均需申请并释放总线控制权，带来一定开销。     | 多数高速I/O设备（单字传送方式）。  |
| **DMA与CPU交替访存** | 将一个CPU工作周期划分为两个子周期，交替供CPU和DMA访存。                 | 无须动态申请或释放总线控制权，数据传送速率高。        | 硬件控制逻辑较为复杂。                  | CPU工作周期大于主存存储周期的场景。 |
