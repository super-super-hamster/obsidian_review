# 1 数据的表示和运算
## 1.1 浮点数
### 1.1.1 IEEE 754 浮点数格式标准

| 类型      | 总位数     | 符号位 | 阶码      | 尾数      | 偏置值      |
| :------ | :------ | :-- | :------ | :------ | :------- |
| **单精度** | **32位** | 1位  | **8位**  | **23位** | **127**  |
| **双精度** | **64位** | 1位  | **11位** | **52位** | **1023** |

## 1.2 类型转换
- **长类型转短类型**：位截断。可能由于位截断导致转换前后的正负不同。
- **相同字长转换**：二进制位不改变，仅改变解释方式。
- **短类型转长类型**：若源数据为有符号数，则进行符号扩展，否则零扩展。

## 1.3 运算
1. 若长度不同，则将长度更短的符号扩展至长度与长度更长的相同，类型改为长度更长的。
2. 若长度相同，但类型不同，将有符号转为无符号(仅改变解释方式)。

## 1.4 浮点数
### 1.4.1 舍入
在对阶和右规过程中，尾数右移可能导致低位丢失。为保证精度，将移出的低位保留用于中间计算。
- **保护位**：尾数最低有效位后的第一位。
- **舍入位**：尾数最低有效位后的第二位。
- **粘滞位**：只要舍入位之后被移除的位中至少存在一个 1，粘滞位就为 1，否则为 0。
- **就近舍入**：选择最接近真实值的可表示的那个数，若恰好位于两个可表示数中间，则选择最低有效位为 0 的。
	1. 若保护位为 0，则直接舍去。
	2. 若保护位为 1，且舍入位和粘滞位中至少一个为 1，则尾数 +1。
	3. 若保护位为 1，舍入位和粘滞位都为 0，则在尾数末位为 1 时 +1。

### 1.4.2 非规格化浮点数
1. **阶码**：固定为 $1 - \text{偏置值}$。
2. **尾数**：小数点前补 0。

### 1.4.3 特殊浮点数
| 阶码      | 尾数        | 值        |
| :------ | :-------- | :------- |
| **全 0** | **全 0**   | 正零或负零    |
| **全 0** | **不全为 0** | 非规格化数    |
| **全 1** | **全 0**   | 无穷 (INF) |
| **全 1** | **不全为 0** | 非数（NaN）  |

## 1.5 无符号整数乘法电路
计算 $X \times Y$
1. 乘积寄存器置 0。
2. 将 $[P,Y]$ 视作一个整体 $Z$。
3. 若 $Z$ 的最低位为 1，则将 $X$ 加到 $Z$ 的高 n 位。
4. 将 $Z$ 逻辑右移一位，返回步骤 3，直到执行 n 次。
5. 若 $P$ 不为 0，则说明发生溢出。

## 1.6 无符号整数除法电路
计算 $X \div Y$
1. 若 $X$ 不足 $2n$ 位，则高位补 0 至 $2n$ 位。
2. 余数寄存器置 0。
3. 将 $[R,X]$  视作一个整体 $Z$。
4. 将 $Z$ 逻辑左移一位。
5. 计算 $R-Y=C$
	1. 若 $C \ge 0$，则 $X+1,R=C$
	2. 若 $C < 0$，则执行 $R=R+Y$，恢复余数
6. 返回步骤 4，直到执行 n 次。
7. 商保存在 $X$ 中，余数保存在 $R$ 中。

# 2 存储系统
## 2.1 Cache
### 2.1.1 Cache 行组成
- **有效位**
- **脏位**
- **替换算法控制位**
- **标记位**：位数 = 地址位数 - Cache组位数 - Cache块内偏移位数
- **数据位**

### 2.1.2 物理地址组成

| 标记  | 组号  | 块内偏移 |
| :-- | :-- | :--- |

### 2.1.3 写策略
1. **写命中**
	1. **全写法**：同时向 Cache 和主存写入数据。
	2. **回写法**：仅修改 Cache 中的副本。只有当该 Cache 行被替换时，才将其写回主存。
2. **写不命中**
	1. **非写分配法**：直接向主存写入数据，不将该块调入 Cache。
	2. **写分配法**：先将主存中的目标块调入 Cache，然后在 Cache 中进行修改。
3. 通常全写法与非写分配法搭配，回写法与写分配法搭配。

## 2.2 SRAM 和 DRAM
1. **SRAM**：只要不断电，信息就不会消失，因此读操作无需再生。
2. **DRAM**：需要定时刷新以维持数据，读操作为破坏性读出，读取后需要立即再生。
	1. **刷新**：
		1. 以**行**为单位。
		2. 不需要 CPU 控制，但影响访存。
		3. 占用 **1 个访问周期**。
	2. **地址复用**：将地址拆分为行地址和列地址，地址引脚总数仅需地址总位数的一半。

## 2.3 非易失性存储器
1. **ROM**
	1. **MROM**：掩模式 ROM，用户不可修改。
	2. **PROM**：一次可编程 ROM，允许用户进行一次编程。
	3. **EPROM**：可擦除可编程 ROM，支持多次编程。
2. **Flash** 存储器/闪存：可多次擦除，写入速度慢。
	1. **SSD**：固态硬盘
	2. **U 盘**

## 2.4 主存和 CPU 之间的连接
1. **位扩展**：将多块芯片的**地址线**、**读写控制线**、**片选线**并联。各芯片的数据线分别引出，连接到数据总线的不同位上。
2. **字扩展**：将多块芯片的**地址线**连接到地址总线的低位、**数据线**、**读写控制线**并联。
3. **字位扩展**：先进行位扩展，再进行字扩展。

## 2.5 多模块存储器
### 2.5.1 低位交叉编制启动方式
1. **轮流启动**：每个模块一次读/写的位数恰好等于数据总线位数时使用。可提高带宽。
2. **同时启动**：所有存储模块一次并行读/写的总位数恰好等于存储器数据总线宽度时使用。每次只能读取地址对齐的块。

## 2.6 磁盘存储器
- **条带化**：把逻辑上连续的数据分散到多个磁盘上，让多个磁盘**并行工作**，从而提高存储系统的**吞吐率和响应速度**。

## 2.7 SSD
- **读/写的基本单位**：页。
- **擦除的基本单位**：块。只有整个块被擦除干净后才能向其中的页写入新数据。
- **闪存翻译层**：负责逻辑块号到物理地址的转换。

| 名称         | 实现方式                                                      |
| :--------- | :-------------------------------------------------------- |
| **动态磨损均衡** | 写入数据时，优先选择累计擦除次数较少的**新闪存块**。                              |
| **静态磨损均衡** | SSD监测并自动进行数据分配与迁移。将**读多写少**的数据迁移到**老旧块**，让**新块**承担更多的写任务。 |

# 4 CPU
## 4.1 指令周期阶段
### 4.1.1 RISC

| 阶段名称        | 核心操作                          |
| :---------- | :---------------------------- |
| **取指**      | 从主存取出指令代码放入 IR，同时 PC 自动加 "1"。 |
| **译码/读寄存器** | 识别操作码和寻址方式，从寄存器中读取操作数，提取立即数。  |
| **执行**      | 根据操作码和操作数进行相应的运算处理。           |
| **访存**      | 若需访问主存，则通过**Cache**或**主存**。   |
| **写回**      | 将结果写回通用寄存器堆                   |
| **中断响应**    | 检查中断请求，保存程序断点（压栈）。            |

### 4.1.2 CISC
CISC 各个阶段都能进行访存和写回，故通常仅分为四个阶段
1. **取指**
2. **译码/读寄存器**
3. **执行**
4. **中断响应**

## 4.2 中断
- 通过 `INTR` 信号线发出的是可屏蔽中断
- 通过 `NMI` 信号线发出的是不可屏蔽中断
- **中断服务程序入口地址**：中断服务程序第一条指令在物理内存中的物理地址。
- **中断向量**：存放“中断服务程序入口地址”的内存单元。
- **中断向量地址**：中断向量表的表项在内存中的物理地址。
### 4.2.1 中断响应过程
1. 向中断控制器发出中断请求
2. 中断控制器将优先级最高的中断请求的中断类型号发给 CPU
3. CPU 在当前指令执行结束后响应

### 4.2.2 中断处理流程
1. **中断隐指令**（由**硬件**自动完成）：  
   * **关中断**：将中断允许标志置0。  
   * **保存断点**：将**程序计数器**和**程序状态字**压入堆栈保存。  
   * **引出中断服务程序**：
	   * CPU 通过中断类型号在中断向量表中查找到中断向量。
	   * 通过中断向量找到中断服务程序入口地址。
1. **中断服务程序**（由**软件**执行完成）：  
   * **保存现场和屏蔽字**：将通用寄存器中的重要数据压栈。  
   * **开中断**（仅多重中断存在此步）：允许响应更高优先级的中断请求。  
   * **执行真正的服务逻辑**：处理具体的中断事件。  
   * **关中断**（仅多重中断存在此步）：防止恢复现场的过程中被再次打断。  
   * **恢复现场和屏蔽字**：从栈中弹出原先保存的通用寄存器内容。  
   * **开中断并返回**：执行中断返回指令，恢复断点，回到原程序继续执行。

## 4.3 微程序控制器
### 4.3.1 微程序数量的计算
* 如果某指令系统中有 $n$ 条机器指令，则微程序的个数**至少是 $n+1$ 个**。
    * $n$ 个不同指令的执行周期微程序段 + $1$ 个公用的取指周期微程序段。
    * **间接寻址**和**中断周期**也是公用的，但不是必须的。

### 4.3.2 微指令地址的形成方式
1.  **断定法(下地址法)**：当前执行的微指令中的**下地址字段**为下一条微指令地址。
2.  **增量计数法**：通过 $PC + 1$ 的方式找到下一条微指令。
3.  **微程序入口地址**：将指令操作码送入微地址形成部件，由其指明对应微程序的首地址。

## 4.4 指令流水线
### 4.4.1 流水线冒险
1. **数据冒险**：后续指令必须等待前一条指令 `WB` 后，才能 `ID`。
2. **控制冒险**：遇到条件转移指令等改变程序计数器值的指令，导致原有的指令执行流断裂。
3. **资源冒险**：多条指令在同一时刻争用同一个硬件资源。

### 4.4.2 高级流水线技术
| 名称              | 工作原理                      |
| :-------------- | :------------------------ |
| **超标量流水线技术**    | 在**同一个时钟周期**内，并行发射出多条独立指令 |
| **超流水技术**       | 将一个机器周期细分为多个更短的时间段        |
| **超长指令字/静态多发射** | 将多条可并行执行的指令打包成一条超长指令字     |

# 5 总线
## 5.1 类型
1. **内部总线**：连接寄存器和 ALU。
2. **系统总线**：连接功能部件。
	1. **数据总线**：传输指令、操作数、状态字和中断类型号等
	2. **地址总线**：单向。
	3. **控制总线**：传输协调与控制信号。
3. **I/O 总线**：连接主机与内部的 I/O 控制器。
4. **通信总线**：连接主机与外部 I/O 设备，或不同计算机。

## 5.2 总线定时
### 5.2.1 半同步定时
- **实现方式**：增设一条 **Wait 信号线**。主设备通过检测 Wait 信号插入等待周期，直到有效才进行数据读写。
- **缺点**：系统时钟频率受限于最慢设备。

### 5.2.2 异步定时

| 互锁方式    | 主设备发“请求”后                      | 从设备发“回答”后                  | 可靠性             |
| :------ | :----------------------------- | :------------------------- | :-------------- |
| **不互锁** | 预设延时后自动撤销“请求”，**无需等待“回答”**。    | 预设延时后自动撤销“回答”，无需确认“请求”已撤销。 | 最低，容易丢包         |
| **半互锁** | **必须收到**“回答”信号后，才撤销“请求”。（存在互锁） | 预设延时后自动撤销“回答”。             | 中等              |
| **全互锁** | **必须收到**“回答”信号后，才撤销“请求”。       | **必须确认**“请求”已撤销后，才撤销“回答”。  | **最高**，确保数据绝对同步 |

### 5.2.3 分离式定时
1. 主设备申请发地址/命令后即释放总线。
2. 从设备准备好数据后主动申请总线，**以主设备身份**发回数据。

## 5.3 数据传输方式
- **非突发传输**：每次仅传输一个数据单元。每次传输都必须经历完整的“发地址 $\rightarrow$ 等待 $\rightarrow$ 传数据”流程。
- **突发传输**：连续传输多个数据单元。主设备仅在事务开始时发送**首地址**，后续地址由硬件自动递增生成。

# 6 I / O
## 6.1 DMA
- 使主存既可被 CPU 访问，又可被外设访问。
### 6.1.1 数据传输过程
1. 驱动程序配置 DMA，完成预处理
2. 外设发出 DMA 请求
3. DMA 控制器向 CPU 发出总线请求
4. CPU 在当前总线周期结束后响应总线请求，响应总线请求后 DMA 控制器接管总线
5. 进行数据传输。
	1. 若使用周期挪用方式，每次释放总线后都要回到第 1 步，直到数据传输完成。
6. 一组数据传输结束后，向 CPU 发出中断请求

### 6.1.2 传送方式

| 传送方式              | 工作原理                                                  | 优点                                 | 缺点                             | 适用场景                 |
| :---------------- | :---------------------------------------------------- | :--------------------------------- | :----------------------------- | :------------------- |
| **停止 CPU 访存**     | I/O 设备发出请求时，CPU 放弃总线控制权，直到整块数据传送完成。                   | 控制逻辑简单。                            | DMA 访存期间，CPU 基本处于空闲状态，资源利用率较低。 | 数据传输速率极高的大批量成组数据传送。  |
| **周期挪用**          | I/O 设备挪用一个主存周期进行数据传送。当 I/O 与 CPU 同时请求访存，CPU暂时放弃总线控制权。 | 既满足 I/O 数据传送需求，又较好地发挥了 CPU 与主存的效率。 | 每次挪用均需申请并释放总线控制权，带来一定开销。       | 多数高速 I/O 设备（单字传送方式）。 |
| **DMA 与CPU 交替访存** | 将一个 CPU 工作周期划分为两个子周期，交替供 CPU 和 DMA 访存。                | 无须动态申请或释放总线控制权，数据传送速率高。            | 硬件控制逻辑较为复杂。                    | CPU 工作周期大于主存存储周期的场景。 |
