# 1 进程
## 1.1 进程互斥需遵循的原则
1.  **空闲让进**：临界区空闲时，应允许一个请求进入临界区的进程立即进入。
2.  **忙则等待**：当已有进程进入临界区时，其他试图进入的进程必须等待。
3.  **有限等待**：对请求访问的进程，应保证能在**有限时间**内进入临界区，即不能被无限插队（防止**进程饥饿**）。
4.  **让权等待**：当进程不能进入临界区时，释放处理机（防止**忙等待**）。

## 1.2 死锁
### 1.2.1 四个必要条件
* **互斥条件**：资源必须**互斥使用**。
* **不剥夺条件**：**不能由其他进程强行夺走**，只能主动释放。
* **请求和保持条件**：进程**保持了至少一个资源**，提出新的资源请求，而该资源被其他进程占有。
* **循环等待条件**：存在一种进程资源的**循环等待链**。

### 1.2.2 死锁预防
破坏产生死锁的四个必要条件中的至少一个，以确保系统永远不会进入死锁状态。

### 1.2.3 死锁避免
在资源分配过程中，系统通过算法预测此次分配是否会导致系统进入**不安全状态**，从而决定是否允许分配。 

## 1.3 进程通信
1. **共享存储**：操作系统在内存中划出一块互斥访问的共享存储区。
2. **消息传递**：通过格式化的消息进行传递信息。
3. **管道通信**：
	1. 在内存中开辟的一个**大小固定的内存缓冲区**。
	2. 半双工通信
	3. 仅允许**一个写进程**或**一个读进程**对其操作。
4. **信号**：
	1. 进程从内核态转为用户态时处理信号。
	2. 暂停进程信号和终止进程信号不能阻塞，也不能由用户自定义函数处理。

## 1.4 调度算法
### 1.4.1 多级反馈队列
* **设置多级队列**：优先级逐级降低，时间片逐级增大。
* **新进程流程**：
    * 新进程进入**第 1 级**队列队尾。
    * 按 **FCFS** 原则排队等待被分配时间片。
    * 若在时间片内未执行完，则**降级**进入**下一级**队列队尾。
* **调度时机**：只有第 $k$ 级队列为空时，才会为第 $k+1$ 级队头的进程分配时间片。

## 1.5 管程
- **条件变量**：支持`wait`和`signal`。
	- 其中，`wait` 和 `signal` 操作与PV操作并不相同，`wait` 仅负责将线程加入等待队列，`signal` 仅负责唤醒等待队列中的一个线程。

## 2.2 分页存储管理
### 2.2.1 访存操作
1. **查 TLB**
	1. 若命中，则直接获得物理地址
	2. 若未命中，则需要查找内存中的页表
2. **查页表**
	1. 若有效，则获得物理地址
	2. 若无效，**处理缺页异常**
3. **查 Cache**
	1. 若命中，则从 Cache 中取数
	2. 若未命中，则从主存中取块装入 Cache，并送入 CPU
- TLB 未命中，不一定需要访存，因为页表项也有可能在 Cache 中

## 2.3 页面置换算法
### 2.3.1 FIFO
存在 **Belady异常**

### 2.3.2 CLOCK
1. 为每个页面设置一个**访问位**（1表示最近访问过，0表示未访问）。
2.  扫描循环队列，若当前页面的访问位为 **1**，则将其置为 **0**，指针指向下一页。
3.  若当前页面的访问位为 **0**，则选择淘汰该页面。

### 2.3.3 改进型 CLOCK
1. 标记位为 $(访问位,修改位)$
2. 第一轮扫描，寻找$(0,0)$
3. 第二轮扫描，寻找$(0,1)$，并将所有扫描过的访问位置0
4. 第三轮扫描，重复第一轮操作
5. 第四轮扫描，重复第二轮操作

## 2.4 内存映射文件
- 在磁盘文件与进程的虚拟地址空间之间建立直接映射关系。将文件映射到进程虚拟地址空间的某一区域，此后便可像访问内存一样读/写文件。
- 通过将同一文件映射到多个通信进程的虚拟地址空间可实现进程间的通信。

## 2.5 其他
- **对换区**：采用**连续分配**，读写速度**快**。
- **文件区**：采用**离散分配**，读写速度**慢**。

# 3 文件
## 3.1 文件分配方式
1. **连续分配**
2. **链接分配**
	1. **隐式链接分配**：FCB中记录文件的**起始块号**和**结束块号**，每个磁盘块中保存指向下一个盘块的指针。
	2. **显示链接分配**：将用于链接的指针显式地存放在一张表中，即**文件分配表(FAT)**。
3. **索引分配**
	1. 为**每个文件**建立一张**索引表**，记录各逻辑块对应的物理块(类似页表)。
	2. 支持**随机访问**。
	3. **索引顺序分配**：
		1. 将记录分组，每组记录对应一个索引号。
		2. 组内无序，组件有序。
		3. 组内连续分配。
		4. 可减小索引表。

## 3.2 存储空间管理
1. **空闲表法**：为每个文件分配一个物理上连续的磁盘区域。系统为所有空闲区维护一张空闲表。
2. **空闲链表法**
3. **位示图法**
4. **成组链接法**
    * **索引块**：每组的第一个块。系统启动时读入内存，记录**下一组空闲盘块数**及**下一组所有空闲盘块号**。
	* **分配操作**：
	    1.  检查超级块中空闲数是否足够。
	    2.  若足够且非该组最后一个块时直接分配。
	    3.  若分配的是该组**最后一个空闲块**，需先将该块中的信息复制到索引块中，再进行分配。

## 3.3 文件共享
### 3.3.1 硬链接
- 所有文件的默认引用计数值为 1，即指向文件本身。
- 所有硬链接同一个文件共享引用计数值。

### 3.3.2 软链接
- 默认引用计数值为 1。
- 软链接文件本身相当于一个文件，拥有自己的 inode。

## 3.4 虚拟文件系统
* VFS 向**用户进程**提供统一标准的**系统调用**接口（如 `open`, `read`, `write`）。
* 当使用 `open` 系统调用**打开**一个文件时，VFS 会在**主存**中新建一个 `vnode`。无论底层是何种文件系统，VFS 都会将文件的相关元数据复制到 `vnode` 中，形成统一格式。

## 3.5 文件保护
### 3.5.1 访问控制
- **保存位置**：文件的**FCB**或**索引结点**中增加一张**访问控制表**（ACL）。

# 4 I / O
## 4.1 磁盘
### 4.1.1 每次读 / 写时间
- 每次读/写时间 = 寻道时间 + 平均旋转延迟 + 读取时间
	- 寻道时间 = 启动磁头臂 + 磁头移动时间
	- 平均旋转延迟 = 旋转半圈的时间
	- 读取时间 = 旋转一个扇区的时间

### 4.1.2 格式化
* **低级格式化 / 物理格式化**：将磁盘的各个磁道划分为**扇区**。
* **逻辑格式化 / 高级格式化**：在磁盘上建立**文件系统**。创建根目录文件，初始化用于存储空间管理的数据结构。

## 4.2 设备
### 4.2.1 设备独立性软件
* **主要功能**：
    1.  **提供统一接口**：向上层提供统一的系统调用（如 `read`/`write`）。
    2.  **设备保护**：检查用户对设备的访问权限。
    3.  **差错处理**：对设备产生的错误进行处理。
    4.  **设备分配与回收**：管理临界资源。
    5.  **数据缓冲区管理**：屏蔽设备间数据交换单位大小及传输速度的差异。
    6.  **逻辑设备映射**：建立**逻辑设备名**到**物理设备名**的映射，并选择对应的驱动程序。

### 4.2.2 设备驱动程序
**主要功能**：
* **硬件相关**
    * 将上层的通用命令（如 `read`/`write`）转化为设备能识别的**一系列硬件操作指令**。
    * 设置**设备寄存器**，检查设备状态。

### 4.2.3 设备分配管理
**1. 核心数据结构**
* **设备控制表 (DCT)**：每个**设备**一张。记录设备类型、标识符、状态、**指向控制器表 (COCT) 的指针**、重复执行次数、**等待队列队首指针**。
* **控制器控制表 (COCT)**：每个**控制器**一张。记录控制器的状态及管辖的设备信息。
* **通道控制表 (CHCT)**：每个**通道**一张。管理通道及其下属控制器。
* **系统设备表 (SDT)**：记录系统中**全部设备**的情况。每个表目包含：设备类型、物理设备名、**DCT 指针**、驱动程序入口。
**2. 设备分配的步骤**
1.  根据进程请求的**物理设备名**查找 **SDT**，找到对应的 **DCT**。
2.  **分配设备**：查看 DCT，若设备忙碌则挂入设备等待队列；若空闲则分配，并更新 DCT。
3.  **分配控制器**：根据 DCT 找到 **COCT**，若控制器忙碌则挂入控制器等待队列；若空闲则分配。
4.  **分配通道**：根据 COCT 找到 **CHCT**，若通道忙碌则挂入通道等待队列；若空闲则分配。

## 4.3 缓冲区
* **定义**：
    * $T$：数据从设备输入到缓冲区的时间。
    * $M$：数据从缓冲区传送到工作区的时间。
    * $C$：CPU处理一块数据的时间。

### 4.3.1 单缓冲
* **处理一块数据的平均耗时**：$$\text{平均耗时} = \max(T, C) + M$$

### 4.3.2 双缓冲
* **处理一块数据的平均耗时**：$$\text{平均耗时} = \max(T, C + M)$$

### 4.3.3 循环缓冲
* **机制**：将多个大小相等的缓冲区链接成一个**循环队列**。
    * **in 指针**指向下一个可以冲入数据的**空缓冲区**。
    * **out 指针**指向下一个可以取出数据的**满缓冲区**。

### 4.3.4 缓冲池
* **维护三种队列**：
    1.  **空缓冲队列**：装有空闲缓冲区。
    2.  **输入队列**：装满输入数据的缓冲区。
    3.  **输出队列**：装满输出数据的缓冲区。

## 4.4 SPOOLing
* **定义**：用**软件**的方式模拟脱机技术。SPOOLing 系统建立在**多道程序技术**之上。
* **组成**：
    1.  **输入井和输出井**：在**磁盘**上开辟的两个存储区域，用于暂存输入/输出设备的数据，并将输入/输出数据以文件形式保存，称为井文件。
    2.  **输入缓冲区和输出缓冲区**：在**内存**中开辟的缓冲区。输入缓冲区暂存由输入设备送来的数据，随后传送到输入井。输出缓冲区暂存从输出井读出的数据，随后传送到输出设备。
    3. **输入进程**：将输入设备的数据经输入缓冲区传送到输入井，当CPU需要输入数据时，直接从输入井读取。
    4. **输出进程**：将输出数据写入输出井，并在输出设备空闲时，井输出缓冲区将数据传送到输出设备。

## 4.5 其他
-  **I/O 端口**：设备控制器中可被CPU访问的寄存器。

# 5 其他
## 5.1 操作系统引导
1. **CPU激活与BIOS初始化**：CPU从ROM中读取并执行BIOS程序，BIOS初始化基本硬件，**建立中断向量表**。
2. **硬件自举与启动设备选择**：BIOS执行通电自检，之后选择首个有效的启动设备。
3. **加载主引导记录(MBR)**：BIOS将主引导记录加载到内存中。MBR包含引导代码和硬盘分区表。
4. **加载分区引导记录**：根据分区表找到活动分区后，将该分区的第一个扇区，即 引导记录 (PBR) 读入内存。
5. **加载操作系统初始化程序**：从根目录中找到 启动管理器。
