# 1 概述

## 1.1 计算机硬件的基本组成

### 1.1.1 冯·诺依曼计算机的六大特征

* **五大部件**：计算机硬件由**运算器**、**控制器**、**存储器**、**输入设备**、**输出设备**组成。
* **存储程序**：指令和数据同等地位存储在存储器中，可按**地址**寻访。
* **二进制表示**：指令和数据均用二进制代码表示。
* **指令结构**：由**操作码**（指明操作性质）和**地址码**（指明数据位置）组成。
* **顺序执行**：指令通常按顺序存放，指令流控制执行顺序。
* **以运算器为中心**：输入/输出设备与存储器之间的数据传送需通过运算器中转。

---
### 1.1.2 计算机的功能部件

* **输入设备**：将信息转换成机器能识别的形式。
* **输出设备**：将运算结果转换成人们熟悉的形式。
* **存储器**：存放数据和程序。
* **运算器**：进行**算术运算**和**逻辑运算**。
* **控制器**：指挥各部件协调工作，解析指令。

---
### 1.1.3 现代计算机结构

**1. 结构改进**
* **核心变化**：由“以运算器为中心”改为 **“以存储器为中心”**。
* **优势**：输入/输出设备的数据直接送入存储器，不再经过运算器中转，解放了运算器的时间，提高了效率。

**2. 硬件集成（CPU 与 主机）**
随着大规模集成电路的发展，硬件部件进行了逻辑上的合并：
* **CPU（中央处理器）** = **运算器** + **控制器**。
* **主机** = **CPU** + **主存储器**。
* **I/O 设备（外设）** = 输入设备 + 输出设备 + **辅助存储器**。

---
## 1.2 各个硬件的工作原理

### 1.2.1 运算器的工作原理

运算器用于实现算术运算（加减乘除）和逻辑运算（与或非）。核心部件是**ALU**。

#### 1.2.1.1 核心部件
* **ALU (算术逻辑单元)**：核心电路，完成具体的算术与逻辑运算。
* **ACC (累加器)**：存放操作数或运算结果。
* **MQ (乘商寄存器)**：在乘、除法运算时使用，存放操作数或结果。
* **X (通用寄存器)**：存放操作数。

#### 1.2.1.2 不同运算中寄存器的作用
| 运算类型   | ACC (累加器) | MQ (乘商寄存器) | X (通用寄存器) |
| :----- | :-------- | :--------- | :-------- |
| **加法** | 被加数、和     | —          | 加数        |
| **减法** | 被减数、差     | —          | 减数        |
| **乘法** | 乘积高位      | 乘数、乘积低位    | 被乘数       |
| **除法** | 被除数、余数    | 商          | 除数        |

---
### 1.2.2 控制器的工作原理

控制器是计算机的指挥中心，负责协调各部件工作。

#### 1.2.2.1 核心部件
* **CU (控制单元)**：控制器的核心，负责分析指令并给出控制信号。
* **IR (指令寄存器)**：存放**当前正在执行**的指令。
* **PC (程序计数器)**：存放**下一条**指令的地址，具有自动加1功能。

#### 1.2.2.2 指令执行阶段
1.  **取指令**：根据PC地址从主存取出指令放入IR。
2.  **分析指令**：CU分析IR中指令的**操作码**。
3.  **执行指令**：CU根据分析结果指挥各部件（如ALU、主存）执行操作。

## 1.3 计算机软件
### 1.3.1 计算机软件的分类

1.  **应用软件**
    * **定义**：为解决特定领域的应用问题而编制的程序，直接为用户提供服务。

2.  **系统软件**
    * **定义**：负责管理计算机系统的硬件资源，并向上层应用软件提供基础服务与支持。系统软件是软件系统的“基建”。
    * **典型示例**：
        * **操作系统 (OS)**：最核心的系统软件。
        * **数据库管理系统 (DBMS)**：提供数据库服务。
        * **网络软件**：如网卡驱动程序。
        * **语言处理程序**：汇编程序、编译程序、解释程序。
        * **服务程序**：如调试程序、诊断程序。
        * **标准程序库**：如 C 语言的 `printf` 等库函数。

### 1.3.2 计算机语言的三个级别

1.  **机器语言**
    * **形式**：二进制代码（0 和 1）。
    * **特点**：计算机**唯一**能直接识别和执行的语言。
    * **缺点**：可读性差，编程困难。

2.  **汇编语言**
    * **形式**：使用**助记符**（如 LOAD, MUL）代替二进制指令。
    * **特点**：比机器语言易读，但**仍属于低级语言**。必须通过汇编程序的翻译，转换为机器语言后才能运行。

3.  **高级语言**
    * **形式**：接近人类自然语言。
    * **特点**：开发效率高，与具体硬件无关，需先编译为汇编语言再经汇编生成机器语言，或直接编译为机器语言。

### 1.3.3 语言处理程序

将高级语言或汇编语言翻译成机器语言的程序统称为**翻译程序**，转换后生成的程序称为目标程序。

#### 1.3.3.1 翻译方式对比

| 翻译程序类型   | 编译程序                 | 解释程序               | 汇编程序       |
| :------- | :------------------- | :----------------- | :--------- |
| **输出结果** | **机器语言目标程序**（.exe 等） | 无独立目标程序生成          | 机器语言目标程序   |
| **翻译过程** | **一次性全部翻译**，再执行      | **翻译一句，执行一句**      | 将助记符转换为二进制 |
| **执行效率** | **高**（代码只需翻译一次）      | **低**（循环代码需重复翻译）   | 中          |
| **典型语言** | C, C++               | Python, JavaScript | 汇编语言       |

### 1.3.4 软件和硬件的逻辑功能等价性

1.  **核心概念**
    * 同一个逻辑功能，既可以用**硬件**实现，也可以用**软件**实现。
    * **等价性**指二者在**功能**上是等效的，但在性能和成本上存在差异。

2.  **实现方式对比**

| 维度          | 硬件实现         | 软件实现  |
| :---------- | :----------- | :---- |
| **性能 (速度)** | **高**        | **低** |
| **成本 (造价)** | **高** (电路复杂) | **低** |
| **灵活性**     | 低 (固化后难改)    | 高     |

### 1.3.5 从源程序到可执行文件

在计算机中编写的C语言程序必须经过**编译**和**链接**过程，转换为一系列低级机器指令，并封装为可执行目标文件。

 **翻译过程的四个阶段**：
 - **预处理阶段**：预处理器处理预处理指令，生成预处理后的C.i。
 - **编译阶段**：编译器将C.i翻译为汇编程序C.s。
 - **汇编阶段**：汇编器将C.s转换为机器语言指令，生成可重定位目标文件C.o。该文件为二进制格式。
 - **链接阶段**：链接器将C.o与标准C库中所需的函数进行链接，解析外部符号引用，最终生成完整的可执行文件。

### 1.3.6 指令集体系结构 (ISA)

* **定义**：规定了**软件和硬件之间的界面（边界）**。
* **作用**：是计算机软硬件之间的**关键接口**，定义了**软件可直接使用的硬件功能**。
* **包含内容**：
    * 指令格式
    * 操作类型
    * 寻址方式
    * 可访问的寄存器等硬件资源
    * 操作数的数据类型，以及存放方式(大端、小端)
    * 程序员可见状态
* **设计意义**：ISA 的设计需要在性能（倾向硬件实现）和成本（倾向软件实现）之间寻找平衡点。

### 1.3.7 微体系架构 / 微架构

- **作用**：微架构是处理器内部的硬件组织方式，用于实现ISA定义的功能。ISA定义了“做什么”，微架构决定了“怎么做？。
- **核心设计**：数据通路组织、控制单元实现、流水线级数、缓存层次结构、分支预测机制等。
- 相同的ISA规范可对应多种不同的微架构，软件无需修改即可兼容。

## 1.4 计算机的性能指标
### 1.4.1 存储器的性能指标

存储器的容量通常由 **存储单元个数** 和 **存储字长** 决定。

* **MAR（存储器地址寄存器）位数**：反映存储单元的个数（最多可寻址范围）。若 MAR 为 $n$ 位，则存储单元个数最多为 $2^n$ 个。
* **MDR（存储器数据寄存器）位数**：反映每个存储单元的大小（存储字长）。若 MDR 为 $m$ 位，则每个存储单元可存放 $m$ bit。
* **总容量计算公式**：
    $$\text{总容量} = \text{存储单元个数} \times \text{存储字长} = 2^{\text{MAR位数}} \times \text{MDR位数} (\text{bit})$$

### 1.4.2 CPU 的性能指标

* **主频（时钟频率）**：CPU 内部数字脉冲信号震荡的频率。
    * 符号：$f$
    * 单位：Hz（赫兹）。
    * 意义：每秒包含的时钟周期数量。
* **CPU 时钟周期**：CPU 中最小的时间单位。
    * 符号：$T$
    * 关系：$T = 1/f$（互为倒数）。
* **CPI**：执行一条指令所需的时钟周期数。
    * **不同指令的 CPI 不同**。
    * **平均 CPI**：通常使用加权平均计算，即 $\text{总时钟周期数} / \text{指令总数}$。
* **CPU 执行时间**：运行一个程序所花费的时间。
    $$\text{CPU执行时间} = \frac{\text{总时钟周期数}}{\text{主频}} = \frac{\text{指令条数} \times \text{CPI}}{\text{主频}} = \text{指令条数} \times \text{CPI} \times \text{时钟周期}$$
* **IPS**：每秒执行的指令条数。
    $$\text{IPS} = \frac{\text{主频}}{\text{平均CPI}}$$
* **MIPS**：每秒执行多少**百万**条指令。
    $$\text{MIPS} = \frac{\text{指令条数}}{\text{执行时间} \times 10^6} = \frac{\text{主频}}{\text{CPI} \times 10^6}$$
* **FLOPS**：每秒执行多少次浮点运算，常用于衡量科学计算性能。

### 1.4.3 系统整体性能指标

* **数据通路带宽**：数据总线一次所能并行传送信息的位数。直接影响各硬件部件之间的数据传输效率。
* **吞吐量**：系统在单位时间内处理**请求**的数量。
    * 取决于信息输入内存的速度、CPU 取指速度等。
* **响应时间**：从用户发送请求开始，到系统对该请求做出响应并获得所需结果为止的时间。
* **基准程序**：
    * 使用专门设计的程序来测量计算机处理速度。
    * **注意**：跑分高不代表在所有应用场景下性能都好，取决于基准程序指令序列的频度与实际应用是否匹配。


### 1.4.4 常见误区

1.  **主频高 $\neq$ 速度快**：如果 CPI 很高，即使主频高，执行一条指令的时间也可能很长。
2.  **CPI 低 $\neq$ 速度快**：如果指令系统复杂（如一条指令完成很多功能），虽然指令条数少，但单条指令周期长；或者反之。需综合考虑 $\text{指令条数} \times \text{CPI}$。

# 2 数据的表示和运算

## 2.1 进制

### 2.1.1 基础概念

* **定义**：进位计数制是一种利用符号及其位置来表示数值的方法。
* **基数**：每个数码位所用到的不同符号的个数。$r$ 进制的基数为 $r$。

| 进制类别     | 有效符号         | 常见后缀  | 前缀     |
| :------- | :----------- | :---- | :----- |
| **二进制**  | 0, 1         | **B** | -      |
| **八进制**  | 0 ~ 7        | **O** | -      |
| **十进制**  | 0 ~ 9        | **D** | -      |
| **十六进制** | 0 ~ 9, A ~ F | **H** | **0x** |

---
### 2.1.2 二进制、八进制、十六进制互转


**1. 二进制 $\leftrightarrow$ 八进制**
* **原则**：**3位一组**。
* **二转八**：以小数点为界，整数部分向左、小数部分向右，每3位一组，不足3位时**补0**（整数补在最高位，小数补在最低位）。每组转换为对应的八进制符号。
* **八转二**：将每一位八进制数展开为对应的3位二进制数。

**2. 二进制 $\leftrightarrow$ 十六进制**
* **原则**：**4位一组**。
* **二转十六**：以小数点为界，每4位一组，不足4位时**补0**。每组转换为对应的十六进制符号。
* **十六转二**：将每一位十六进制数展开为对应的4位二进制数。

### 2.1.3 十进制转换为任意进制

**1. 整数部分：除基取余法**
* **方法**：不断除以基数 $r$，取余数，直到商为0。
* **顺序**：**最先**得到的余数是**最低位**，最后得到的余数是最高位。
* **口诀**：**除基取余，逆序排列**。

**2. 小数部分：乘基取整法**
* **方法**：不断乘以基数 $r$，取整数部分，直到小数部分为0或达到精度要求。
* **顺序**：**最先**得到的整数是**最高位**。
* **口诀**：**乘基取整，顺序排列**。
* **精度问题**：十进制小数转换为二进制时，**可能无法精确表示**，会出现无限循环。

---
## 2.2 定点数的表示

### 2.2.1 有符号数的定点表示

有符号数包括**定点整数**和**定点小数**。最高位为**符号位**（0 表示正，1 表示负），其余为**尾数**。

#### 2.2.1.1 原码
* **定义**：用尾数表示真值的绝对值，符号位表示正负。
* **定点整数**：
    * 小数点隐含在最低位之后。
    * 若机器字长为 $n+1$ 位（1 位符号，$n$ 位数值），表示范围：$-(2^n - 1) \sim 2^n - 1$。
* **定点小数**：
    * 小数点隐含在符号位之后。
    * 表示范围：$-(1 - 2^{-n}) \sim 1 - 2^{-n}$。
* **真值 0 的表示**：有两种形式。
    * $[+0]_{原} = 000\dots0$
    * $[-0]_{原} = 100\dots0$

#### 2.2.1.2 反码
* **定义**：
    * **正数**：与原码相同。
    * **负数**：原码的符号位不变，数值位**全部取反**。
* **真值 0 的表示**：有两种形式。
    * $[+0]_{反} = 000\dots0$
    * $[-0]_{反} = 111\dots1$

#### 2.2.1.3 补码
* **定义与转换**：
    * **正数**：与原码相同。
    * **负数**：反码末位 $+1$。
    * **补码$\rightarrow$原码**：正数不变；负数符号位不变，数值位取反后 $+1$（规则与正向相同）。
    * **$[x]_{补} \rightarrow[-x]_{补}$**：将 $[x]_{补}$ 连同符号位在内**全部取反，末位 $+1$**。
* **特殊性质**：
    * **真值 0 的表示**：**唯一**。
        * $[+0]_{补} = [-0]_{补} = 000\dots0$。
    * **表示范围扩展**：由于少了一个 $-0$，补码能多表示一个负数。
        * **定点整数**：$-2^n \sim 2^n - 1$（$[x]_{补}=1,0000000=-2^7$）。
        * **定点小数**：$-1 \sim 1 - 2^{-n}$（$[x]_{补}=1.0000000=-1$）。
- **作用**：让减法操作转变为加法操作

#### 2.2.1.4 移码
* **定义**：将**真值**加上一个固定的偏置值，若字长为$n+1$偏置值通常设为$2^n$。
* **适用性**：**只能用于表示整数**。
* **特点**：
    * **真值 0 的表示**：唯一（$100\dots0$）。
    * **大小比较**：偏置值为$2^n$时，移码保持了数据的“序”特性，全 0 最小，全 1 最大。硬件可通过从高位到低位逐位比较来判断大小。
    * **用途**：常用于浮点数的阶码表示。

---

假设机器字长为 $n+1$ 位（含 1 位符号位），尾数为 $n$ 位。

| 编码方式   | 整数表示范围                    | 小数表示范围                          | 真值 0 的表示 | 备注               |
| :----- | :------------------------ | :------------------------------ | :------- | :--------------- |
| **原码** | $-(2^n - 1) \sim 2^n - 1$ | $-(1 - 2^{-n}) \sim 1 - 2^{-n}$ | 两种       | 直观，乘除法简单，加减法复杂   |
| **反码** | $-(2^n - 1) \sim 2^n - 1$ | $-(1 - 2^{-n}) \sim 1 - 2^{-n}$ | 两种       | 中间状态，硬件很少直接使用    |
| **补码** | **$-2^n \sim 2^n - 1$**   | **$-1 \sim 1 - 2^{-n}$**        | **唯一**   | 加减运算统一，符号位参与运算   |
| **移码** | **$-2^n \sim 2^n - 1$**   | 无                               | **唯一**   | 便于硬件比较大小，用于浮点数阶码 |

### 2.2.2 C语言中整数类型和类型转换
在C语言中，表达式的赋值、运算或比较操作会触发自动类型转换，自动类型转换由范围和精度较低的向更高者进行，一般不会丢失信息。这类由编译器自动完成的转换称为**隐式类型转换**。

#### 2.2.2.1 整数类型
- **short**: 通常为16位。
- **int**:通常为32位。
- **long**:64位系统中为64位。
- **char**:通常为8位。

#### 2.2.2.2 类型转换

定点数在类型转换过程中，若涉及字长变化，则会触发两种基本操作：**位截断**和**位扩展**。
##### 2.2.2.2.1 位截断
长类型转换为短类型时，丢弃高位，仅保留低位。

##### 2.2.2.2.2 位扩展
- **零扩展**
	* **适用场景**：**无符号整数**。
	* **操作规则**：原有数据位保持不变，多出的高位部分全部**填补 0**。
	* **原理**：无符号数的所有位均为数值位，在高位补0不会改变其代表的真值。
- **符号扩展**
	* **适用场景**：**补码**表示的**带符号整数**。
	* **操作规则**：原有数据位保持不变，多出的高位部分全部**填补符号位**。
	* **原理**：
	    * **正数补码**：与原码相同，高位补0真值不变。
	    * **负数补码**：若高位补0会变成正数，导致真值错误；只有高位补1才能保证补码对应的真值不变。

#### 2.2.2.3 类型转换方式
- **长类型转短类型**：位截断。可能由于位截断导致转换前后的正负不同。
- **相同字长转换**：二进制位不改变，仅改变解释方式。
- **短类型转长类型**：若源数据为有符号数，则进行符号扩展，否则零扩展。

## 2.3 加法器
### 2.3.1 一位全加器

* **输入与输出**：
    * **输入**：被加数本位 $A_i$、加数本位 $B_i$、来自低位的进位 $C_{i-1}$。
    * **输出**：本位和 $S_i$、向高位的进位 $C_i$。
* **逻辑表达式**：
    * **本位和**：$S_i = A_i \oplus B_i \oplus C_{i-1}$。
    * **进位**：$C_i = A_iB_i + (A_i \oplus B_i)C_{i-1}$。

### 2.3.2 串行进位加法器

- **定义**：将n个全加器级联可构成n位**串行进位加法器**（又称**行波进位加法器**）。
- **特点**：进位信号逐级传递，每一级的进位输出作为下一级的进位输入。
- **性能**：进位链越长，延迟越大。**缩短进位传递路径是提升加法器性能的关键**。

### 2.3.3 带标志位加法器

为了支持程序逻辑判断（如溢出、大小比较、判零），加法器需要输出四个状态标志位：**OF、SF、ZF、CF**。

#### 2.3.3.1 溢出标志 OF
* **含义**：判断**带符号数** (补码) 加法运算是否发生溢出。
* **逻辑**：$OF = 1$ 表示溢出，$OF = 0$ 表示未溢出。
* **生成电路**：最高位进位 $C_n$ 与次高位进位 $C_{n-1}$ 进行**异或**。
    $$OF = C_n \oplus C_{n-1}$$
* **适用性**：仅对**带符号数**运算有意义。

#### 2.3.3.2 符号标志 SF
* **含义**：判断**带符号数**加减运算结果的正负。
* **逻辑**：$SF = 1$ 表示结果为负，$SF = 0$ 表示结果为正。
* **生成电路**：直接取运算结果的**最高位** (符号位)。
    $$SF = S_n$$
* **适用性**：仅对**带符号数**运算有意义。

#### 2.3.3.3 零标志 ZF
* **含义**：判断加减运算结果是否为 **0**。
* **逻辑**：$ZF = 1$ 表示结果为0，$ZF = 0$ 表示结果非0。
* **生成电路**：对结果的所有位 ($S_1 \dots S_n$) 进行**或非**运算。只有全为0时，输出才为1。
    $$ZF = \overline{S_n + \dots + S_1}$$
* **适用性**：**带符号数**和**无符号数**均适用。

#### 2.3.3.4 进位/借位标志 CF
* **含义**：判断**无符号数**加减运算是否发生溢出 (进位或借位)。
* **逻辑**：$CF = 1$ 表示溢出/有进位/需借位。
* **生成电路**：最高位进位输出 $C_{out}$与控制信号 $Sub$ 进行**异或**。
    $$CF = C_{out} \oplus Sub$$
* **适用性**：仅对**无符号数**运算有意义。

---
### 2.3.4 算术逻辑单元 ALU

#### 2.3.4.1 ALU 的主要功能

1.  **算术运算**：加、减、乘、除等。
2.  **逻辑运算**：与、或、非、异或、移位等。
3.  **辅助功能**：
    * **求补码**：将源码转换为补码。
    * **直送**：数据不进行处理，直接通过 ALU 输出。
4. **ALUop**：ALUop为操作控制信号，用于选择ALU执行的具体功能。ALUop的位数决定了支持的操作种类数量。

##### 2.3.4.1.1 输入信号
* **运算操作数 (A, B)**：
    * 通常有两个输入端。
    * 位宽为 $n$ bit，通常与**机器字长**相同。
* **控制信号 (Op)**：
    * 来源：由**控制器**经指令译码后产生。
    * 作用：决定 ALU 当前执行哪种功能。
    * **位宽**：若 ALU 支持 $K$ 种功能，控制信号位宽 $m$ 需满足：$m \ge \lceil \log_2 K \rceil$

##### 2.3.4.1.2 输出信号
* **运算结果 (F)**：
    * 位宽为 $n$ bit，与机器字长相同。
* **标志位信号**：
    * 包含 **ZF** (零标志)、**OF** (溢出标志)、**SF** (符号标志)、**CF** (进位/借位标志)。
    * 去向：送入 **PSW** (程序状态字寄存器)，也称为 **FR** (标志寄存器)。

##### 2.3.4.1.3 进位信号
* **Cin**：低位进位输入。
* **Cout**：向高位进位输出。

#### 2.3.4.2 总结

| 维度         | 关键内容                           |
| :--------- | :----------------------------- |
| **核心部件**   | 运算器核心是 ALU，ALU 核心是加法器          |
| **控制信号位数** | $m \ge \lceil \log_2 K \rceil$ |
| **数据位宽**   | 运算数、结果位宽通常等于**机器字长**           |
| **标志位去向**  | 存入 **PSW** (或称 **FR**)         |

## 2.4 定点数的移位运算

### 2.4.1 逻辑移位

* **逻辑左移**
    * **规则**：高位移出丢弃，**低位补 0**。
    * **注意**：若移出的高位为 **1**，则发生**溢出**。
* **逻辑右移**
    * **规则**：低位移出丢弃，**高位补 0**。
    * **注意**：若移出的低位为 **1**，则发生**精度丢失**。

---

### 2.4.2 算术移位

* **算术左移**
    * **规则**：高位移出丢弃，**低位补 0**。
    * **溢出判断**：若**移位前后符号位发生改变**，则发生**溢出**。
* **算术右移**
    * **规则**：低位移出丢弃，**高位补符号位**。
    * **注意**：若移出的低位为 **1**，则发生**精度丢失**。

## 2.5 加减运算

### 2.5.1 补码加减运算

$$[A+B]_{\text{补}} = [A]_{\text{补}} + [B]_{\text{补}}$$

- 符号位与数值位一同参与运算，结果的符号位由运算得出。

**溢出**是指运算结果超出了机器字长所能表示的数值范围。
* **上溢/正溢**：两个正数相加，结果为负。
* **下溢/负溢**：两个负数相加，结果为正。

**判别溢出的三种方法**:

| 方法名称                    | 判别依据            | 逻辑表达式 / 规则                                                                                       | 备注                             |
| :---------------------- | :-------------- | :----------------------------------------------------------------------------------------------- | :----------------------------- |
| **一位符号位法（模2补码）**        | 利用操作数与结果的符号位    | $V = A_S B_S \overline{S_S} + \overline{A_SB_S}S_S$ <br> ($A_S, B_S$为操作数符号，$S_S$为结果符号)           | 若 $V=1$，则溢出。                   |
| **进位判别法**               | 利用符号位进位与最高数值位进位 | $V = C_S \oplus C_1$ <br> ($C_S$: 符号位的进位，即最高数值位产生的进位；$C_1$: 符号位产生的进位)                            | 若 $V=1$，则溢出。                   |
| **双符号位法**<br>**(模4补码)** | 利用运算结果的两个符号位    | $V = S_{s1} \oplus S_{s2}$ <br> ($S_{s1}, S_{s2}$ 为结果的高位和低位符号，$S_{s1}$表示正确的符号位,$S_{s2}$表示实际的符号位) | 若 $V=1$，则溢出。<br>实际存储时只保存一位符号位。 |

#### 2.5.1.1 加减运算电路

- 无论是无符号数还是补码表示的有符号数，都可以通过同一加法器完成运算。
- 加法器的输入端包括两个n位操作数X和Y，以及一个控制信号Sub。X作为输入端1。其中Y分为Y和$\overline{Y}$，分别接入多路选择器（MUX）。$\overline{Y}$表示所有位按位取反。MUX作为输入端2。Sub选择Y或$\overline{Y}$进入加法器，也作为$C_{in}$作为输入。

- **加法**：
	- $Sub=C_{in}=0$
	- 加法器执行$X+Y+C_{in}$，即$X+Y$。
- **减法**：
	- $Sub=C_{in}=1$
	- 加法器执行$X+Y+C_{in}$，即$X+Y+1$。

---
### 2.5.2 无符号数的溢出判断方法

| 运算类型   | 判断依据（最高位进位 $C_{\text{out}}$） | 溢出结论   | 备注             |
| :----- | :--------------------------- | :----- | :------------- |
| **加法** | $C_{\text{out}} = 1$         | **溢出** | 结果超过了最大值       |
| **减法** | $C_{\text{out}} = 0$         | **溢出** | 实际上发生了借位（结果为负） |

---

在无符号计算中仅CF有意义，在有符号计算中仅OF有意义。
加减计算中，CF可以看作是无符号整数计算产生的，OF可以看作是有符号整数计算产生的。

**操作步骤**：
- 将乘数寄存器Y的最低位和辅助位共2bit送入“控制逻辑”进行判断；
- 根据“控制逻辑”的判断结果，决定操作为"$+[x]_补$"、"$-[x]$"还是“+0”；
- 将$[P,Y,辅助位]$视为整体，**算数右移**一位；
- 计数器$C_n$减1。

| **寄存器Y 最低位** | **辅助位** | **本轮操作**      |
| ------------ | ------- | ------------- |
| 0            | 0       | **+0**        |
| 0            | 1       | **$+ [x]_补$** |
| 1            | 0       | **$- [x]_补$** |
| 1            | 1       | **+0**        |

**溢出判断**：
- 通常仅保存低n位作为乘法运算结果，仅当**高n+1位不完全相同**时发生溢出。

### 2.6.3 计算机实现乘法的三种方式

#### 2.6.3.1 迭代式乘法器

* **核心部件**：
    * **ALU**：负责加法运算。
    * **移位器与寄存器**：负责存放部分积、乘数，并支持移位操作（通常由具有移位功能的寄存器实现）。
    * **控制逻辑**：控制运算的轮数。
* **工作原理**：
    * 采用**串行**处理方式。
    * 对于 $n$ 位无符号数相乘，逻辑需进行 $n$ 轮处理，每一轮处理乘数的1位。
* **运算速度**：
    * **较快**，但不如阵列乘法器。
    * 完成一次乘法运算至少需要 **$n$ 个时钟周期**。
* **优化方案（两位乘法）**：
    * 改进控制逻辑，每轮处理乘数的 **2 bit**。
    * 此时完成运算仅需 **$n/2$** 个时钟周期，速度提升一倍。

#### 2.6.3.2 阵列乘法器

* **硬件结构**：
    * 由大量全加器和逻辑门电路组成阵列网络。
    * 数据信号直接流过逻辑门阵列得到结果。
* **工作原理**：
    * **并行**处理方式。
    * 输入被乘数和乘数后，信号在电路中并行传播。
* **运算速度**：
    * **最快**。
    * 不依赖时钟计数进行多轮循环，在时钟周期足够长的前提下，**仅需 1 个时钟周期**即可完成乘法运算。

#### 2.6.3.3 模拟

* **实现原理**：
    * 编译器将乘法操作（$x \times y$）翻译为若干条**加法**、**移位**和**逻辑运算**指令的组合。
* **运算速度**：
    * **最慢**。

---
#### 2.6.3.4 总结

| 实现方式       | 硬件依赖      | 核心特点              |
| :--------- | :-------- | :---------------- |
| **迭代式乘法器** | ALU、移位寄存器 | 串行时序逻辑，逐位处理       |
| **阵列乘法器**  | 专用组合逻辑电路  | 并行计算，以空间换时间       |
| **模拟**     | 仅需加法/移位指令 | 使用多条指令模拟，取指/执行开销大 |

2.  将被除数放入寄存器**R**。

**操作步骤**：
电路通过 **$1+n$ 轮处理** 确定商的每一位。

2.  **后续 $n$ 轮循环**：

    * **尝试减法**：计算 $R - Y$。
    * **上商**：若结果 $\ge 0$，商 1，将结果写回**R**；若结果 $< 0$，商 0 且 $R$ 需执行加 $Y$ 操作以**恢复余数**。

### 2.6.5 有符号整数除法

有符号整数采用**补码**表示，**符号位和数值位一同参与运算，直接生成补码形式的商和余数**。
对于两个n位补码数相除，被除数需要先进行**符号扩展**至$2n$位。若被除数为2n位，除数位n位，则无须进行扩展。

电路与无符号除法基本一致。

* **余数寄存器 (R)**：初始存放被除数的高位，运算结束后存放 **最终余数**。
* **商寄存器 (Q)**：初始存放被除数的低位，运算结束后存放 **最终商**。
* **除数寄存器 (Y)**：存放除数。
* **控制逻辑与计数器 (Cn)**：循环次数。

**初始化**：
1.  将除数放入寄存器 **Y**。
2.  将被除数放入寄存器**R**。
3. **Q**全部置为被除数的符号位，即完成**符号扩展**。
4.  计数器 **Cn** 初始值置为 $n$。

**操作步骤**：
电路通过 **$1+n$ 轮处理** 确定商的每一位。

1.  **第 1 轮特殊处理（溢出判断）**：
    * 直接计算 $R - Y$。
    * 若结果 $\ge 0$（商为 1），判定为“**商溢出**”，停止运算。
    * 若结果 $< 0$（商为 0），判定不溢出，将 $R$ **加 $Y$ 恢复原值**，继续后续运算。
2.  **后续 $n$ 轮循环**：
    * **左移**：[R, Q] 执行一次**算数左移**。
    * **上商**：若R与Y同号，商1；否则商0，且 $R$ 需执行加 $Y$ 操作以**恢复余数**。
    * **计数减一**：Cn 减 1，直到为 0 时结束。

## 2.7 浮点数
### 2.7.1 浮点数的表示 IEEE 754

#### 2.7.1.1 基本原理

* 形式：$(-1)^{符号位} \times {尾数} \times 2^{阶码}$
* **符号位**：决定正负。
* **尾数**：决定数值精度。
* **阶码**：反映小数点实际位置（决定数值范围）。
* **基数**：默认为2，无需存储。
* **规格化**：确保尾数的最高非零位刚好在小数点之前。

#### 2.7.1.2 IEEE 754 浮点数格式标准

| 类型      | C语言类型      | 总位数     | 符号位 | 阶码      | 尾数      | 偏置值      |
| :------ | :--------- | :------ | :-- | :------ | :------ | :------- |
| **单精度** | **float**  | **32位** | 1位  | **8位**  | **23位** | **127**  |
| **双精度** | **double** | **64位** | 1位  | **11位** | **52位** | **1023** |

#### 2.7.1.3 表示规则

**符号位**：
* **规则**：**0表示正，1表示负**。

**尾数**：
- **编码方式**：用**原码**表示。
* **隐含位技术**：
    * 由于二进制规格化后，小数点前必然是 **1**（即 $1.M$ 的形式）。
    * IEEE 754 规定 **省略小数点前的 1**，仅存储小数点后的部分。
* **存储方式**：不足位数在低位 **补0**。

**阶码**：
* **编码方式**：用 **移码**表示。
* **偏置值计算公式**：$Bias = 2^{n-1} - 1$ （其中 $n$ 为阶码位数）。
    * **单精度 (n=8)**：$2^{7} - 1 = 127$。
    * **双精度 (n=11)**：$2^{10} - 1 = 1023$。
* **计算步骤**：
    1.  **阶码真值 + 偏置值 = 移码值**。
    2.  将结果转换为**无符号**二进制整数。
- **取值范围**：
	- $[1,2^n-2]$。
	- 全0和全1保留，用于表示特殊值。

---
### 2.7.2 规格化浮点数的表示范围

* **规格化特征**：当阶码不全为0且不全为1时，为规格化浮点数。此时尾数的小数点前默认隐含一个1。
* **单精度可表示最大正数**：$(2 - 2^{-23}) \times 2^{127}$
    * 尾数全为1（最大），阶码取最大真值127。
* **单精度可表示最小正数**：$1.0 \times 2^{-126}$
    * 尾数全为0（隐含1，小数部分全0），阶码取最小真值-126。

### 2.7.3 非规格化浮点数

* **特点**：
    * **阶码 (E)**：全 0。
    * **尾数 (M)**：不全为 0。
* **真值计算规则**：
    * **阶码**：固定为 $1 - \text{偏置值}$。
    * **尾数**：小数点前隐式位补 **0**（即 $0.M$）。
* **表示范围（以 float 为例）**：
    * **绝对值最小**：尾数最后一位为 1，真值为 $2^{-149}$。
    * **绝对值最大**：尾数全为 1，真值为 $(1 - 2^{-23}) \times 2^{-126}$。

### 2.7.4 溢出处理与异常

* **正上溢**：结果为正且大于最大规格化正数。
* **负上溢**：结果为负且小于最小规格化正数（绝对值过大）。
- **上溢处理规则**：
	- 将结果设为$+\infty$/$-\infty$。
	- 置位浮点**溢出异常标志**。
* **正下溢/负下溢**：运算结果为正/负，并且绝对值过小，落在非规格化数区间或更小。
    * **非规格化区间**：使用非规格化数存储，程序不中断。
    * **机器零区间**：真值逼近 0，直接存储为 **0**。
    * 置位浮点**下溢异常标志**。

* **溢出异常响应**：IEEE 754标准规定**默认不触发**中断异常。发生溢出时不会中断当前程序的运行，这种机制确保了较好的容错性。

* **数学上未定义的运算会产生 NAN，如**：
    * $0 \div 0$
    * $\infty \pm \infty$
    * $\infty / \infty$
    * $0.0 \times \infty$
    * 负数开平方根
* **产生无穷大的情况**：
    * 非零数 $\div 0$（如 $1.0 \div 0 = +\infty$）

---
### 2.7.5 特殊状态浮点数

| 阶码状态   | 尾数状态     | 值的类型    | 数值解读特征                 |
| :----- | :------- | :------ | :--------------------- |
| **全0** | **全0**   | 正零或负零   | 符号为0时为正零，符号为1时为负零。     |
| **全0** | **不全为0** | 非规格化数   | 尾数的小数点前隐含的是0，而非1。      |
| **全1** | **全0**   | 极值（无穷大） | 符号为0时为正无穷，符号为1时为负无穷。   |
| **全1** | **不全为0** | 非数（NaN） | 常用于表示无意义的运算结果，如对负数开根号。 |

**记忆**：
- 阶码决定大小：全0表示接近0的数（0和非规格化数），全1表示超出范围（无穷大和NaN）。
- 尾数决定细节：全0表示无额外信息（0和无穷大），全1表示有额外信息（非规格化数和NaN）。

## 2.8 浮点数的加减运算

浮点数进行加减运算时阶码和尾数分开处理。

### 2.8.1 对阶
- **原则**：小阶向大阶看齐。即将阶码较小的数的尾数右移，右移位数等于阶码的差的绝对值。
- **尾数右移**：
	- 仅移动数值位，不移动符号位。
	- 对于规格化数，隐藏位1会随尾数右移进入小数部分，空出的高位补0。
	- 移出的低位应**保留**并参与后续尾数运算。

### 2.8.2 尾数加减
- **计算方式**：实质上是定点原码小数的加减运算，保留的**辅助位(保护位、舍入位和粘滞位)也要参与运算**，**运算结束后的辅助位**用于判断舍入。
- **规格化数**：对于规格化数，在运算前还需要将隐藏位还原到尾数部分，形成“1.f”的形式。

### 2.8.3 尾数规格化
- **规格化**：通过调整尾数与阶码，使浮点数的尾数满足最高有效位为1的形式。
- **右规**：当结果为$1x...$时，尾数右移，尾数每移出一位，阶码+1。
- **左规**：当结果为$0.0x1...$时，尾数左移，尾数每移一位，阶码-1。

### 2.8.4 舍入
在对阶和右规过程中，尾数右移可能导致低位丢失。为保证精度，将移出的低位保留用于中间计算。

#### 2.8.4.1 辅助位
- **保护位**：尾数最低有效位后的第一位。
- **舍入位**：尾数最低有效位后的第二位。
- **粘滞位**：只要舍入位之后被移除的位中至少存在一个1，粘滞位就为1，否则为0。

#### 2.8.4.2 舍入模式
- **就近舍入**：选择最接近真实值的可表示的那个数，若恰好位于两个可表示数中间，则选择最低有效位为0的。
	1. 若保护位为0，则直接舍去。
	2. 若保护位为1，且舍入位和粘滞位中至少一个为1，则尾数+1。
	3. 若保护位为1，舍入位和粘滞位都为0，则在尾数末位为1时+1。
- **正向舍入**：朝数轴正方向舍入，即选择数值更大的可表示数。
- **负向舍入**：朝数周负方向舍入，即选择数值更小的可表示数。
- **截断法**：直接截取所需位数，丢弃后面的所有位，即选择更接近原点的那个可表示数。

#### 2.8.4.3 溢出判断
尾数的溢出可通过右规修正，因此浮点数的溢出由阶码是否超出可表示范围决定。

- **上溢判断**：
	- 尾数相加后或舍入时，若结果 $\ge$ 2，需要进行右规。
	- 若原阶码已为最大正规格化值(1...10)，右规导致阶码加1后溢出，称为**指数上溢**，通常会引发异常。
- **下溢判断**：
	- 若左规时阶码真值低于最小规格化值，则进入非规格化数范围。若结果进一步小于最小可表示非规格化数，则视为**指数下溢**，通常将结果置为**机器零**。

## 2.9 数据的存储和排列

### 2.9.1 数据的大小端模式

在多字节数据存储时，根据字节在内存地址中的排列顺序，分为**大端模式**和**小端模式**。

* **最高有效字节 (MSB)**：数据的最高位字节。
* **最低有效字节 (LSB)**：数据的最低位字节。

| 存储模式     | 定义                               | 特点                                         |
| :------- | :------------------------------- | :----------------------------------------- |
| **大端模式** | 将 **MSB** 存放在低地址，**LSB** 存放在高地址。 | 符合人类阅读习惯，地址由低到高顺序对应数据的高位到低位。               |
| **小端模式** | 将 **LSB** 存放在低地址，**MSB** 存放在高地址。 | 符合机器处理习惯，便于 CPU 从低位开始进行算术运算。**字节**顺序与书写相反。 |

---

### 2.9.2 边界对齐与存储寻址

现代计算机通常按**字节编址**，但支持按**字节**、**半字**、**字**进行寻址。

#### 2.9.2.1 寻址方式与地址转换
由于每个字或半字包含多个字节，寻址时需进行地址转换（通常采用**逻辑左移**实现）：
* **按半字寻址**：1个半字 = 2个字节。半字地址转字节地址需**左移 1 位**。
* **按字寻址**：1个字 = 4个字节（假设字长 32 位）。字地址转字节地址需**左移 2 位**。

#### 2.9.2.2 存储方式

| 存储方式      | 原理                                        | 优点                           | 缺点                                          |
| :-------- | :---------------------------------------- | :--------------------------- | :------------------------------------------ |
| **边界对齐**  | 要求数据的起始地址必须是该数据类型所占字节数的整数倍。若空间不足，则填充空白字节。 | **访存速度快**。任何类型的数据仅需一次访存即可读出。 | 存在一定的**空间浪费**。                              |
| **边界不对齐** | 数据紧凑排列，不留空隙。                              | **空间利用率高**，无存储碎片。            | **访存效率低**。每次访存只能读/写一个字，跨越字边界的数据需要两次访存并进行拼接。 |

# 3 存储系统
## 3.1 主存储器的基本组成

### 3.1.1 存储器的分类
1. **随机存取存储器**：可随机读写任意存储单元，常用于主存或高速缓存。
2. **顺序存取存储器**：只能按顺序读写数据。容量大但速度慢。
3. **直接存取存储器**：可先直接定位到目标区域，再按顺序读取数据。
4. **相联存储器**：按内容而非地址进行存取，查找速度快，成本高容量小。

### 3.1.2 半导体存储元器件及其原理

#### 3.1.2.1 基本组成
* **存储体**：由许多**存储单元**组成，用于存放二进制数据。
    * **存储元件**：最小物理单位（如电容），存储一位二进制代码（0或1）。
    * **存储单元**：存放一串二进制代码，每个单元对应一个唯一的**地址**。
    * **存储字**：存储单元中二进制代码的组合。
    * **存储字长**：存储单元中二进制代码的位数。
* **MAR (存储地址寄存器)**：
    * 用于存放欲访问的**存储单元地址**。
    * 其位数反映了存储单元的个数（寻址范围）。
* **MDR (存储数据寄存器)**：
    * 用于暂存从存储器读出或写入的**数据**。
    * 其位数通常等于**存储字长**。
* **注意**：在现代计算机中，MAR和MDR通常集成在**CPU**芯片内部。

#### 3.1.2.2 读/写操作流程
* **读操作**：CPU将地址写入MAR $\rightarrow$ 主存根据MAR地址找到数据 $\rightarrow$ 数据写入MDR $\rightarrow$ CPU从MDR取走数据。
* **写操作**：CPU将地址写入MAR $\rightarrow$ CPU将数据写入MDR $\rightarrow$ CPU发出写控制信号 $\rightarrow$ 主存将MDR数据写入对应地址。

* **MOS管**：充当电路的**控制开关**。当输入电压达到阈值（高电平）时，MOS管导通。
* **电容**：利用电荷的有无来存储二进制位。
    * **1**：电容保存电荷。
    * **0**：电容不保存电荷。
* **读写原理**：
    * **写操作**：通过MOS管导通向电容充电或放电。
    * **读操作**：MOS管导通后，检测电容是否有电荷流出。

---
### 3.1.3 存储器的层次化结构
为缓解存储系统在**容量、速度与成本**之间的矛盾，引入了两个关键的层级**Cache-主存**和**主存-辅存**，核心思想为：**将上一层存储器作为下一层的高速缓存**。CPU按**Cache $\rightarrow$ 主存 $\rightarrow$ 辅存**顺序查找。

- **Cache-主存**：用于缓解CPU与主存速度不匹配问题，由**硬件自动完成**。
- **主存-辅存**：用于解决存储容量不足问题，由**硬件与操作系统协同完成**。
---
### 3.1.4 存储器的主要性能指标
- **存取时间**：完成一次读/写操作的时间。
	- **读出时间**：从主存接收到有效地址到数据有效输出的时间。
	- **写入时间**：从主存接收到有效地址到数据成功写入的时间。
- **存储周期**：连续进行两次独立的读/写操作所需的最小**时间间隔**，即两次开始存储的时间差。通常存储周期大于存取时间，因为存储器需要一定时间恢复内部状态。
- **存储器带宽**：存储器每秒能够传输的最大数据量。

---
### 3.1.5 存储芯片的基本结构

存储芯片通过合理连接多个存储元，实现按**存储字**进行批量访问。

* **存储体（存储矩阵）**：由多个存储单元组成。
    * **存储单元**：同一行存储元组成一个存储单元，其MOS管连接在同一根**字选择线**上。
    * **存储字长**：一个存储单元中存储元的个数。
* **译码驱动电路**：
    * **译码器**：将地址寄存器（MAR）输出的$n$位地址信号转换为$2^n$根选通线中的一根高电平信号。
    * **驱动器**：放大译码器输出的电信号，确保其能稳定驱动整行存储元。
* **读写电路**：包括数据寄存器（MDR）和控制逻辑，负责将数据从存储阵列导出或写入。
* **控制信号线**：
    * **片选线**（CS或CE）：低电平有效，用于选择当前工作的芯片，解决多芯片并联时的选址问题。
    * **读写控制线**：分为独立两根线（WE允许写、OE允许读）或合二为一的一根线。

---
### 3.1.6 存储芯片的规格与引脚计算

| 规格表述示例 | 存储单元数 | 存储字长 | 地址线位数 | 数据线位数 |
| :--- | :--- | :--- | :--- | :--- |
| **8K × 8位** | 8K ($2^{13}$) | 8位 | 13根 | 8根 |
| **64K × 16位** | 64K ($2^{16}$) | 16位 | 16根 | 16根 |

**芯片引脚数**：
引脚总数 = 地址线数 + 数据线数 + 片选线数（通常1根） + 读写控制线数（1或2根） + 电源/接地线。

---
## 3.2 SRAM和DRAM

### 3.2.1 存储元件与基本原理

**随机访问存储器**（RAM）分为**静态 RAM（SRAM）** 和 **动态 RAM（DRAM）**，二者均为易失性存储器。

* **SRAM（静态 RAM）**：
	* 使用**双稳态触发器**（通常由 6 个 MOS 管组成）存储信息。
	* **非破坏性**：只要不断电，信息就不会消失，因此读操作无需再生。
	* **特点**：集成度低，功耗大，成本高。
	* **典型应用**：Cache。
* **DRAM（动态 RAM）**：
	* 使用**栅极电容**存储电荷。利用电容的有无电荷分别代表二进制的 1 和 0。
	* **刷新**：电荷会因漏电逐渐减少，因此需要定时刷新以维持数据。
	* **破坏性**：读操作为破坏性读出，因此读取后需要立即再生。
	* **特点**：功耗低，成本低，读取速度较慢。
	* **典型应用**：主存。

---
### 3.2.2 存储芯片的组成
1. **存储体(存储矩阵)**：存储单元的集合。通过行选择线(X)和列选择线(Y)共同选中目标单元，位于相同行列的多个位(Z不同)被同时读/写。
2. **地址译码器**：将输入地址转换为移码输出线上的高电平信号，以驱动响应的读/写电路。
	- **单译码法**：仅使用一个行译码器，缺点为译码器输出线数量过多。
	- **双译码法**：使用行译码器和列译码器。
3. **I/O电路**：用于控制被选中存储单元的读/写，具有放大信号的作用。
4. **片选控制线**：为满足计算机对主存容量的需求，需要将多个芯片组合扩展。片选控制线用于选中访问的存储字的芯片。
5. **读/写控制线**：根据CPU发出的读/写命令，通过读/写控制线对选中单元进行相应操作。

---

### 3.2.3 DRAM 的刷新操作

由于电容电荷只能维持约 **2ms**，即使不断电，也必须在 2ms 内对所有存储单元进行一次刷新。

* **刷新单位**：以**行**为单位，由存储器内部刷新电路独立完成，**不需要 CPU 控制，但影响访存**。
* **刷新周期**：两次刷新的时间间隔。
* **存取周期**：仅把信息读出到刷新放大器，刷新放大器集成在RAM上，因此**仅1次访存**，即只占用**1个访问周期**。
* **刷新策略**：
    1.  **集中刷新**：在刷新周期内，集中一段时间进行刷新。这段时间 CPU 无法访问存储器，称为**访存死区**。
    2.  **分散刷新**：将刷新操作分散到每个存取周期中（前半周期读写，后半周期刷新）。优点是没有死区，但**存取周期变长**（性能折半）。
    3.  **异步刷新**：在刷新周期内，将刷新各行的时间间隔均匀分布。这种方式可以缩短死区时间，最为常用。

---
### 3.2.4 DRAM 地址线复用技术

* **核心原理**：将 N 位地址拆分为**行地址**和**列地址**（通常各为 $N/2$ 位），通过相同的引脚分两次送入。
* **影响**：
    * **引脚减半**：地址引脚数只需地址总位数的一半。
    * **内部结构**：存储单元在内部排列成**二维矩阵**。通过行地址译码器和列地址译码器共同选中目标单元。
* **计算**：在计算 DRAM 芯片引脚总数时，地址线数量应按**实际物理引脚**（总位数的一半）计算。

- **DRAM芯片行列数**：因为地址线复用技术和刷新机制，应让行数小于列数，且行列数尽可能接近。

---
### 3.2.5 DRAM 缓存机制
芯片内部设有一个**行缓存器**，用于缓存选中行所有列的数据。容量为$列数 * 位数$。
行缓存器通常由**SRAM**实现。

### 3.2.6 同步 DRAM(SDRAM)
- 读/写操作**与系统时钟同步**，能够以CPU-主存总线的较高速率运行。
- 在连续访问同一行(页)时，可实现突发传输，**能显著减少甚至避免插入等待状态**。
- 能在预设的若干时钟周期后返回数据或完成写入，使CPU无需等待，可执行其他命令，显著提升系统性能。

---
## 3.3 只读存储器 ROM

**ROM**的主要特性是**非易失性**，即断电后数据不会丢失，且结构简单，位密度高于SRAM等存储器。与 **RAM** 类似，**ROM** 也支持**随机存取**。

| 常见芯片类型    | 全称          | 读写特性                    | 备注                                           |
| :-------- | :---------- | :---------------------- | :------------------------------------------- |
| **MROM**  | 掩模式只读存储器    | 生产过程中直接写入，任何人不可重写。      | 可靠性高、灵活性差、生产周期长，适合批量定制。                      |
| **PROM**  | 可编程只读存储器    | 用户可用专门的写入器写入信息，但只能写入一次。 | 较 MROM 灵活，但依旧不可更改。                           |
| **EPROM** | 可擦除可编程只读存储器 | 可通过特殊手段擦除后多次重写。         | 分为 **UVEPROM**（紫外线擦除全部）和 **EEPROM**（电擦除特定字）。 |

| 芯片类型             | 全称        | 读写特性                    | 备注                            |
| :--------------- | :-------- | :---------------------- | :---------------------------- |
| **Flash Memory** | 闪速存储器（闪存） | 基于 EEPROM 发展，支持快速擦除与重写。 | 如 U盘、SD卡。写速度通常慢于读速度（需先擦除再写入）。 |
| **SSD**          | 固态硬盘      | 由控制单元和多块闪存芯片构成。         | 速度快、功耗低，正在逐步取代传统的机械硬盘。        |

---
## 3.4 多模块存储器

### 3.4.1 多模块存储器
多模块存储器利用**空间并行技术**，通过多个独立的存储体（内存条）并行或交叉工作，缓解单体存储器的恢复时间瓶颈。

| 特性       | 高位交叉编址（连续编址）              | 低位交叉编址（交叉编址）                               |
| :------- | :------------------------ | :----------------------------------------- |
| **编址方式** | 高位地址为体号，低位地址为体内偏移。        | 低位地址为体号，高位地址为体内偏移。                         |
| **存储规律** | 地址连续的数据存放在同一个存储体中。        | 地址连续的数据分布在不同的存储体中。<br>**模块号=单元地址 mod 模块数** |
| **并行性**  | 由于CPU按顺序访问存储模块，无法实现流水线存取。 | 可实现**存取流水线**。                              |
| **主要作用** | 单纯扩充存储容量。                 | **大幅提升访存速度**，提高带宽。                         |

---

### 3.4.2 低位交叉编址的启动方式
#### 3.4.2.1 轮流启动
当**每个模块一次读/写的位数恰好等于数据总线位数**时，使用轮流启动。
在低位交叉编址中，若存储体个数为 $m$，存取周期为 $T$，存取时间（或总线传输周期）为 $r$：

* **模块数要求**：为了保证流水线不间断，模块数 $m$ 必须满足 $m \ge T/r$。
    * 若 $m < T/r$，则在访问完一轮后，第一个模块尚未完成恢复，流水线会出现断流。
    * 若 $m > T/r$，模块资源会出现闲置，造成成本浪费。
* **存取 $n$ 个字的总耗时**：
    $$Total = T + (n - 1)r$$
* **微观理解**：第一个字读出耗时 $T$，后续 $n-1$ 个字由于流水线效应，每个仅需 $r$ 时间即可产出。
* **访存冲突**：如果相邻的访存地址出现在同一个模块内，则会出现访存冲突，此时需要延迟发生冲突的访问请求。

#### 3.4.2.2 同时启动
当**所有存储模块一次并行读/写的总位数恰好等于存储器数据总线宽度**时，采用同时启动方式。
并行访问以**连续的8字节为单位**进行，即每次读取的数据只能来自地址对齐的块，若未对齐则需要两次访存。

---
### 3.4.3 单体多字存储器
* **原理**：在一个存取周期内，从存储器中同时读出 $m$ 个字。
* **硬件要求**：数据总线宽度需增加至 $m$ 个字的宽度。
* **优缺点**：
    * **优点**：结构简单，能显著提升地址连续数据的访问速度。
    * **缺点**：灵活性差。若访问的变量不连续或跨行分布，会读入大量冗余数据。

---
## 3.5 主存储器与CPU的连接

在计算机系统中，主存储器通常由多块存储芯片组成。由于单块存储芯片的容量和字长有限，需要通过特定的连接方式与 CPU 连通，以充分利用 CPU 的寻址能力和数据总线的传输能力。

* **数据总线**：与 CPU 的 **MDR** 相连。其位数和频率的乘积决定数据传输速率。
* **地址总线**：与 CPU 的 **MAR** 相连。其位数决定了CPU的寻址范围。
* **控制总线**：因存储器类型而异。
	* SRAM芯片通常包含片选和读/写控制信号线。
	* ROM芯片仅需片选线。
	* DRAM仅读/写控制线，一般不设片选线(可通过行列地址选通)。

### 3.5.1 存储容量扩展方式

#### 3.5.1.1 位扩展法
* **适用场景**：单块存储芯片的**字长**小于数据总线的宽度。
* **连接方式**：
    * 将多块芯片的**地址线**、**读写控制线**、**片选线**并联。
    * 各芯片的数据线分别引出，连接到数据总线的不同位上。
* **结果**：增加了存储字长，但存储字数（地址范围）保持不变。

#### 3.5.1.2 字扩展法
* **适用场景**：单块存储芯片的**字数**（容量）少于 CPU 的寻址范围。

#### 3.5.1.3 字位同时扩展法
* **适用场景**：存储芯片的字长和字数均不能满足要求。
* **连接方式**：先进行位扩展形成“芯片组”，再对芯片组进行字扩展。

### 3.5.2 字扩展中的片选控制技术

在字扩展中，如何利用高位地址线选中特定芯片是关键，主要分为**线选法**和**译码片选法**。

| 比较维度     | 线选法                      | 译码片选法                   |
| :------- | :----------------------- | :---------------------- |
| **实现方式** | 每根高位地址线直接连接一个芯片的片选端      | 使用译码器处理高位地址             |
| **地址空间** | **不连续**                  | **连续**                  |
| **芯片数量** | 受限于地址线数量（$n$ 条线对应 $n$ 片） | 扩展能力强（$n$ 条线对应 $2^n$ 片） |
| **优点**   | 电路极其简单                   | 能够充分利用寻址空间              |
| **缺点**   | 地址空间浪费，容易出现地址重叠/冲突       | 电路相对复杂                  |

## 3.6 磁盘存储器
### 3.6.1 磁盘存储器基本原理

磁盘属于**磁表面存储器**，通过在记录介质表面涂覆磁性材料来存储二进制信息。

* **写入原理**：利用电磁铁（写磁头）产生的不同方向电流，改变磁性介质的磁极方向。
* **读取原理**：磁性介质移动划过读磁头时，由于切割磁感线产生感应电流，通过电流方向识别二进制状态。
* **物理特性**：
    * **串行读写**：每次只能读写**1比特**数据。
    * **不可同时读写**：读动作和写动作不能同步进行。
    * **非破坏性读出**：读取数据不会破坏原有磁场信息，无需再生。
    * **串并转换**：主机并行传输数据，磁盘控制器需通过专门电路完成串并行转换。

### 3.6.2 磁盘驱动器与控制器

磁盘存储器由磁盘驱动器、磁盘控制器和盘片组成。

* **磁盘驱动器**：磁盘由多个记录面组成，每面含有若干磁道，每条磁道被划分为若干扇区。
	- **记录面数**：对应磁头数量每个磁头负责一个记录面的数据读/写。
	- **柱面数**：表示单个记录面上的磁道数量，所有记录面上相同编号的磁道构成一个柱面。
	- **扇区数**：表示每条磁道包含的扇区数量，扇区是磁盘读/写的最小单位。
* **磁盘控制器**： 属于I/O控制器，负责实现磁盘与主机间的数据交互。

### 3.6.3 磁盘高速缓存
- 在内存中开辟一块空间用于暂存写入磁盘的数据。
- 磁盘以“簇”(由若干扇区组成)为单位进行读写操作，缓存可以减少频繁的小块写入。若在写入前被使用，可直接从缓存中读取。

### 3.6.4 磁盘性能指标计算

* **磁盘容量**：
    * **非格式化容量**：物理上能存储的比特上限。
    * **格式化容量**：排除坏道、备份扇区等用途，按特定格式组织后，实际可用的容量。
    * 非格式化容量大于格式化容量。
* **记录密度**：
    * **道密度**：沿半径方向单位长度的磁道数。
    * **位密度**：磁道单位长度记录的二进制位数。
    * **面密度**：位密度和道密度的乘积。
    * **注意**：越靠近内侧磁道，位密度越大；磁盘总容量常受限于最内圈磁道的位密度。
* **平均存取时间**：
    $平均存取时间 = 寻道时间 + 旋转延迟时间 + 传输时间 + 控制器延迟$
    * **寻道时间**：磁头移动到目标磁道的时间。
    * **旋转延迟**：通常取**转半圈**的时间。
    * **传输时间**：目标扇区经过磁头下方的时间。
* **数据传输率**：
    单位时间内向主机传送的字节数。
    $传输率 = 转速(r/s) \times 磁道容量(B)$

### 3.6.5 磁盘地址结构

| 地址分量         | 作用             |
| :----------- | :------------- |
| **柱面号（磁道号）** | 移动磁头臂到指定的径向位置。 |
| **盘面号（磁头号）** | 激活对应记录面的磁头。    |
| **扇区号**      | 在旋转过程中识别目标数据段。 |

### 3.6.6 磁盘阵列 (RAID)

RAID通过将多个独立物理磁盘组成阵列，利用并行访问和冗余校验提高性能和可靠性。

| RAID级别       | 核心思想            | 容错能力      | 存储效率         |
| :----------- | :-------------- | :-------- | :----------- |
| **RAID 0**   | 条带化，数据分散存储在不同盘。 | **无**     | 100%         |
| **RAID 1**   | 镜像备份，存两份相同数据。   | **强**     | 50%          |
| **RAID 2**   | 使用海明校验码（位级并行）。  | 有（纠一错检二错） | 较高（取决于校验位占比） |
| **RAID 3-5** | 使用奇偶校验等更复杂的机制。  | 逐步增强      | 随编号增大，冗余占比降低 |

* **RAID 0 的优势**：利用类似“低位交叉编制”的思想，实现并行访问，大幅提升读写带宽。
* **可靠性趋势**：从RAID 0到RAID 5，等级编号越大，冗余信息占比通常越优化，在保证安全的前提下降低了成本。

---
## 3.7 固态硬盘 SSD

### 3.7.1 核心概念与物理结构
* **物理基础**：固态硬盘基于**闪存技术**，本质上属于**电可擦除只读存储器（EEPROM）**。
* **组成部分**：
    * **闪存翻译层**：负责逻辑块号到物理地址的转换（映射）。
    * **存储介质**：由多个**闪存芯片**组成。
* **层次结构**：
    * **块**：擦除的基本单位。
    * **页**：读写的基本单位。一个块包含多个页。

---

### 3.7.2 读写性能特性
* **读写单位**：系统对 SSD 的读/写以**页**为单位。
* **擦除单位**：SSD 以**块**为单位进行擦除，只有整个块被擦除干净后才能向其中的页写入新数据。
* **写操作限制**：
    * 页被写入数据后，必须先擦除其所在的整个块，才能再次写入。
    * **读快写慢**：写操作可能触发数据迁移（将块内其他有效页复制到新块）和擦除动作，导致写速度远慢于读速度。
* **访问方式**：支持**随机访问**，通过电路直接定位物理地址，无须机械运动，访问延迟极低。

---

### 3.7.3 磨损均衡技术
由于 SSD 的闪存块具有擦写寿命限制（重复擦除次数过多会损坏），需要通过**磨损均衡**将“擦除”操作平均分布在各个块上。

* **动态磨损均衡**：在写入新数据时，优先选择累计擦除次数较少的空闲闪存块。
* **静态磨损均衡**：由控制器后台监测，将**读多写少**的静态数据迁移至老旧块，让较新的闪存块承担更频繁的写任务。

---
### 3.7.4 SSD 与机械硬盘对比

| 特性        | 固态硬盘（SSD）  | 机械硬盘（HDD）     |
| :-------- | :--------- | :------------ |
| **存储介质**  | 闪存芯片（电路控制） | 磁性物质（盘片旋转）    |
| **读写速度**  | 快          | 慢             |
| **噪音与功耗** | 安静、能耗低     | 有机械噪声、功耗较高    |
| **耐用性**   | 耐摔抗震，无机械部件 | 怕震动，机械部件易损    |
| **寿命限制**  | 闪存块有擦写次数上限 | 扇区不会因写入次数多而损坏 |
| **成本**    | 价格较贵       | 价格较便宜         |

---
* **地址映射**：由于数据迁移，SSD 的逻辑地址对应的物理地址是动态变化的，由闪存翻译层实时维护映射关系。

---
## 3.8 Cache

### 3.8.1 Cache 的性能分析
评价 Cache 系统性能的核心指标是**平均访问时间**。

* **命中率 ($H$)**：CPU 欲访问的信息已在 Cache 中的比率。
* **缺失率（未命中率）($M$)**：$M = 1 - H$。

| 访问策略 | 命中时的耗时 | 未命中时的耗时 | 平均访问时间公式 |
| :--- | :--- | :--- | :--- |
| **先访问 Cache，未命中再访问主存** | $t_c$ | $t_c + t_m$ | $t = H \times t_c + (1 - H) \times (t_c + t_m)$ |
| **同时访问 Cache 和主存** | $t_c$ | $t_m$ | $t = H \times t_c + (1 - H) \times t_m$ |

---
### 3.8.2 Cache 的存储结构与分块策略

为了方便管理，主存与 Cache 之间以**块**为单位进行数据交换。

#### 3.8.2.1 分块概念
* **主存分块**：将主存空间划分为大小相等的块。主存块常被称为**页**、**页面**或**页框**。
* **Cache 分块**：Cache 空间也被划分为与主存块大小相等的块。Cache 块常被称为 **Cache 行**。
#### 3.8.2.2 地址逻辑拆分
主存地址在逻辑上可以拆分为两个部分：
* **主存块号**：用于定位数据属于哪一个块。
* **块内地址**：用于定位块内的具体字节或字。

#### 3.8.2.3 基础组件与标记机制
* **Cache行/块**：Cache与主存交换数据的基本单位，大小相等。
* **有效位**：用于说明Cache行中的标记是否有效。
    * **1**：表示标记有效，Cache块已装入主存数据。
    * **0**：表示标记无效，Cache块初始状态或数据已失效。
* **标记**：记录对应主存块的标识信息。在不同映射方式下，标记所占位数不同。

#### 3.8.2.4 标记信息
- **有效位和标记位**：所有Cache必须包含的。
- **脏位**：仅采用回写法是存在。
- **LRU替换位**：仅使用LRU时存在。

---

### 3.8.3 三种映射方式详解

#### 3.8.3.1 直接映射
* **映射规则**：每个主存块只能映射到Cache中一个**特定**的位置。
    * 计算公式：$Cache行号 = 主存块号 \bmod Cache总行数$
* **工作原理**：CPU先通过地址中的行号定位到唯一的Cache行，仅需对比该行的标记和判断有效位。若缓存未命中则从主存中读取并装入对应Cache行，置有效位为1，更新标记为地址高位。
* **比较器**：仅需设置1个比较器。

#### 3.8.3.2 全相联映射
* **映射规则**：主存块可以存放到Cache的**任意**一个Cache行中。
* **工作原理**：CPU访问主存地址时，需将地址中的标记与Cache中**所有**行的标记进行对比。若标记匹配且有效位为1，则命中。
* **比较器**：需要设置n个比较器。

#### 3.8.3.3 组相联映射
* **映射规则**：Cache划分为若干组，主存块映射到特定的**分组**中，但在组内可以存放在**任意**位置。
    * 计算公式：$组号 = 主存块号 \bmod 分组数$
    * **n路组相联**：指每n个Cache行分为一组。
* **工作原理**：CPU先根据组号定位到组，然后在组内检索所有行的标记。
* **比较器**：n路组相联，需要设置n个比较器。

| 映射方式 | 空间利用率 | 命中率 | 标记对比速度 | 常用地址结构划分 |
| :--- | :--- | :--- | :--- | :--- |
| **全相联映射** | 最高 | 高 | 最慢（需比对全表） | 标记 + 块内地址 |
| **直接映射** | 最低 | 低 | 最快（仅需对比一次） | 标记 + 行号 + 块内地址 |
| **组相联映射** | 居中 | 居中 | 居中 | 标记 + 组号 + 块内地址 |

---
### 3.8.4 四种Cache替换算法

| 算法名称       | 英文缩写    | 替换规则              | 优点              | 缺点            | 局部性考虑          |
| :--------- | :------ | :---------------- | :-------------- | :------------ | :------------- |
| **随机算法**   | RAND    | 随机选择一块替换          | 实现最简单           | 命中率低，运行不稳定    | 未考虑            |
| **先进先出算法** | FIFO    | 优先替换最先进入 Cache 的块 | 实现简单（按行号轮询）     | 可能出现“抖动”，命中率低 | 未考虑            |
| **近期最少使用** | **LRU** | 替换最长时间未被访问的块      | **命中率最高**，效果最优秀 | 硬件实现相对复杂      | 充分考虑（时间局部性）    |
| **最不经常使用** | **LFU** | 替换到目前为止访问次数最少的块   | 统计了全局访问频率       | 可能保留不再使用的旧数据  | 考虑不周（易受历史数据干扰） |

---
### 3.8.5 近期最少使用算法

#### 3.8.5.1 硬件实现原理
每个 Cache 行设置一个 **计数器**，记录该行多久未被访问：
* **命中**：所命中行的计数器清 0，计数器值比其小的行加 1，其余不变。
* **未命中且有空闲行**：新块装入，计数器置 0，其余非空闲行计数器全部加 1。
* **未命中且无空闲行**：替换计数器值最大的块，新块计数器置 0，其余加 1。

#### 3.8.5.2 特点与优势
* 若 Cache 块数为 $2^n$，则计数器只需 $n$ 位即可。
* **抖动现象**：当频繁访问的主存块数量大于 Cache 行数时，LRU 仍可能发生抖动。

**记忆**：保留Recent(近期)的数据，替换最久为使用的数据。

---
### 3.8.6 最不经常使用算法

#### 3.8.6.1 硬件实现原理
每行设置一个计数器，装入新数据时将计数器置0，每次访问时计数器加一。替换时选择计数器值最小的。

#### 3.8.6.2 局限性
LFU 记录的是 **访问频率**。其失效场景通常在于：
* 某数据在短时间内被高频访问，导致计数器数值极大。
* 该阶段结束后，该数据不再被使用，但因计数器值过大而长期占据 Cache 空间，无法被淘汰。
* **结论**：全局统计不一定优于局部统计，LFU 的实际命中率往往不如 LRU。

**记忆**：保留Frequent(频率)高的数据，替换频率低的数据。

---
### 3.8.7 写命中时的策略

| 策略名称          | 核心机制                                         | 优缺点                                      |
| :------------ | :------------------------------------------- | :--------------------------------------- |
| **全写法** (直写法) | CPU 同时向 Cache 和主存写入数据。                       | **优点**：实时保持数据一致，实现简单；**缺点**：访存频繁，写操作速度慢。 |
| **回写法**       | 仅修改 Cache 中的副本。只有当该 Cache 行被替换（淘汰）时，才将其写回主存。 | **优点**：减少访存次数，速度快；**缺点**：存在数据不一致风险。      |

* **脏位**：写回法需为每个 Cache 行增加 1 位脏位。若脏位为 1，表示该行被修改过，替换时须写回主存；若为 0，则直接覆盖即可。
* **写缓冲**：全写法的优化手段。使用 SRAM 构成的 FIFO 队列。CPU 先将数据写入写缓冲，随后由专门控制电路在后台将其同步至主存，**缓解CPU与主存之间的速度差异**。若写操作过于频繁导致缓冲饱和，CPU 仍需阻塞等待。

---
### 3.8.8 写不命中时的策略

| 策略名称      | 核心机制                               | 配对习惯            |
| :-------- | :--------------------------------- | :-------------- |
| **写分配法**  | 先将主存中的目标块调入 Cache，然后在 Cache 中进行修改。 | 通常与**写回法**配合使用。 |
| **非写分配法** | CPU 直接向主存写入数据，不将该块调入 Cache。        | 通常与**全写法**配合使用。 |

### 3.8.9 Cache的应用
#### 3.8.9.1 分离Cache
现代处理器通常将指令Cache和数据Cache分开，形成分离的Cache结构。分离的Cache可以消除取指部件和执行部件访问同一Cache时产生的冲突，从而提升性能。

#### 3.8.9.2 多级Cache
按距离CPU距离分别称为L1 Cache、L2Cache等。

---
## 3.9 虚拟存储器
虚拟存储器是一种由硬件和系统软件协同实现的存储管理机制，它利用主存和辅存构建一个逻辑上连续且容量巨大的地址空间。

### 3.9.1 基本概念
- **逻辑地址/虚地址**：用户程序使用的地址称为逻辑地址。
- **物理地址/实地址**：实际主存单元的地址称为实地址。

由于辅存访问延迟极高，系统采用类似**回写**的策略。此外虚拟存储器的分页机制允许任一虚页装入主存中任意可用的物理页框，类似**全相联映射**。

**访存过程**：
1. 访问快表，若命中，得到物理地址，否则访问页表。
2. 通过物理地址访问Cache，若未命中则访问主存。

# 4 指令系统

## 4.1 指令的基本格式
### 4.1.1 指令系统基本概念

* **指令（机器指令）**：指示计算机执行某种操作的命令，是计算机运行的最小功能单位。
* **指令系统（指令集）**：一台计算机所能执行的所有指令的集合。
* **指令格式**：逻辑上由**操作码（OP）** 和**地址码（A）** 两部分组成。
    * **操作码**：指明执行的操作。
    * **地址码**：指明操作的对象及其存放位置。

---

### 4.1.2 地址码数量

* **零地址指令**：
    * **无需操作数**的指令（如停机、空操作、关中断）。
    * 堆栈型计算机中，**操作数隐含**在栈顶和次栈顶。
* **一地址指令**：
    * 单操作数指令（如加1、求反、求补），结果存回原地址。
    * 双操作数指令，**其中一个操作数隐含**在寄存器（如 **ACC**）中。
* **二地址指令**：常用于算术和逻辑运算，指令格式为 `(A1) OP (A2) -> A1`。
* **三地址指令**：显式指明结果存放地址，格式为 `(A1) OP (A2) -> A3`。
* **四地址指令**：在三地址基础上增加下一条指令的地址 `A4`。执行后会将程序计数器 **PC** 的值修改为 `A4`。

---
### 4.1.3 指令字长

| 概念       | 定义                  | 备注           |
| :------- | :------------------ | :----------- |
| **指令字长** | 一条指令的总长度（比特数）       | 长度可变，影响访存次数  |
| **机器字长** | CPU 一次整数运算能处理的二进制位数 | 通常与 ALU 直接相关 |
| **存储字长** | 一个存储单元中的二进制代码位数     | 通常与 MDR 位数相同 |

* **定长指令字结构**：指令系统中所有指令长度相等。
* **变长指令字结构**：指令系统中各类指令长度不等。

---
### 4.1.4 定长操作码

 **优点**：控制器译码电路设计简单。
 **缺点**：灵活性低，限制了指令总数（$n$ 位操作码最多支持 $2^n$ 条指令）。

### 4.1.5 扩展操作码

扩展操作码通常采用**定长指令字结构**，通过牺牲地址码位数来增加操作码位数。

* **不允许短码是长码的前缀**：短操作码不能与长操作码的前缀相同。
* **各指令操作码不重复**：确保每条指令具有唯一性。
* **频率优先原则**：通常为**使用频率较高**的指令分配**较短**的操作码，以减少指令译码和分析的时间。

| 分类        | 定义                           | 优点                       | 缺点                         |
| :-------- | :--------------------------- | :----------------------- | :------------------------- |
| **定长操作码** | 整个指令系统中所有指令的操作码长度均相同。        | 简化计算机硬件设计，指令译码与识别速度快。    | 指令数量增加时会占用更多固定位，限制了地址码的位数。 |
| **扩展操作码** | 全部指令的操作码字段位数不固定，长度随地址码减少而增加。 | 在指令字长有限的前提下，能保持较丰富的指令种类。 | 增加了指令译码和分析的难度，使控制器设计复杂化。   |

---
### 4.1.6 操作类型

1.  **数据传送类**：实现主存与 CPU 寄存器之间的数据交换。
2.  **运算类**：算术运算、逻辑运算、移位操作。
3.  **程序控制类**：改变程序的执行顺序。本质是修改 **PC** 的值。
4.  **输入输出类**：实现 CPU 与 I/O 设备（通过端口寄存器）之间的数据传送。
5. **CPU控制类**：停机、开中断、关中断等。

---

## 4.2 指令寻址

**指令寻址**是指确定**下一条**欲执行指令的存放地址的过程。在计算机运行过程中，该地址始终由**程序计数器（PC）** 给出。

### 4.2.1 顺序寻址

顺序寻址是指程序按指令序列在存储器中存放的顺序执行。

* **基本原理**：每取出一条指令，CPU 自动修改 PC 的内容，使其指向下一条相邻的指令。
* **计算公式**：$(PC) + \text{“1”} \rightarrow PC$。
* **“1”**：此处的“1”是一个抽象的**指令字长**，表示**当前指令的字节长度**，实际的数值取决于**编址方式**和**指令字长**。

### 4.2.2 跳跃寻址

跳跃寻址是指通过执行**转移类指令**（如无条件转移、条件转移、子程序调用等）直接修改 PC 的值，从而改变程序的执行顺序。

* **执行流程**：
    1.  **取指阶段**：CPU 取出转移指令后，PC 仍会先完成自动加“1”（指向原本顺序的下一条指令）。
    2.  **执行阶段**：在执行该转移指令时，CPU 根据指令中的地址码计算出目的地址，并**强行修改** PC 的值。
- **转移方式**：
	1. **绝对转移**：地址码直接给出目标地址。
	2. **相对转移**：地址码给出相对于当前PC值的偏移量。
* **核心影响**：程序的执行流不再受内存存放顺序限制，实现逻辑跳转。

---
## 4.3 数据寻址
为区分不同寻址方式，指令字中通常设有**寻址特征**字段，其位数决定了可支持的寻址方式种类。

### 4.3.1 隐含寻址
* **特点**：指令中不明显给出操作数的地址，而是由操作码**隐含**指定。
* **应用场景**：如单地址指令中，另一个操作数默认在累加寄存器（ACC）中。
* **优点**：缩短指令字长。
* **缺点**：可有效缩短指令字长，依赖硬件电路来实现隐含操作。

### 4.3.2 立即寻址
* **特点**：指令的形式地址部分不是地址，而是**操作数本身**（又称立即数）。
* **标识**：在汇编语言中常带符号“**#**”。
* **数据形式**：通常采用**补码**表示。
* **优缺点**：执行速度最快（指令执行阶段无需访存），但操作数范围受限于指令中地址字段的位数。

### 4.3.3 直接寻址
* **特点**：指令字中的形式地址 A 就是有效地址，即 **EA = A**。
* **优缺点**：简单、执行阶段仅需**一次访存**；但寻址范围受限，且程序不便于修改和移动。

### 4.3.4 间接寻址
* **特点**：形式地址指向的是操作数有效地址所在的**存储单元**。
* **公式**：**EA = (A)**。
* **多级间址**：如果存储单元的首位为 1，则表示该单元存储的是下一级地址；为 0 则表示是有效地址。
* **优点**：**扩大了寻址范围**，便于编制子程序返回。
* **缺点**：多次访存导致指令执行效率降低。

### 4.3.5 寄存器寻址
* **特点**：形式地址指明的是 CPU 内部**寄存器的编号**，操作数存放在该寄存器中。
* **公式**：**EA = Ri**。
* **优点**：执行阶段无需访存，只访问寄存器，速度快；指令字长较短。

### 4.3.6 寄存器间接寻址
* **特点**：寄存器中存放操作数在主存中的**有效地址**。
* **公式**：**EA = (Ri)**。
* **特点总结**：比一般的间接寻址快，因为寻找有效地址的过程不需要访问主存。

### 4.3.7 偏移寻址
偏移寻址是一类通过将某个**基准地址**与指令中给出的**形式地址（A）** 相加，从而计算出**有效地址（EA）** 的寻址方式。其核心公式为：$EA = \text{基准地址} + A$。

根据基准地址选取来源的不同，偏移寻址分为以下三种：

| 寻址方式     | 基准地址来源          | 形式地址 A 的角色 | 主要应用场景             |
| :------- | :-------------- | :--------- | :----------------- |
| **基址寻址** | 基址寄存器（BR）或通用寄存器 | 偏移量        | 多道程序并发、程序浮动、扩大寻址范围 |
| **变址寻址** | 变址寄存器（IX）或通用寄存器 | 基地址（起点）    | 循环程序设计、数组处理        |
| **相对寻址** | 程序计数器（PC）       | 位移量（可正可负）  | 转移类指令、一段代码在程序内的浮动  |

#### 4.3.7.1 基址寻址
* **实现原理**：将 CPU 中基址寄存器的内容加上指令格式中的形式地址 $A$，形成操作数的有效地址。$EA = (BR) + A$。
* **管理权限**：基址寄存器是**面向操作系统**的。其内容由操作系统或管理程序确定，在程序执行过程中，BR 内容不变，而形式地址 $A$ 可变。
* **核心作用**：
    * **便于程序浮动**：程序可以加载到主存的任意位置，只需修改 BR 的值即可，无需改动指令中的地址码。
    * **扩大寻址空间**：BR 通常位数较长，可以访问比形式地址 $A$ 更大的地址范围。

#### 4.3.7.2 变址寻址
* **实现原理**：有效地址 $EA$ 等于指令字中的形式地址 $A$ 与变址寄存器 $IX$ 的内容相加之和。$EA = (IX) + A$。
* **管理权限**：变址寄存器是**面向用户**的。程序员可以通过指令直接修改 IX 的内容。
* **核心作用**：
    * **循环与数组处理**：在处理数组时，设定 $A$ 为数组的首地址，通过不断改变 $IX$ 的内容（偏移量），即可轻松访问数组中的各元素。
* **基址与变址复合寻址**：在实际应用中，常将两者结合使用。例如，在程序浮动的情况下访问数组，计算公式为：$EA = (IX) + ((BR) + A)$。

#### 4.3.7.3 相对寻址
* **实现原理**：把程序计数器 PC 的内容加上指令格式中的形式地址 $A$ 形成有效地址。$EA = (PC) + A$。
* **关键点**：$A$ 是相对于**下一条指令地址**的位移量。因为 CPU 取出当前指令后，PC 会自动完成“自增”操作，指向下一条指令。
* **核心作用**：
    * **转移指令**：广泛用于跳转类指令。
    * **局部浮动**：方便一段代码在程序内部移动位置，只要跳转目标与跳转指令的相对距离不变，就不需要修改地址码。

---

### 4.3.8 堆栈寻址
**堆栈寻址**是指指令的操作数存放在堆栈中，通过**堆栈指针（SP）** 进行隐含寻址的一种方式。
* **物理本质**：堆栈是存储器（或专用寄存器组）中一块特定的按“**后进先出（LIFO）**”原则管理的存储区。
* **地址指定**：指令中不需要显式给出操作数的地址，其地址隐含在专用的寄存器**SP**中，SP始终指向当前的**栈顶元素**。

---

**硬堆栈 和 软堆栈**：
根据存放介质的不同，系统堆栈主要有两种实现形式：

| 维度       | **硬堆栈**             | **软堆栈**                   |
| :------- | :------------------ | :------------------------ |
| **实现方式** | 由一组专用的**寄存器**组成     | 从**主存**中划出一片特定区域          |
| **访问速度** | **快**（无需访存，仅需访问寄存器） | **慢**（需要进行访存操作）           |
| **成本**   | 高                   | 低                         |
| **访存次数** | 指令执行期间**0次**访存      | 指令执行期间需**1次**访存（Pop/Push） |
| **应用场景** | 寄存器资源充足的特定设计        | 实际系统中最常用（函数调用、局部变量保存）     |

---

**堆栈基本操作与指针变化**：

* **出栈操作**：
    1.  读取当前SP指向的单元数据。
    2.  SP内容自动修改，指向新的栈顶。
    3.  **有效地址**：操作发生时SP的初始指向。
* **入栈操作**：
    1.  SP内容先自动修改，预留出存储空间。
    2.  将数据写入当前SP指向的单元。
    3.  **有效地址**：修改后的SP值。

> SP的增减方向（加1还是减1）取决于系统设计的堆栈生长方向（向高地址生长还是向低地址生长）。这类操作由硬件自动完成。

---

### 4.3.9 总结

| 寻址方式 | 有效地址（EA） | 访存次数（执行期间） | 典型应用 |
| :--- | :--- | :--- | :--- |
| **隐含寻址** | 程序指定（如ACC） | 0 | 缩短指令长度 |
| **立即寻址** | 无（A即操作数） | 0 | 给变量赋初值 |
| **直接寻址** | EA = A | 1 | 访问静态变量 |
| **一次间接寻址** | EA = (A) | 2 | 扩大寻址范围 |
| **寄存器寻址** | EA = Ri | 0 | 速度最快 |
| **寄存器间接寻址** | EA = (Ri) | 1 | 常用寻址方式 |
| **相对寻址** | EA = (PC) + A | 1 | 转移指令、程序浮动 |
| **基址寻址** | EA = (BR) + A | 1 | 多道程序设计、扩展寻址 |
| **变址寻址** | EA = (IX) + A | 1 | 数组问题、循环程序 |
| **堆栈寻址** | 由SP确定 | 见硬/软堆栈对比 | 函数调用、中断处理 |

---
## 4.4 CISC 和 RISC
### 4.4.1 CISC 与 RISC 的基本概念

在指令系统的设计方向上，主要存在两种不同的设计哲学：**CISC**（复杂指令集计算机）与 **RISC**（精简指令集计算机）。

* **CISC**：
    * **设计思路**：增强指令功能，设置多功能指令，试图通过一条指令完成复杂的任务。
    * **典型代表**：**x86 架构**。
    * **应用领域**：台式机、笔记本、商业服务器等对功能复杂性要求较高的设备。
* **RISC**：
    * **设计思路**：简化指令功能，仅保留最基本、最常用的指令。复杂功能通过多条简单指令的组合来实现。
    * **典型代表**：**ARM 架构**。
    * **应用领域**：手机、平板电脑等对低功耗和高效率有要求的移动设备。

---
### 4.4.2 对比

| 对比项目       | CISC (复杂指令集)       | RISC (精简指令集)            |
| :--------- | :----------------- | :---------------------- |
| **指令系统**   | 复杂、庞大              | 简单、精简                   |
| **指令数目**   | 一般**大于 200 条**     | 一般**小于 100 条**          |
| **指令字长**   | **不固定** (变字长)      | **定长** (通常为一个字)         |
| **指令访存限制** | 不加限制 (如乘法指令可直接访存)  | **只有 Load/Store 指令**可访存 |
| **执行时间**   | 各指令相差较大            | 绝大多数在**一个时钟周期**内完成      |
| **使用频率**   | 相差很大 (符合 80/20 规律) | 各指令都比较常用                |
| **通用寄存器**  | 较少                 | **较多** (因中间结果需暂存)       |
| **目标代码**   | 难以通过编译器优化生成高效代码    | 采用优化编译器，目标代码效率较高        |
| **控制方式**   | 绝大多数为**微程序控制**     | 绝大多数为**组合逻辑控制** (硬布线)   |
| **指令流水线**  | 可以实现，但较困难          | **必须实现**，且效率极高          |
| **兼容性**    | 通常向后兼容             | 难以兼容老机型                 |

RISC更加节约芯片面积。由于指令数量少，格式统一，运算速度也更高。

---
# 5 中央处理器

## 5.1 CPU 的功能和基本结构

### 5.1.1 CPU 的功能
CPU 由**运算器**和**控制器**两大部件组成，其核心功能包括：
* **指令控制**：完成取指令、分析指令和执行指令的操作。
* **更新程序计数器**：确定下一条指令的地址。
* **取操作数和写结果**：访问主存或I/O接口，读取操作数或将运算结果写回。
* **时序控制**：对各种微操作实施时间上的定时，确保操作信号按先后顺序逐一发出。
* **数据加工**：对数据进行算术运算和逻辑运算。
* **处理中断和异常**：负责对计算机运行过程中的突发异常情况或外部请求进行处理。

---

### 5.1.2 运算器的基本结构
运算器主要负责对数据进行加工，其内部核心部件包括：
* **算术逻辑单元**：进行算术和逻辑运算的核心组合逻辑电路。
* **通用寄存器组**：如 AX、BX、CX、DX、SP（堆栈指针）等，用于存放操作数（源操作数、目的操作数及中间结果）和地址信息。
* **暂存寄存器**：用于暂时存放从主存读来的数据，防止破坏通用寄存器中的原内容。
* **累加寄存器**：专门用于暂时存放运算结果的通用寄存器。
* **标志寄存器(FR)**：又称程序状态字寄存器，保留由算术逻辑运算建立的各种状态信息（如溢出标志、符号标志、零标志、进位标志等）。

---

### 5.1.3 控制器的基本结构
控制器负责协调控制计算机各部件执行指令序列，主要由以下部件组成：
* **程序计数器(PC)**：指出下一条指令在主存中的存放地址，具有自增功能。
* **指令寄存器(IR)**：保存当前正在执行的指令。
* **指令译码器(ID)**：对指令的操作码字段进行译码，向控制器提供特定的操作信号。
* **操作信号发生器**：根据指令、状态信息（来自标志寄存器）及周期信号，产生控制整个计算机系统所需的各种控制信号。
* **时序系统**：用于产生各种时序信号，由统一时钟分频得到。
* **存储器地址寄存器(MAR)**：存放欲访问的主存单元地址。
* **存储器数据寄存器(MDR)**：存放向主存写入的信息或从主存读出的信息。
* **总线控制**：实现对总线传输的控制。
* **中断机构**：实现对异常情况和外部中断请求的处理。

---
### 5.1.4 寄存器的可见性

| 用户可见（可由指令读写） | 用户不可见（对用户透明） |
| :----------- | :----------- |
| **程序计数器**    | **指令寄存器**    |
| **基址寄存器**    | **存储器地址寄存器** |
| **通用寄存器组**   | **存储器数据寄存器** |
| **累加寄存器**    | **暂存寄存器**    |

还有一类**用户只读的存储器**，即**标志寄存器(FR)**，内容只能由ALU修改。

---
## 5.2 指令执行过程
### 5.2.1 指令周期

**指令周期**是指 CPU 从主存中取出并执行一条指令所需的全部时间。

* **组成层次**：指令周期通常由若干个**机器周期**（也称 **CPU 周期**）组成，而一个机器周期又包含若干个**时钟周期**（也称**节拍**、**T 周期**）。
* **时钟周期**：CPU 操作的**最基本单位**，其倒数即为 CPU 主频。
* **周期关系**：一个指令周期内机器周期的个数可以不等，每个机器周期内的节拍数也可以不等。

---
### 5.2.2 指令周期的阶段

| 阶段名称        | 核心操作                          |
| :---------- | :---------------------------- |
| **取指**      | 从主存取出指令代码放入 IR，同时 PC 自动加 "1"。 |
| **译码/读寄存器** | 识别操作码和寻址方式，从寄存器中读取操作数，提取立即数。  |
| **执行**      | 根据操作码和操作数进行相应的运算处理。           |
| **访存**      | 若需访问主存，则通过Cache或主存完成读/写操作。    |
| **写回**      | 将结果写回Cache或主存                 |
| **中断响应**    | 检查中断请求，保存程序断点（压栈）。            |

---
### 5.2.3 指令执行模型

| 名称         | 特点                                                          | 系统效率 |
| :--------- | :---------------------------------------------------------- | :--- |
| **单周期处理器** | 所有指令选用**相同且固定**的执行时间（按最慢指令设定），指令间串行。每条指令都在一个时钟周期内完成(CPI=1)。 | 很低   |
| **多周期处理器** | 不同指令选用**不同数量**的机器周期，指令间串行。各指令的CPI不同，平均CPI通常大于1。             | 较高   |
| **流水线方案**  | 多条指令在不同阶段**并行执行**，每个时钟周期启动一条新指令。理想情况下CPI=1。                 | 最高   |

单周期处理器不能采用单总线结构的数据通路，因为单总线将所有寄存器都连接到一条公共总线上，一个时钟周期内只允许一次操作，无法完成一条指令的所有操作。

---
## 5.3 数据通路

**数据通路**是指令执行过程中，数据传送的路径和途径的功能部件(如ALU和通用寄存器等)。

### 5.3.1 数据通路的组成
#### 5.3.1.1 组合逻辑元件/操作元件
**特点**：
- 任意时刻的输出仅由当前输入决定。
- 不含记忆单元，不受时钟控制，且无输出到输入的反馈通路。
**应用**：ALU、译码器、多路选择器(MUX)和三态门等。

#### 5.3.1.2 时序逻辑元件/状态元件
**特点**：
- 输出取决于当前输入和电路的历史状态。
- 包含记忆单元，必须在时钟的同步控制下工作。
**应用**：各类寄存器和存储器。

数据通路的基本结构可抽象为时序逻辑元件和组合逻辑元件的交替连接的形式。
- **寄存器延迟 $T_{ \text{clk\_to\_q} }$**：从时钟上升沿开始到寄存器稳定输出的时间。
- **关键路径延迟 $T_{max}$**：所有输出信号达到稳定所需的最长时间。
- **寄存器建立时间 $T_{setup}$**：输入必须在时钟沿到来之前保持稳定的时间。
**最小时钟周期必须不小于**$T_{clk\_to\_q}+T_{max}+T_{setup}$。，其中$T_{max}$是关键因素，缩短关键路径延迟是提升系统频率的关键手段。

---
### 5.3.2 数据通路的分类

| 特性        | 专用数据通路                    | 单总线                   | 多总线     |
| :-------- | :------------------------ | :-------------------- | ------- |
| **连接方式**  | 根据数据流动方向在部件间安排专门连线        | 所有寄存器输入/输出端连接到一条公共通路上 | 多条独立总线。 |
| **性能**    | 性能较高，基本不存在数据冲突            | 性能较低，数据传输存在较多冲突       |         |
| **结构复杂度** | 结构复杂，硬件量大，连线繁琐            | 结构简单，容易实现             |         |
| **常用组件**  | 使用**多路选择器**或**三态门**管理多条通路 | 必须配合**暂存寄存器**来解决总线冲突  |         |

| **数据通路类型**  | **执行过程**                                                                        | **时钟周期长度决定因素**   | **特点**                    |
| ----------- | ------------------------------------------------------------------------------- | ---------------- | ------------------------- |
| **单周期数据通路** | 每条指令的所有操作（取指、译码、执行、访存、写回等）都在一个时钟周期内完成。                                          | 由最慢的指令决定。        | 控制简单，资源利用率低。              |
| **多周期数据通路** | 将一条指令的执行划分为多个阶段（如取指、译码与读寄存器、执行/地址计算、访存、写回等），每个阶段在一个时钟周期内完成。各阶段的结果在时钟边沿被锁存到寄存器中。 | 通常以一次存储器访问时间为基准。 | 相比单周期设计，提高了硬件复用率，缩短了时钟周期。 |
| **流水线数据通路** | 将指令执行过程分解为若干独立、可重叠的阶段，不同指令在不同阶段并发推进。每个阶段由专用功能部件完成，并通过流水段寄存器隔离和传递中间结果。           | 由最长阶段决定。         | 理想情况下，每个周期可以完成一条指令。       |

单周期数据通路无需设置IR，若设置IR则至少需要2个时钟周期。

---
### 5.3.3 内部总线与系统总线的对比分析

| 概念名称     | 定义与连接对象                          | 作用范畴       |
| :------- | :------------------------------- | :--------- |
| **内部总线** | 连接 CPU 内部各寄存器（PC、IR、ACC 等）及运算部件。 | CPU 内部数据交换 |
| **系统总线** | 连接计算机系统的各部件（CPU、内存、I/O 接口等）。     | 计算机全局通信    |

---
### 5.3.4 单总线 和 多总线

| 结构类型    | 硬件成本 | 数据传输效率 | ALU 配套要求          |
| :------ | :--- | :----- | :---------------- |
| **单总线** | 低    | 低      | **必须**设置暂存寄存器 $Y$ |
| **多总线** | 高    | 高      | 可不设暂存器，直接从不同总线输入  |

### 5.3.5 专用数据通路结构

**专用数据通路**是指在任何两个需要进行数据流动的部件之间，建立起专门的物理连接。这种结构与单总线结构相比，其核心优势在于支持**并行操作**。

* **基本原理**：通过控制信号来控制特定通路的导通。当控制信号有效时，数据即可在对应的专用线路上流通。
* **性能特点**：由于各部件间通路独立，允许指令执行过程中的多组数据同时传输，显著提升了指令执行速度，但硬件造价成本较高。
* **冲突解决**：当一个部件（如寄存器）有多个输入来源时，通常采用以下两种逻辑组件进行选择：
    * **多路选择器（MUX）**：根据控制信号选择其中一路输入。
    * **三态门**：通过控制端使能特定的输入线路，确保同一时间只有一个信号源驱动总线或输入端。

---

### 5.3.6 专用数据通路与单总线结构对比

| 特性       | 单总线结构           | 专用数据通路结构        |
| :------- | :-------------- | :-------------- |
| **连接方式** | 所有部件挂载在一条公共总线上  | 需求部件之间建立独立点对点连接 |
| **并发性**  | 同一时刻仅允许两个部件交换数据 | 支持多个部件对同时进行数据交换 |
| **执行效率** | 较低              | 较高              |
| **硬件成本** | 较低              | 较高              |

## 5.5 微程序控制器

### 5.5.1 基本术语

将每条`机器指令`编写为一段`微程序`，`微程序`由若干条`微指令`组成，每条`微指令`可产生一个或多个`微命令`。

| 核心概念          | 定义与特点                                               | 数量对应关系                        |
| :------------ | :-------------------------------------------------- | :---------------------------- |
| **微命令 和 微操作** | 微操作是具体要完成的动作，微命令是驱使该动作发出的控制信号。                      | **一一对应**。                     |
| **微指令**       | 包含**操作控制字段**（指明对应哪些微操作）和**顺序控制字段**（下地址，指明下一条微指令地址）。 | 一条微指令可包含多个微命令，即**并行完成多个微操作**。 |
| **微程序**       | 由一系列微指令序列组成，是对某一条具体机器指令执行步骤的描述。                     | 一个微程序包含多条微指令。                 |
| **机器指令**      | 对程序执行步骤的描述。机器指令实际上是对微指令功能的封装。                       | 每一种机器指令对应**一个**微程序。           |

- **微指令**：通常包含以下两个字段
	- **操作控制字段/微操作码字段**：用于生成当前步骤所需的微操作控制信号。
	- **顺序控制字段/下址字段**：用于确定下一条微指令的地址。
- **微周期**：执行一条微指令所需的基本时间单位，通常为一个时钟周期。

---
### 5.5.2 微程序控制器的基本结构

#### 5.5.2.1 核心硬件部件

* **控制存储器 (CM)**：用于存放所有机器指令对应的微程序。
    * 采用**只读存储器 (ROM)** 构成，按地址寻访，速度快且掉电非易失。
* **微地址形成部件**：根据机器指令的**操作码 (OP)**，产生该指令对应的执行周期微程序的第一条微指令的存放地址（初始微地址）。
* **顺序逻辑**：用于控制微指令的执行顺序。它根据机器标志、时序信息以及当前微指令的“下地址”，来确定下一条微指令的存放地址。
* **地址译码器**：将微地址寄存器中的地址信息转化为存储单元的电信号，以控制 CM 读出微指令。

#### 5.5.2.2 内外硬件结构类比

| 外部系统 (主存与CPU)    | CU内部系统 (微程序控制器)    | 核心作用与说明                                       |
| :--------------- | :----------------- | :-------------------------------------------- |
| 主存储器             | **控制存储器 (CM)**     | 存放微程序序列。                                      |
| MAR (地址寄存器) / PC | **CMAR ($\mu$PC)** | **微地址寄存器**：指明接下来要执行的微指令在 CM 中的存放地址。           |
| MDR (数据寄存器) / IR | **CMDR ($\mu$IR)** | **微指令寄存器**：暂存从 CM 中读出的当前正在执行的微指令，其位数与微指令字长相同。 |

---
### 5.5.3 工作原理

#### 5.5.3.1 工作流程与公共微程序段
* 当一条机器指令被取到 IR 后，其操作码会被送入**微地址形成部件**，从而定位到该指令对应的微指令序列的首地址。
* **执行周期的微程序各不相同**：不同的机器指令需要完成的操作不同，因此各自对应专属的执行周期微程序段。
* **取指、间址、中断周期是公用的**：任何指令在这三个周期内要做的事情（微操作序列）都是相同的。因此在 CM 中，这些周期的微程序段**通常只需要各自保存一份**即可，供所有指令共享。

#### 5.5.3.2 微程序数量的计算
* 如果某指令系统中有 $n$ 条机器指令，则 CM 中微程序的个数**至少是 $n+1$ 个**。
    * 包含：$n$ 个不同指令的执行周期微程序段 + $1$ 个公用的取指周期微程序段。
    * *注：早期 CPU 或物联网微型 CPU 可能不提供间接寻址和中断功能，因此可以不包含间址和中断周期的微程序段。*
* 在逻辑上，我们把取指、间址、执行、中断这四个微程序段看作一个整体，所以“一条指令对应一个完整的微程序”的说法是正确的。

---
### 5.5.4 硬布线控制器和微程序控制器对比

| 特性       | 硬布线控制器             | 微程序控制器               |
| :------- | :----------------- | :------------------- |
| **实现方式** | **组合逻辑电路**（纯硬件）    | **存储程序原理**（软硬结合）     |
| **执行速度** | **快**（延迟仅受门电路限制）   | **慢**（需从控制存储器读取微指令）  |
| **可扩充性** | **差**（修改指令需重新设计电路） | **好**（通过修改控制存储器内容实现） |
| **应用领域** | **精简指令集系统（RISC）**  | **复杂指令集系统（CISC）**    |

## 5.6 微指令的设计
### 5.6.1 微指令格式
在设计微指令时，需要考虑多个微操作能否同时执行。
* **相容性微命令**：允许同时并行的微命令。
* **互斥性微命令**：不允许并行的微命令。

根据微指令的结构，通常分为以下三种格式：

| 格式类型    | 特点与原理                                                  | 优点                           | 缺点                            |
| :------ | :----------------------------------------------------- | :--------------------------- | :---------------------------- |
| **水平型** | 一条微指令可以定义多个可并行的微命令。**控制字段**的各个位直接控制不同的微操作。微程序整体呈“胖矮”型。 | 微程序短（指令条数少）；执行速度快（**并行度高**）。 | 微指令字长过长；编写微程序较麻烦。             |
| **垂直型** | 每一条只能定义一个微命令，由**微操作码**指明具体微操作。微程序整体呈“瘦高”型。             | 每一条微指令较短；格式简单规整，便于编写。        | 微程序很长（指令条数多）；执行速度慢，工作**效率低**。 |
| **混合型** | 在垂直型的基础上增加一些不太复杂的并行操作。是前两者的折中。                         | 微指令较短，便于编写；微程序不长，执行速度加快。     | -                             |

### 5.6.2 微指令的编码方式
微指令的编码方式（或称控制方式）是指如何利用操作控制字段的二进制位来形成控制信号。其设计目标是在保证执行速度的情况下，尽量缩短微指令字长。

| 编码方式       | 原理说明                                             | 优点                           | 缺点                                 |
| :--------- | :----------------------------------------------- | :--------------------------- | :--------------------------------- |
| **直接编码**   | 操作控制字段中，**每一位代表一个具体的微操作命令**。规定某位为 $1$ 即发出相应控制信号。 | 简单直观；执行速度快，操作并行性良好；硬件电路设计简单。 | **微指令字长过长**；导致控制存储器容量极大，增加芯片面积和成本。 |
| **字段直接编码** | 将控制字段分为若干“段”，每一段经过**译码器**译码后发出对应的控制信号。           | 有效**缩短微指令字长**。               | 必须经过译码电路后再发出控制信号，**执行速度比直接编码慢**。   |
| **字段间接编码** | 一个字段的微命令需要由另一个字段的微命令来解释。又称隐式编码。                  | 进一步缩短指令字长。                   | 需要两层（多级）译码处理，**执行速度最慢**，并行控制能力降低。  |

**字段直接编码的分段原则**：
采用字段直接编码时，必须遵循以下重要原则：
1.  **互斥性微命令分在同一段内**，相容性微命令分在不同段内。
2.  每个分段中包含的信息位不能太多，否则会增加译码线路的复杂性和译码时间。
3.  每个分段**必须留出一个状态（通常用全 $0$ 表示）表示本字段“不操作”**。

### 5.6.3 下一条微指令地址的形成方式

1.  **断定法（下地址法）**：根据当前执行的微指令中的**下地址字段**直接指出下一条微指令的存放地址。
2.  **增量计数法**：类似机器指令的操作，通过 $\text{PC} + 1$ 的方式顺序找到下一条微指令。
3.  **微程序入口地址**：将指令操作码送入微地址形成部件，由其指明对应微程序的首地址。
4.  **分支转移**：遇到转移类微指令时，根据测试网络的状态和转移地址形成下一条微指令地址。
5.  **由硬件直接产生**：用专门硬件记录公共的入口地址（如取指周期、中断周期微程序的首地址）。

## 5.7 微程序控制单元的设计
### 5.7.1 微程序控制单元的设计步骤

#### 5.7.1.1 分析微操作序列
* 需要分析出所有指令在每个阶段所需执行的微操作序列。
* 与硬布线控制器将操作码送给指令译码器不同，微程序控制器需要将指令操作码送给**微地址形成部件**，由其指明该指令在执行周期对应的微程序起始地址。
* 相容的微操作可以安排在同一个节拍内（即同一条微指令内）并行完成。

#### 5.7.1.2 安排微操作与节拍
* 在第一步的基础上，将可并行的微操作安排在同节拍进行。
* **特有微操作一**：在每个机器周期内，除了最后一条微指令外，每条微指令结束之后都必须增加一个微操作：根据当前微指令的下地址信息，将其送入控制存储器地址寄存器，以指明下一条微指令的存放地址。该操作需消耗一个节拍。
* **特有微操作二**：在取指周期的最后一条微指令执行结束后，需要增加一个微操作：将**微地址形成部件**指明的微程序首地址送入控制存储器地址寄存器，以便进入执行周期。该操作同样消耗一个节拍。
* **注意**：由于需要不断补充指明下一条微地址的微操作，因此微程序控制器执行速度更慢。每个执行周期结束后，最后一条微指令的下地址通常会指回取指周期的第一条微指令地址，从而自然进入下一条机器指令的执行。

#### 5.7.1.3 确定微指令格式
* 微指令格式包含**操作码**和**下地址**两部分。
* 根据微操作的个数选择合适的编码方式（如直接编码、字段直接编码、字段间接编码），从而确定操作码控制字段的位数。
* 根据控制存储器中存储的微指令总数，确定顺序控制字段（下地址）的位数。
* 结合控制字段位数与顺序控制字段位数，最终确定微指令的字长。

#### 5.7.1.4 设计微指令码点并存入控制存储器
* 根据所选的编码方式及每条微指令需执行的操作，确定每条微指令控制码部分的具体二进制代码。
* 将确定好的所有微指令序列存入控制存储器中，完成设计。

### 5.7.2 微程序设计的分类与进阶

微程序设计根据其存储介质和可修改性，主要分为静态与动态两类。此外还有更底层的设计概念。

| 设计分类 | 核心特点 | 硬件支持 | 应用场景 |
| :--- | :--- | :--- | :--- |
| **静态微程序设计** | 微程序一旦写入便不可改变，无法扩展新指令。 | 只读存储器 | 早期或固化的简单处理器 |
| **动态微程序设计** | 允许在出厂后修改微指令序列，可扩充新机器指令或优化现有指令执行过程。 | 可擦除只读存储器芯片 | 现代处理器 |

* **毫微程序设计**：属于更底层的嵌套设计，使用**毫微指令**序列来解释和执行每一条微指令。

### 5.7.3 硬布线控制器与微程序控制器对比

| 对比维度      | 硬布线控制器                              | 微程序控制器                                         |
| :-------- | :---------------------------------- | :--------------------------------------------- |
| **工作原理**  | 依靠组合逻辑电路，结合指令操作码、机器状态及时序系统直接产生控制信号。 | 通过执行一条条微指令，发出相应的微操作控制信号。                       |
| **执行速度**  | 纯硬件思想实现，速度**更快**。                   | 需要频繁访问控制存储器读取微指令，速度**较慢**。                     |
| **电路规整度** | 电路结构不规整，设计繁琐。                       | 内部硬件构造和电路相对比较**规整**。                           |
| **修改与扩充** | 增加新指令非常困难，需重新设计内部组合逻辑电路。            | **易于扩充**，只需在控制存储器中添加或修改描述新指令的微指令序列即可，无需修改硬件电路。 |
| **适用指令集** | 适用于**精简指令集系统**，支持的机器指令条数少且相对固定。     | 适用于**复杂指令集系统**，支持指令种类多且经常需要扩充。                 |
| **设计成本**  | 较高，逻辑复杂。                            | 较低，便于规模化设计。                                    |

## 5.8 异常和中断
### 5.8.1 基本概念

| 维度       | 异常（内中断）                      | 中断（外中断）                         |
| :------- | :--------------------------- | :------------------------------ |
| **事件来源** | CPU内部，由当前执行的指令直接引发           | 外部设备，与当前指令的执行无关                 |
| **同步性**  | **同步事件**                     | **异步事件**（具有随机性）                 |
| **检测时机** | 指令执行过程中，或执行完成时立即响应           | 当前指令**完整执行结束**后才被检测，不打断当前指令的执行。 |
| **返回断点** | 通常需要重新执行第 $i$ 条指令（即**当前指令**） | 从第 $i+1$ 条指令开始继续执行（即**下一条指令**）  |

---
### 5.8.2 异常和中断的分类

#### 5.8.2.1 异常的分类
异常按发生原因可分为**硬故障中断**（终止）和**程序性异常**（故障和终止）。其中，程序性异常按发生原因和返回方式的不同，进一步细分为以下三种：

| 分类     | 触发性质          | 发生时机            | 返回断点                   | 举例                                |
| :----- | :------------ | :-------------- | :--------------------- | :-------------------------------- |
| **故障** | 被动检测的意外事件     | 指令启动之后、执行完成之前   | **当前指令**（处理后重新执行同一条指令） | 缺页（可恢复）、非法指令/除零错误（不可恢复致命错误，将终止进程） |
| **自陷** | **主动**触发的同步事件 | 指令**正常执行完毕后**触发 | **下一条指令**              | 断点调试指令、系统调用预设陷阱                   |
| **终止** | 严重的硬件故障错误     | 指令执行过程中发生       | 无法继续运行，强制终止程序          | 存储器校验错、总线错误、控制器出错                 |

#### 5.8.2.2 中断的分类
中断是外部设备发起的异步请求，进入中断响应周期后，可按是否能被屏蔽进行分类：

| 分类 | 屏蔽特性 | 适用场景 |
| :--- | :--- | :--- |
| **可屏蔽中断** | 受CPU控制器的中断屏蔽寄存器控制（允许被软件屏蔽） | 常规外部设备请求（如键盘输入、定时器周期性时钟中断） |
| **不可屏蔽中断** | **无法被软件屏蔽**，确保CPU能及时响应 | 处理具有最高优先级的紧急事件（如电源掉电、内存校验错） |

---
### 5.8.3 异常和中断的响应过程

响应过程是指从事件发生到转移至相应处理程序之间的**硬件自动操作序列**。完整过程由硬件与软件紧密协同完成，但在转移前的核心三阶段均由**硬件自动完成**：

1. **关中断**
   为确保保存上下文的原子性，CPU在响应初始阶段会自动屏蔽可屏蔽中断。硬件会将标志寄存器中的中断允许标志清零。不可屏蔽中断和部分高优先级异常仍可能在此期间发生。
2. **保存断点和程序状态**
   * **断点**：即返回地址，对于异常通常指向当前指令，对于中断通常指向下一条指令。
   * **程序状态字**：包含条件码、中断允许标志、特权级等系统运行状态。
3. **识别事件类型并转移至处理程序**
   * **硬件向量机制**（现代主流）：为每类事件分配唯一的类型号。事件发生时，CPU自动获取类型号，并以此为索引直接访问**中断向量表**，获取服务程序的入口地址并转移，**全程无须软件介入**。
   * **软件查询方式**（早期非向量中断）：通过软件依次读取各设备状态寄存器以确定中断源，效率极低。

## 5.9 指令流水线

### 5.9.1 流水线对指令集的要求
1. **指令长度统一**：避免取指周期不固定。
2. **指令格式规整**：确保源操作数寄存器字段位置固定，支持在译码前预取操作数。
3. **采用LOAD/STORE架构**：仅LOAD和STORE访问主存，便于调度。
4. **数据与指令按边界对齐存放**：确保单次访存即可获取完整操作数。

每个流水段之后都需设置一个**流水段寄存器**，用于锁存该段的输出结果，确保其能在下一个时钟周期供下一个流水段使用。

### 5.9.2 指令流水线的性能指标

**假设**：流水线分为 $K$ 个阶段，时钟周期为 $\Delta t$，共需执行 $N$ 个任务。
引入流水线后，执行 $N$ 个任务的总耗时为：$$T_K = (K+N-1) \times \Delta t$$
* **装入时间**：第一条指令从进入流水线到完全结束所经历的时间（即各部件陆续投入工作的时间）。
* **排空时间**：最后一条指令从进入流水线到完全结束所经历的时间（即各部件逐渐退出工作的时间）。

| 指标名称    | 定义与物理意义                  | 计算公式                                                                         | 理想极限值 ($N \to \infty$)            |
| :------ | :----------------------- | :--------------------------------------------------------------------------- | :-------------------------------- |
| **吞吐率** | 单位时间内流水线完成的任务（指令）数量      | $$TP = \frac{N}{T_K} = \frac{N}{(K+N-1)\Delta t}$$                           | $$TP_{max} = \frac{1}{\Delta t}$$ |
| **加速比** | 顺序执行总耗时与使用流水线执行总耗时的比值    | $$S = \frac{T_0}{T_K} = \frac{N \times K \times \Delta t}{(K+N-1)\Delta t}$$ | $$S_{max} = K$$                   |
| **效率**  | 流水线设备的利用率，即设备忙碌时间占总时间的比例 | $$E = \frac{N \times K \times \Delta t}{K \times T_K} = \frac{N}{K+N-1}$$    | $$E_{max} = 1$$                   |

---
### 5.9.3 五段式指令流水线

指令流水线将指令的执行过程划分为五个机器周期，通过在各阶段间增加**锁存器**（缓冲寄存器）暂存执行结果，并将各阶段耗时统一为耗时最长阶段的时间，从而方便流水线对齐安排。
* **取指阶段**：根据程序计数器访问指令存储器（通常命中指令缓存），取出指令放入锁存器。
* **译码阶段**：对指令进行译码，并从通用寄存器组中读取所需的操作数放入锁存器。
* **执行阶段**：利用**算术逻辑单元**对操作数（或立即数）进行运算处理，将运算结果存入锁存器。
* **访存阶段**：访问主存（通常命中数据缓存）进行数据的读写操作。
* **写回阶段**：将运算或访存获得的结果**写回到通用寄存器**中。

### 5.9.4 流水线的冒险

| 冲突类型          | 产生原因                                            | 解决办法                                                                                                                                               |
| :------------ | :---------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- |
| **结构冒险/资源冲突** | 多条指令在同一时刻争用同一个硬件资源（如访存阶段与取指阶段同争存储器，写回与译码同争寄存器）。 | 1. **暂停后续指令**一个周期等待资源。<br>2. **使用限制**，确保每个功能部件在每条指令中至多使用一次，且总在固定截断。<br>3. **增加硬件资源**。                                                              |
| **数据冲突**      | 后续指令必须等待前一条指令执行完毕并写回结果后，才能获取正确的操作数。             | 1. **暂停相关指令**（硬件阻塞插入气泡，或编译器及程序员插入空操作指令）。<br>2. **数据旁路技术**（转发机制）：将运算单元的输出端直接连到输入端，作为后续指令的操作数，下一跳指令即可不需要等待写回操作。<br>3. **编译优化**：调整不存在依赖关系的后续指令顺序提前执行。 |
| **控制冲突**      | 遇到条件转移指令、函数调用/返回或中断等改变程序计数器值的指令，导致原有的指令执行流断裂。   | 1. **分支预测**，**静态分支预测**为固定预测转移发生或不发生，**动态分支预测**为依据历史动态预测。<br>2. 预取转移成功和失败两个控制流方向上的目标指令。<br>3. **延迟分支**：插入分支延迟周期数的气泡。                                |

### 5.9.5 流水线的多发技术

| 技术名称               | 工作原理                                                      | 特征                                                                                                  |
| :----------------- | :-------------------------------------------------------- | :-------------------------------------------------------------------------------------------------- |
| **超标量流水线技术/动态多发射** | 在**同一个时钟周期**内，并行发射出多条独立指令。                                | 1. 属于**空分复用**技术。<br>2. 必须配置多个独立的功能部件（如多个算术逻辑单元）。<br>3. 依赖编译优化，通常**不能打乱**原有机器代码的按序排列（支持乱序发射的特殊架构除外）。 |
| **超流水技术**          | 将一个机器周期细分为多个更短的时间段，在**同一个周期的不同时间点**错开发射多条指令。              | 1. 属于**时分复用**技术。<br>2. 同一功能部件在一个周期内会被多次使用。<br>3. 同样不可调整程序的指令顺序，需靠编译程序优化指令队列。                        |
| **超长指令字/静态多发射**    | 编译器发掘指令间的潜在并行性，将多条能在不同部件并行的指令，合并拼装为**一整条**包含多个操作码字段的超长指令。 | 必须提供多个相互独立的处理部件以支撑多种操作同时进行运算。                                                                       |

### 5.9.6 指令执行过程

在精简指令集系统中，仅有**取数指令**和**存数指令**被允许访问主存，其余指令的操作数必须来自寄存器或立即数。

| 指令类型 | 取指 | 译码 | 执行 | 访存 | 写回 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **运算类指令** | 依据程序计数器取指令并存入锁存器 | 指令译码，将所需源操作数取至锁存器 | 算术逻辑单元进行数学或逻辑运算 | **空段**（不访存，但必须消耗对应时间） | 将算数逻辑单元的运算结果写回**目的寄存器** |
| **取数指令** | 同上 | 提取基地址和偏移量至锁存器 | 将基地址与偏移量相加，计算出**有效地址** | 根据有效地址从**数据缓存**中读取目标数据 | 将读取出的数据写回**目的寄存器** |
| **存数指令** | 同上 | 提取基地址、偏移量，并将**待存数据**取至锁存器 | 计算**有效地址**，同时将待存数据直接转存至下一级锁存器 | 根据有效地址，将数据写入**数据缓存**（后续同步回主存） | **空段** |
| **条件转移指令** | 同上 | 提取需要比对的两个操作数及偏移量 | 算术逻辑单元进行比对运算，得出条件是否成立 | 若条件成立，则计算目标地址并**写回程序计数器**（由于写回程序计数器耗时较短，通常安排在访存段完成） | **空段** |
| **无条件转移指令** | 同上 | 提取跳转偏移量至锁存器 | 直接计算目标地址并**提前写回程序计数器**（此举是为了尽早确定下一条指令地址，从而减少**控制冲突**） | **空段** | **空段** |

#### 5.9.6.1 转移指令的目标地址计算
转移类指令通常采用**相对寻址**，即以当前的程序计数器值为基准进行偏移。其目标地址计算公式为：

$$PC_{new} = (PC) + \text{指令字长} + (\text{偏移量} \times \text{指令字长})$$

**注意**：上式中的 $(PC)$ 指代的是**当前正在执行的这条转移指令**所存放的地址；而 $(PC) + \text{指令字长}$ 实际上就是顺序执行时的下一条指令地址。偏移量的含义是向前或向后偏移多少条指令。

## 5.10 多处理器

### 5.10.1 基本概念

| 架构类型 | 全称 | 并行类型 | 核心工作原理与结构特征 | 典型应用与局限性 |
| :--- | :--- | :--- | :--- | :--- |
| **SISD** | 单指令流单数据流 | 无（串行） | 包含**一个处理单元**和**一个存储器**，指令按顺序依次执行。可通过流水线技术或多模块交叉存储器提升性能。 | 传统单处理器架构。 |
| **SIMD** | 单指令流多数据流 | **数据级并行** | **一个控制单元**控制**多个处理单元**。一条指令同时操作不同数据。典型实现为**向量处理器**（以流水化方式批量处理一维数组）。 | 适用于规则、同构的数据处理。遇到条件分支时（因各处理单元需执行不同操作）效率显著降低。 |
| **MISD** | 多指令流单数据流 | 无实际应用 | 多个指令流同时处理同一个数据流。 | 仅在理论上存在，通用计算机中极少见。 |
| **MIMD** | 多指令流多数据流 | **任务级/线程级并行** | 多条指令分别处理多个不同数据流。分为两类：<br>1. **多计算机系统**：各节点拥有私有内存，无全局空间，通过消息传递通信。<br>2. **多处理器系统**：具有统一全局地址空间，通过访问共享存储器通信。 | 目前主流的并行计算模型，适用范围广，支持细粒度与粗粒度并发。 |

### 5.10.2 硬件多线程技术
硬件多线程技术通过为每个线程配备**独立的通用寄存器组**和**程序计数器**等上下文硬件，实现零开销或极低延迟的线程切换。

| 技术分类 | 切换时机与原理 | 优缺点分析 |
| :--- | :--- | :--- |
| **细粒度多线程** | **每个时钟周期**交替切换不同线程的指令。 | **优点**：有效提升功能部件利用率，大幅降低长延迟操作的影响。<br>**缺点**：单线程的执行速度被拖慢。 |
| **粗粒度多线程** | 仅当当前线程发生**高延迟事件**（如 Cache 缺失导致流水线阻塞）时，才切换至另一线程。 | **优点**：单线程执行不被打断，资源利用率高于单线程。<br>**缺点**：切换时需清空并重填流水线，切换开销大于细粒度。 |
| **同时多线程 (SMT)** | 在**单个时钟周期内**并发发射并执行来自多个线程的指令。 | **优点**：结合了指令级并行与线程级并行，利用超标量乱序执行架构最大化整体吞吐率。 |

### 5.10.3 多核处理器架构
多核处理器是指将多个**独立的处理单元**集成到单个芯片中，也称**片上多处理器**。
* **缓存结构**：通常每个核配备**私有的一级缓存**，所有核通过片内网络共享主存；部分架构会共享更高层级的缓存（如二级或三级缓存）。
* **并行方式**：主要通过**线程级**或**任务级**并行发挥硬件算力，区别于向量处理器的单指令控制多数据。

### 5.10.4 共享内存多处理器
所有处理器共享**统一的物理地址空间**，各处理器通过读写共享变量进行通信。根据内存访问延迟特性，分为两大类：

| 架构类型 | 内存访问特征 | 系统瓶颈与注意事项 |
| :--- | :--- | :--- |
| **统一存储访问 (UMA)** | 所有处理器访问任何内存单元的**延迟基本相同**，访存请求与目标物理位置无关。 | 随着核心数增加，多个处理器争用前端总线访问内存，易形成**系统性能瓶颈**。 |
| **非统一存储访问 (NUMA)** | 内存被划分为多个区域直连特定的处理器（本地内存）。处理器**访问本地内存极快**，但通过互连总线访问其他处理器的内存（远程内存）延迟较高。 | 程序性能对**数据布局极为敏感**，需要优化数据存放位置以降低访存延迟。 |

# 6 总线
## 6.1 总线概述
### 6.1.1 总线的分类

| 总线分类      | 功能描述                         |
| :-------- | :--------------------------- |
| **内部总线**  | 芯片内部各寄存器与算术逻辑单元之间的连接。        |
| **系统总线**  | 连接计算机系统内各功能部件。               |
| **I/O总线** | 用于连接主机与其内部的各类外设控制器（如显卡、网卡等）。 |
| **通信总线**  | 用于主机与外部设备，或不同计算机之间的通信。       |

**系统总线分为以下三类：**

| 系统总线类型   | 传输方向   | 核心功能与决定因素                                           |
| :------- | :----- | :-------------------------------------------------- |
| **数据总线** | **双向** | 传输数据、指令、操作数、状态字及中断类型号等。其位数决定了**中央处理器一次能并行传送的数据位数**。 |
| **地址总线** | **单向** | 指定要访问的**主存单元**或**外设端口**地址。其位数决定了**系统最大可寻址空间**。      |
| **控制总线** | 单/双向   | 传输协调与控制信号（如时钟、复位、总线请求/允许、中断请求/响应、读写等），确保各部件同步有序工作。  |

---
### 6.1.2 总线的性能指标

| 性能指标       | 概念解析                    | 特点                                           |
| :--------- | :---------------------- | :------------------------------------------- |
| **总线传输周期** | 完成一次完整总线事务（如一次读/写）的总时间。 | 通常由若干总线时钟周期组成。                               |
| **总线时钟频率** | 总线基础时钟信号的频率（时钟周期的倒数）。   | 现代总线时钟通常独立于中央处理器时钟。                          |
| **总线工作频率** | 总线每秒能进行的**有效数据传输次数**。   | 现代总线一个时钟周期可传多次数据，因此**工作频率 = 时钟频率 × 每次传输次数**。 |
| **总线宽度**   | 数据线的条数。                 | 决定每次能并行传输的数据位数。                              |
| **总线带宽**   | 单位时间内所能传输的最大数据量。        |                                              |
| **总线复用**   | 同一组物理线路在不同时间段传输不同类型的信息。 | 典型代表是**地址/数据线复用**，核心目的是**减少引脚数量，节省硬件成本**。    |
| **总线寻址能力** | 由地址线的位数决定。              |                                              |

**总线带宽：**

$$\text{总线带宽} = \text{总线宽度} \times \text{总线工作频率}$$

---
### 6.1.3 总线结构的演进

总线结构的发展主线是**提升带宽、降低延迟、打破通信瓶颈**，从共享式逐步演进为分层互连及点对点直连。

| 发展阶段        | 架构特征                                                                       | 性能表现与优缺点分析                                                                                                               |
| :---------- | :------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------- |
| **单总线结构**   | 处理器、主存及所有外设全挂在同一条系统总线上。                                                    | **优点**：结构简单，成本低廉。<br>**缺点**：所有设备分时竞争使用权，**极易产生传输冲突**，并发性差，成为严重瓶颈。                                                        |
| **双/三总线结构** | **双总线**：增设一条处理器与主存间的专用存储总线。<br>**三总线**：进一步增设**直接内存访问(DMA)** 总线，允许高速外设直连主存。 | **优点**：缓解了处理器与主存的通信压力，提升了高速外设的吞吐能力。<br>**缺点**：依然具有共享、广播特性，并发性和可扩展性受限。                                                    |
| **南北桥结构**   | **北桥**：高速枢纽，连接处理器、主存与显卡（前端总线连接处理器与北桥）。<br>**南桥**：低速枢纽，汇聚慢速外设再接入北桥。         | **优点**：实现了物理分层和一定程度的数据分离。<br>**缺点**：所有外设数据最终都要汇聚到前端总线进入处理器，**前端总线成为系统整体吞吐量的唯一性能瓶颈**。                                     |
| **现代集成架构**  | 传统北桥消失，内存控制器直接集成入处理器。处理器之间、处理器与高速外设间采用**点对点高速串行互连**。                       | **优点**：<br>1. **内存路径极短**：处理器直访主存，支持多通道。<br>2. **点对点互连**：取代前端总线，大幅提升互连效率和峰值带宽。<br>3. **外设直连**：高速外设直连处理器，低速外设由新一代控制中心统一管理。 |

---
## 6.2 总线事务与总线定时
### 6.2.1 总线事务

在总线上，主设备与从设备之间完成一次完整的信息交换过程称为**总线事务**。总线事务的类型由操作性质决定，典型的包括存储器读写、I/O读写、中断响应等。

通常，一个完整的总线事务包含以下三个基本阶段：
1. **地址传送阶段**：主设备将**目标地址**和**操作类型**通过总线传送给从设备。
2. **从设备响应阶段/数据准备阶段**：从设备根据地址准备数据。
3. **数据传送阶段**：完成实际数据在总线上的传输。

#### 6.2.1.1 数据传送方式

| 传输方式      | 工作原理                                                                | 优缺点                            |
| :-------- | :------------------------------------------------------------------ | :----------------------------- |
| **非突发传输** | 每次仅传输一个数据单元。每次传输都必须经历完整的“发地址 $\rightarrow$ 等待 $\rightarrow$ 传数据”流程。 | **缺点**：需重复发送地址，导致地址开销大，传输效率较低。 |
| **突发传输**  | 连续传输多个数据单元。主设备仅在事务开始时发送**首地址**，后续地址由硬件自动递增生成。                       | **优点**：省去多次地址传送开销，显著提升有效带宽。    |

#### 6.2.1.2 物理传输方式

| 通信方式     | 传输机制                           | 优缺点                                                           | 应用场景                              |
| :------- | :----------------------------- | :------------------------------------------------------------ | :-------------------------------- |
| **串行通信** | 数据按比特位依次顺序传输，通常仅使用一条双向或两条单向线路。 | **优点**：引脚少、布线简单、抗干扰能力强。<br>**缺点**：硬件实现较复杂。                    | 长距离通信及现代高速多采用此设计（如USB、PCIe、SATA）。 |
| **并行通信** | 利用多条数据线同时传输多个比特位（如32位、64位）。    | **优点**：短距离内延迟低、吞吐量高。<br>**缺点**：频率提高后信号串扰和时序偏移问题加剧，难以持续提高总线频率。 | 板级或芯片级的短距离通信（如早期PCI、内存总线）。        |

并行传输频率难以提升，故并行传输并不一定比串行传输快。

其中，串行通信又可分为：
- **同步串行通信**：由发送方时钟直接控制接收方时钟，双方的时钟严格一致。
- **异步串行通信**：收发双方时钟独立。每个数据帧至少包括1位起始位、1位终止位和数据部分。

---
### 6.2.2 总线定时
**总线定时**是指总线上主设备与从设备在交换数据时，用于协调双方操作时序的控制协议。其实质是一种时序规则，分为以下四种核心方式：

#### 6.2.2.1 四种定时方式综合对比
| 定时方式      | 控制机制与原理                                                                                     | 优点                                  | 缺点                             | 适用场景                      |
| :-------- | :------------------------------------------------------------------------------------------ | :---------------------------------- | :----------------------------- | :------------------------ |
| **同步定时**  | 采用统一的时钟信号，实现严格同步。所有操作严格受统一的时钟节拍约束。                                                          | 传送速度快；总线控制逻辑简单。                     | 缺乏应答机制，无法根据设备实际状态调整，**可靠性较差**。 | 总线长度较短，且连接各部件存取时间比较接近的系统。 |
| **异步定时**  | 无统一时钟，通过主从设备之间的**握手信号**（请求与回答）实现定时控制。                                                       | 总线周期长度可变，能可靠连接工作速度差异大的设备，**自适应性强**。 | 控制逻辑复杂，多次信号交互导致整体传输速率较低。       | 适用于总线较长，包含不同速度设备的系统。      |
| **半同步定时** | 结合同步与异步。增设一条 **Wait信号线**。主设备通过检测 Wait 信号插入等待周期，直到有效才进行数据读写。                                 | 在统一时钟下工作，控制比异步简单，可靠性较高。             | 系统时钟频率受限于最慢设备，整体速度不高。          | 包含多速度差异较大设备，但性能要求不高的简单系统。 |
| **分离式定时** | 采用**非独占事务模型**，将事务拆分为两个独立子阶段：<br>1. 主设备申请发地址/命令后即释放总线。<br>2. 从设备准备好数据后主动申请总线，**以主设备身份**发回数据。 | 显著减少总线空闲等待时间，极大**提高总线利用率**。         | 控制逻辑复杂，协议开销大，对总线仲裁要求高。         | 多主设备竞争激烈且从设备响应延迟较大的高性能系统。 |

#### 6.2.2.2 异步定时方式的握手协议

| 互锁方式    | 主设备发“请求”后的操作逻辑                 | 从设备发“回答”后的操作逻辑             | 可靠性             |
| :------ | :----------------------------- | :------------------------- | :-------------- |
| **不互锁** | 预设延时后自动撤销“请求”，**无需等待“回答”**。    | 预设延时后自动撤销“回答”，无需确认“请求”已撤销。 | 最低，容易丢包         |
| **半互锁** | **必须收到**“回答”信号后，才撤销“请求”。（存在互锁） | 预设延时后自动撤销“回答”。（无互锁）        | 中等              |
| **全互锁** | **必须收到**“回答”信号后，才撤销“请求”。       | **必须确认**“请求”已撤销后，才撤销“回答”。  | **最高**，确保数据绝对同步 |

# 7 I/O 系统
## 7.1 I/O 接口

* **定义**：主机与外部设备之间的交接界面，也称 **I/O 控制器**。
* **核心作用**：弥合主机与外设在工作方式、数据格式和工作速度等方面的显著差异，实现二者的信息交换。

### 7.1.1 I/O 接口的主要功能
1.  **地址译码与设备选择**：产生设备选择信号，确保主机仅与指定外设通信。
2.  **通信联络与时序协调**：通过握手信号或状态轮询，动态协调 CPU 与慢速外设之间的工作节奏。
3.  **数据缓冲**：接口内设有数据缓冲寄存器暂存数据，避免因速度不匹配导致数据丢失。
4.  **信号格式转换**：实现电平转换、并/串转换、模/数或数/模转换等，保证物理兼容。
5.  **控制命令与状态信息传递**：CPU 向接口写入命令字，接口向 CPU 反馈状态。

**I/O 接口与端口**
* **I/O 接口**：指完整的硬件电路及其内部的所有逻辑。
* **I/O 端口**：专指接口电路中**可被 CPU 直接访问的寄存器**。
    * **数据端口**：支持读/写操作。
    * **状态端口**：仅支持读操作。
    * **控制端口**：仅支持写操作。

---
### 7.1.2 I/O 接口的类型
* **按数据传送方式**：**并行接口**（多位同时传送）、**串行接口**（逐位顺序传送）。
* **按主机访问控制方式**：程序查询接口、中断接口、DMA 接口。
* **按功能灵活性**：可编程接口、不可编程接口。

### 7.1.3 I/O 端口的编址方式
为了让 CPU 能够访问各个 I/O 端口，必须对其进行编址。

| 编址方式     | 核心机制                                           | 优点                                                  | 缺点                                                                   |
| :------- | :--------------------------------------------- | :-------------------------------------------------- | :------------------------------------------------------------------- |
| **独立编址** | 端口拥有完全独立的地址空间，与内存地址空间分离。必须使用**专用指令**进行访问。      | 1. 专用指令使程序逻辑清晰，便于调试。<br>2. 译码电路简单，**寻址速度快**。        | 1. 专用指令功能有限，数据处理灵活性差。<br>2. CPU 需提供额外的读写控制信号，增加控制逻辑复杂性。              |
| **统一编址** | 将部分主存地址空间分配给端口，端口与内存共享同一空间。使用**普通访存指令**即可访问端口。 | 1. 无需专用指令，编程更灵活。<br>2. 保护机制可由虚拟存储管理系统统一实现，无需额外硬件支持。 | 1. 端口占用主存地址空间，**减少了可用内存容量**。<br>2. 寻址时需要进行完整的地址译码，电路复杂，可能**降低寻址速度**。 |

---
## 7.2 I/O 方式

### 7.2.1 程序查询方式
数据交换的控制完全由CPU执行程序来实现。接口电路中通常包含一个**数据缓冲寄存器**和一个**设备状态寄存器**。

工作流程主要分为以下几步：
1. **预置参数**：CPU初始化程序，设置主存起址、传送数量等。
2. **启动外设**：向I/O接口发送命令字。
3. **循环检查**：不断读取外设状态寄存器。
4. **数据传送**：若未就绪，继续死循环检查；若已就绪，传送一次数据。
5. **参数修改**：修改主存地址和计数器。
6. **判断结束**：判断是否传送完成，未完成则返回循环检查阶段。

| 方式分类 | 工作特点 |
| :--- | :--- |
| **独占查询** | 启动外设后，CPU不断死循环检查状态，不执行其他任务。**CPU与外设完全串行工作**，效率极低。 |
| **定时查询** | CPU以固定时间间隔周期性地检查状态。设备未就绪时CPU继续执行原程序，避免数据丢失，提高了CPU利用率。 |

**优点**：设计简单，硬件开销小。
**缺点**：CPU需要花费大量时间进行查询和等待，且同一时间只能与一台外设通信，效率很低。

### 7.2.2 程序中断方式
当出现外部事件或内部异常时，CPU暂停当前程序的执行，转去处理该事件，处理完毕后再返回断点处继续执行。其核心思想是实现**CPU与I/O设备的并行工作**。

#### 7.2.2.1 中断请求与判优
一台计算机允许多个中断源同时存在，CPU必须通过判优逻辑决定响应顺序。

| 维度         | 特征描述                                                                            |
| :--------- | :------------------------------------------------------------------------------ |
| **中断源**    | 向CPU发出中断请求的设备或事件，由**中断请求触发器**记录状态（状态为1表示有请求）。                                   |
| **可屏蔽中断**  | 优先级较低，在关中断状态下**不被响应**，主要处理一般外设请求。                                               |
| **不可屏蔽中断** | 优先级最高，**不受中断允许标志的影响**，主要用于处理紧急的致命硬件故障（如电源掉电、总线错误）。                              |
| **判优原则**   | **不可屏蔽中断 > 可屏蔽中断**；<br>**高速设备 > 低速设备**；<br>**输入设备 > 输出设备**；<br>**实时设备 > 普通设备**。 |

#### 7.2.2.2 CPU响应中断的条件
CPU仅在指令执行结束时统一采样中断请求，响应必须**同时满足**以下三个条件：
1. 存在有效的中断请求。
2. CPU处于**开中断状态**（中断允许标志为1，异常和不可屏蔽中断不受此限制）。
3. **当前指令已执行完毕**。

#### 7.2.2.3 中断处理完整流程
整个中断处理过程由硬件（**中断隐指令**）和软件（**中断服务程序**）共同完成。

1. **中断隐指令**（由**硬件**自动完成）：
   * **关中断**：将中断允许标志置0，防止在保存断点和现场时被新中断打断。
   * **保存断点**：将程序计数器和程序状态字压入堆栈保存，以便后续恢复。
   * **引出中断服务程序**：识别中断源，将服务程序的入口地址送入程序计数器。
2. **中断服务程序**（由**软件**执行完成）：
   * **保存现场和屏蔽字**：将通用寄存器中的重要数据压栈。
   * **开中断**（仅多重中断存在此步）：允许响应更高优先级的中断请求。
   * **执行真正的服务逻辑**：处理具体的中断事件。
   * **关中断**（仅多重中断存在此步）：防止恢复现场的过程中被再次打断。
   * **恢复现场和屏蔽字**：从栈中弹出原先保存的通用寄存器内容。
   * **开中断并返回**：执行中断返回指令，恢复断点，回到原程序继续执行。

#### 7.2.2.4 中断向量表与寻址
采用硬件向量法识别中断源时，存在以下寻址关系：
* **中断向量**：中断服务程序的**入口地址**。
* **中断向量地址**：存放“中断向量”的主存地址，也称为向量表指针。
* **数据流向**：硬件分配中断类型号 $\rightarrow$ 计算出中断向量地址 $\rightarrow$ 读取中断向量 $\rightarrow$ 送入程序计数器。

#### 7.2.2.5 单重中断与多重中断（中断嵌套）

| 机制类型 | 核心区别 | 处理流程差异 |
| :--- | :--- | :--- |
| **单重中断** | **不允许中断嵌套**。执行中断服务程序期间全程处于关中断状态。 | 服务程序中省略了“开中断”和“关中断”步骤。 |
| **多重中断** | **允许中断嵌套**。允许更高优先级的中断请求打断当前正在执行的中断服务程序。 | 在保存现场后必须**开中断**，在恢复现场前必须**关中断**。 |

**屏蔽字技术扩展**：
中断响应优先级由硬件线路决定，不可更改；但通过设置**中断屏蔽字**，可以动态调整**中断处理优先级**。屏蔽字中对应位设为1表示屏蔽该请求（不响应），设为0表示放行。

**优点**：程序中断方式克服了程序查询方式中CPU的忙等现象，显著提高了CPU的利用率。
**缺点**：但当高速设备频繁使用时，会不断打断CPU的现行程序以执行中断服务程序，造成较大的开销。

### 7.2.3 DMA方式

完全由**硬件**控制的数据传输方法。在**外设与主存**之间建立直接的数据通路，信息传送**无须经过CPU**，避免了保存与恢复CPU现场等复杂操作，显著降低CPU的负担。

**适用场景**：适用于磁盘、显卡、网卡等高速设备的大批量数据传输。

**主要特性**：
1. 打破主存与CPU的固定关联，主存既可被CPU访问，也可被外设直接访问。
2. 数据传输过程中，主存地址的生成与传送字数的计数均由**硬件电路自动完成**。
3. 主存中需设置专用缓冲区，以支持高效的数据交换。
4. 支持高速数据传输，且**CPU与外设可并行工作**，显著提升系统效率。
5. 传输开始前需由**软件进行预处理**，结束后通过**中断机制完成后处理**。

#### 7.2.3.1 DMA控制器的组成与功能

对数据传送过程进行控制的硬件称为**DMA控制器**。

**主要功能**：
1. 接收外设发出的DMA请求，并向CPU发出总线请求信号。
2. CPU响应后接管**总线控制权**，进入DMA操作周期。
3. 确定传送的主存起始地址及长度，并自动更新主存地址和传送长度计数器。
4. 指定传送方向，发出读/写等控制信号。
5. 传送结束后，向CPU报告传送完成（发送中断请求）。

**核心部件**：
* **主存地址计数器**：存放待传送数据的主存地址。传送前保存起始地址；传送中每传一个字，内容自动加1。
* **传送长度计数器**：记录待传送数据的总长度。传送前存入总字数；每传送一个字，内容减1，当计数器为0时，表示传送结束。
* **数据缓冲寄存器**：暂存每次传送的数据。
* **DMA请求触发器**：当I/O设备准备好数据时，发出DMA请求信号。
* **控制/状态逻辑**：用于设定传送方向、更新传送参数，并协调DMA请求与CPU响应信号。
* **中断机构**：当一批数据传送完毕后，触发中断并向CPU发出中断请求。

#### 7.2.3.2 DMA的传送方式

主存与I/O设备交换信息时不经过CPU，为高效利用主存并解决I/O设备与CPU同时访问主存的冲突，通常采用以下三种方式共享主存：

| 传送方式            | 工作原理                                             | 优点                             | 缺点                           | 适用场景                |
| :-------------- | :----------------------------------------------- | :----------------------------- | :--------------------------- | :------------------ |
| **停止CPU访存**     | I/O设备发出请求时，CPU放弃总线控制权，直到整块数据传送完成。                | 控制逻辑简单。                        | DMA访存期间，CPU基本处于空闲状态，资源利用率较低。 | 数据传输速率极高的大批量成组数据传送。 |
| **周期挪用**        | I/O设备挪用一个主存周期进行数据传送。当I/O与CPU同时请求访存，CPU暂时放弃总线控制权。 | 既满足I/O数据传送需求，又较好地发挥了CPU与主存的效率。 | 每次挪用均需申请并释放总线控制权，带来一定开销。     | 多数高速I/O设备（单字传送方式）。  |
| **DMA与CPU交替访存** | 将一个CPU工作周期划分为两个子周期，交替供CPU和DMA访存。                 | 无须动态申请或释放总线控制权，数据传送速率高。        | 硬件控制逻辑较为复杂。                  | CPU工作周期大于主存存储周期的场景。 |

#### 7.2.3.3 DMA的传送过程

1. **预处理（CPU执行）**：
   由**CPU**完成必要的初始化工作，包括设置DMA控制器中的主存起始地址、传送方向、传送数据个数，并启动I/O设备。随后CPU继续执行原程序。
2. **数据传送（硬件控制）**：
   以数据块为单位进行。DMA控制器一旦获得总线控制权，便通过**硬件循环自动完成**数据的输入或输出操作，**整个过程无须CPU干预**。
3. **后处理（中断服务）**：
   数据块传送完成后，DMA控制器向CPU发出**中断请求**。CPU响应后执行中断服务程序，进行数据校验等后处理工作。

#### 7.2.3.4 DMA方式与中断方式对比

| 区别维度 | 中断方式 | DMA方式 |
| :--- | :--- | :--- |
| **程序切换与现场保护** | 需要保存和恢复CPU现场，完全占用CPU资源。 | 不需要保存和恢复CPU现场，**不占用CPU资源**。 |
| **响应时机** | 只能在**每条指令执行结束**后被响应。 | 可在**当前总线周期结束**后立即获得响应，无须等待指令完成。 |
| **实现机制** | 依赖CPU执行中断服务程序（**软件控制**）。 | 由专用硬件直接在主存与外设间传送数据（**硬件控制**）。 |
| **请求优先级** | 优先级较低。 | 优先级**高于**中断请求。 |
| **功能定位** | 具备处理异常事件的能力。 | 仅用于大批量数据的高效传送，不处理异常事件。 |
