# 1 进程
## 1.1 七状态模型
**流转**：
* **就绪态 $\leftrightarrow$ 就绪挂起**：内存不足调出，内存空闲或需要执行时激活调入。
* **阻塞态 $\leftrightarrow$ 阻塞挂起**：内存不足调出，激活时调入。
* **阻塞挂起 $\to$ 就绪挂起**：当阻塞挂起的进程等待的事件发生时，直接转换为就绪挂起。
* **运行态 $\to$ 就绪挂起**：进程下处理机时可能直接被放到外存。
* **创建态 $\to$ 就绪挂起**：创建完毕后若内存不足，可能先进入就绪挂起。

## 1.2 PCB 管理
为了高效管理并发进程，必须将系统中所有PCB进行组织管理：
1. **线性表方式**：将系统中所有PCB集中存放在一个连续的内存数组中。
2. **链接表方式**：将同一状态的PCB通过指针链接成一个队列。如活动就绪队列、静止就绪队列。
3. **索引表方式**：根据进程状态建立多张索引表。如就绪索引表、阻塞索引表。

## 1.3 原子性
- **单核系统**：仅通过关中断指令，即可原语的原子性。
- **多核系统**：必须采用关本地中断 + 多核自旋锁。

## 1.4 线程
### 1.4.1 用户级线程调度器
用户级线程切换开销小，一旦发生缺页或 I/O 调用将导致整个进程被阻塞。
- 在用户态运行一个用户级线程调度器。当进程中某个线程遭到阻塞时，内核捕获该事件，将不再挂起整个进程，而是通过**向上调用**通知用户级线程调度器。用户级线程调度器可保存该线程上下文，并调度另一个线程继续执行。

## 1.5 处理器亲和
1. **软亲和性**：操作系统调度器在策略上**尽量优先安排进程在上次运行的CPU上执行**，但不做强制保证。当该CPU负载过重而其他CPU空闲时，调度器依然会为了负载均衡将进程迁移走。
2. **硬亲和性**：用户进程通过显式系统调用，传递一个**CPU亲和性掩码**，强制绑定系统**只能在指定的特定物理核心集合上调度该进程**。

## 1.6 其他
  - **孤儿进程**：父进程在子进程退出之前就已经先终止退出。孤儿进程不会被系统杀死，而是会立即被系统的祖先进程收养。当孤儿进程最终运行结束退出时，其收养者 `init` 进程会负责调用 `wait()` 为其收尸，因此孤儿进程没有任何危害。
  - **僵尸进程**：子进程已经执行完毕终止，但其**父进程尚未调用 `wait()` 或 `waitpid()` 读取其退出状态信息**。
	- 僵尸进程会一直霸占内核 PCB 表槽位和 PID。由于系统可用 PID总数是有限的，最终将导致系统无法创建任何新进程。
	- 通过杀死产生僵尸的父进程，使僵尸进程变成孤儿进程，由 `init` 接管并自动调用 `wait()` 清除其残留 PCB。
- **最早截止时间优先 / EDF**：任务的截止时间越早，其优先级越高。
- **最低松弛度优先 / LLF**：定义松弛度为任务距离非执行不可的死线还有多少闲暇时间。松弛度越小的任务，优先级越高。
- **AND 型信号量**：传统记录型信号量极易由于推进顺序不当导致死锁。AND 型信号量，只有当所有共享资源都满足时才分配。

### 1.6.1 优先级倒置
- **优先级倒置**：高优先级任务 $P_H$ 等待低优先级任务 $P_L$ 占有的共享互斥资源，而中优先级任务 $P_M$ 无需该资源却抢占了 $P_L$ 的 CPU，导致 $P_L$ 无法推进释放资源，最终导致高优先级任务 $P_H$ 被低级别的 $P_M$ 长时间阻塞。
1. **优先级继承协议**：当 $P_H$ 被 $P_L$ 阻塞时，$P_L$ 临时继承 $P_H$ 的优先级，防止被 $P_M$ 抢占。缺陷：可能引起死锁和链式阻塞。
2. **优先级天花板协议**：
	- **天花板**：为每个共享互斥信号量赋予一个固定的“天花板优先级”，其值等于**所有可能访问该信号量的任务中的最高优先级**。
	- 当任务 $P$ 试图对某一互斥资源加锁时，系统检查当前被其他任务加锁的所有资源的天花板。**仅当任务 $P$ 的动态优先级严格大于当前所有已被占用的资源的天花板优先级时**，才准予加锁，否则挂起 $P$。
	- 保证**彻底预防死锁**，且高优先级任务最多只会被阻塞一个临界区的时间。

# 2 内存
## 2.1 反置页表
每个进程都拥有极大的虚拟地址范围，然而实际使用的内存空间可能很少。即使采用4级甚至5级页表，各进程自身的页表在内存中累积占用的物理页框数量仍极其巨大。
- 操作系统中全局一张反置页表，以物理页框号为索引。
- 以 $[进程标识符 PID,逻辑页号]$ 作为关键字进行哈希散列计算，得到索引。
- 若发生哈希冲突，则比较 $[进程标识符 PID,逻辑页号]$。
- 难实现多进程内存页面共享。

## 2.2 页面缓冲
1. **空闲页面链表**：若淘汰的页面未被修改过，挂入此链表尾部。
2. **修改页面链表**：若淘汰的页面已被修改，挂入此链表尾部。
3. 若进程随后再次访问已被淘汰的页面，系统在分配新页框前先检查这两个链表。若页面仍在链表中，只需将其从链表摘除并恢复页表映射。
4. 当修改页面链表中的页面累积达到阈值时，系统一次性启动集中连续批量写回磁盘，写回后页面移入空闲链表。

## 2.3 其他
- **顶级页表 / 页目录表**：必须恰好占用一个物理页框。

# 4 I / O
## 4.1 LUT
- 应用程序编写时只需使用抽象的逻辑设备名，实际运行时由操作系统将其映射为具体的物理设备名。
- 表项包含：`逻辑设备名 | 物理设备名 | 设备驱动程序入口地址`

## 4.2 磨损均衡
| 名称         | 实现方式                                                      |
| :--------- | :-------------------------------------------------------- |
| **动态磨损均衡** | 写入数据时，优先选择累计擦除次数较少的**新闪存块**。                              |
| **静态磨损均衡** | SSD监测并自动进行数据分配与迁移。将**读多写少**的数据迁移到**老旧块**，让**新块**承担更多的写任务。 |

## 4.3 其他
  - **脱机输入/输出（Off-line I/O）技术**：在主计算机系统之外增设一台结构相对简单、成本低廉的专用辅助计算机（称为**外围机**或卫星机）。
  - **写惩罚**：以RAID 5为例，修改一个块，需要读旧数据块，旧校验块，写入新数据块，写入新校验块。写惩罚系数为 4。

# 5 其他
## 5.1 系统调用参数传递
1. **通用寄存器传递**：将参数直接写入CPU的通用寄存器。
2. **内存参数块/表传递**：操作系统在用户空间连续内存中开辟一个“参数块/表”，将参数填入该块，然后将该参数块的**首地址**放入一个通用寄存器中传递给内核。
3. **用户栈入栈传递**：在执行陷入指令之前，由编译器或库函数将所有参数自右向左依次压入当前进程的用户栈中。陷入内核后，内核通过读取用户栈指针定位并拷贝出所需参数。

## 5.2 其他
- **网络操作系统（NOS）**：基于计算机网络各自主节点的本地操作系统之上，配置网络通信和资源共享软件。各节点拥有**独立的自治操作系统**，用户必须显式知道资源所在的具体物理机器名或IP地址。
  - **分布式操作系统（DOS）**：构建在若干物理分散的独立计算机集群之上，**由统一的分布式内核进行协同管理**。核心特征是**单一系统映像**与**高度透明性**。用户在提交计算任务或访问文件时，感觉整个网络就是一台统一的超级虚拟单机，无需知晓也无法感知具体是在哪一台物理机上调度执行。

| 体系结构    | 描述                                                      | 优点                     | 缺点                        |
| :------ | :------------------------------------------------------ | :--------------------- | :------------------------ |
| **大内核** | 将操作系统的主要功能模块都作为系统内核，运行在核心态。                             | **高性能**（各模块间交互无需切换状态）。 | 代码庞大，结构混乱，**难以维护**。       |
| **微内核** | 只把最基本的功能（时钟、中断、原语）保留在内核。                                | 功能少，结构清晰，**方便维护**。     | **性能低**，需要频繁在核心态和用户态之间切换。 |
| **外核**  | 内核负责保护资源，**外核负责分配“未经抽象”的硬件资源**。把资源的具体管理交给用户态的**库操作系统**。 | 绝大部分逻辑在用户态执行，极大减少了切换开销 | 管理复杂。                     |
