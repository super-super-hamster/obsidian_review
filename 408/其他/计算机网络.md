# 1 物理层
* **双绞线**：通过将两根绝缘铜线**相互绞合**来抵御电磁干扰，是**成本最低**、布线方便，但传输距离较短。
* **同轴电缆**：拥有良好的**屏蔽层**使其抗干扰能力较强，笨重且成本较高。
* **光纤**：具有**极高带宽**、超远传输距离和**完全抗电磁干扰**的特性。
* **微波通信**：无需铺设物理线缆，利用**直线传播**的高频电磁波在空气中传输，实现了**移动通信**的便利性，但信号易受建筑物阻挡、衰减大且易受干扰。

# 2 数据链路层
## 2.1 静态划分信道

### 2.1.1 频分复用(FDM)
* **基本原理**：将整个传输频带划分为若干个频率范围不同的子信道，每个子信道分配给一对用户专用。为了防止子信道之间的干扰，相邻子信道之间需要设置**保护频带**。
* **特点**：所有用户在**同样的时间**占用**不同的带宽**资源。

### 2.1.2 时分复用(TDM)
* **基本原理**：将时间划分为一个个等长的时分复用帧，每个用户在每个TDM帧中占用固定序号的时隙。当用户无数据发送时，分配给他的时隙只能空闲，其他用户无法使用，导致信道资源浪费。
* **特点**：所有用户在**不同的时间**占用**同样的频带宽度**。
* **统计时分复用/异步时分复用(STDM)**：仅当用户有数据要发送时，才为其分配STDM帧的时隙。

### 2.1.3 波分复用(WDM)
* **定义**：即**光的频分复用**。
* **原理**：在光纤通信中，利用棱镜或光栅将不同频率（波长）的光信号合并在一根光纤上传输。
* **特点**：光信号在光纤中传输时损耗极小，适合长距离、大容量传输。

## 2.2 PPP
- **标志**：用作帧标识帧的开始与结束。
	- **长度**：8 位，首位各一个。
- **数据**：
	- **长度**：0 到 1500B。
- **帧检验序列**：CRC 校验生成的冗余码。
- 仅支持全双工的点对点链路，不支持多点线路。

## 2.3 MAC
- 地址第一个字节最低位为奇数时为广播/组播地址，为偶数时则为单播地址。

# 3 网络层
## 3.1 软件定义网络 SDN
网络层的核心任务是分组转发与路由选择。从功能架构上，网络层可逻辑划分为**数据平面**（负责执行分组转发）与**控制平面**（负责实现路由选择、生成并维护路由信息）。

| 维度         | 软件定义网络                                                      |
| :--------- | :---------------------------------------------------------- |
| **控制平面部署** | **集中式**部署，由逻辑集中的远程**控制器**掌握全局视图                             |
| **路由器功能**  | 仅保留**数据平面**功能，不运行路由选择软件                                     |
| **节点间交互**  | 路由器之间无须交互路由信息，由控制器统一下发**流表**                                |

| 维度     | 具体表现                                                                                                                                                |
| :----- | :-------------------------------------------------------------------------------------------------------------------------------------------------- |
| **优点** | 1. **集中控制与分布转发**：控制平面具备全局视图便于统一优化，数据平面分布执行保障高速转发性能。<br>2. **灵活可编程性**：通过标准化接口，开发者能以软件方式动态定义网络行为。<br>3. **降低成本**：控制与转发分离使硬件设备极度简化（仅需基础转发能力），有效降低组网成本。 |
| **缺点** | 1. **安全风险**：集中化的控制器易成为攻击靶点，存在**单点故障**风险，一旦崩溃将影响整个网络。<br>2. **性能瓶颈**：随着网络规模急剧扩大，控制器的处理能力可能成为整个网络性能的瓶颈。                                               |

## 3.2 多播地址冲突
- **原因**：IPv4 多播地址中，有 28 位为多播组标识，而 MAC 帧中仅 23 位有效多播地址。将 IPv4 多播地址的低 23 位填入以太网 MAC 地址的低 23 位中，因此将有 32 个不同的 IP 多播地址映射到同一个 MAC 多播地址上。
- **解决方式**：在网络层读取 IP 多播地址，非本组数据包丢弃。

# 4 运输层
## 4.1 TCP
### 4.1.1 零窗口死锁
* **产生原因**：接收方向发送方发送了“零窗口”通知（`rwnd=0`）。发送方收到后暂停发送，等待新的窗口通知。接收方之后有了缓存空间，发送了一个“非零窗口”通知 ，但这个报文在传输中**丢失**了。
- **解决方法**：收到对方的“零窗口”通知，就启动计时器。若计时器到期仍未收到非零窗口通知，发送方会发送一个**零窗口探测报文**（消耗一个序号）。接收方收到探测报文后，必须确认 ACK，并在确认报文中给出当前的窗口值。
* **特别规定**：TCP 规定，即使接收窗口为0，接收方也必须接收以下三种报文：
    * 零窗口探测报文
    * 确认报文
    * 携带紧急数据的报文

### 4.1.2 糊涂窗口综合征
- **现象**：数据部分过短，而首部开销固定，导致利用率极低。
- **解决方法**：
	1. **接收方**：只要空闲空间未达到整个接收缓存空间的一半，或者不足以容纳一个 MSS，接收方就通告 `rwnd = 0`
	2. **发送方**：若发送方应用进程若逐字节写入数据，发送方先将第一个字节组成报文段立即发送出去。在等待该字节的确认 ACK 到达之前，发送端协议栈将后续到达的零散字节全部在本地缓存积攒起来。只有当收到了前一个报文段的确认 ACK 或本地缓存中积攒的数据量已经达到了一个 MSS时才允许发送下一个报文段。

# 5 应用层
## 5.1 HTTP/2
- **HTTP/1.1 的缺陷**：由于 TCP 严格遵循 FIFO，导致后续请求可能被前一个请求阻塞，服务器不得不开 6 个 TCP 连接保证性能，浪费大量套接字。
- **HTTP/2 的改进**：
	1. 将数据切分为更小的帧，并附带序号。
	2. 仅建立一个 TCP 连接，将多个请求的帧在同一个 TCP 连接上传输，避免阻塞。
	3. 使用静态字典( 固定内容 )和动态字典(cookie 等)，减少首部内容。

## HTTP/3
- **HTTP/2 的缺陷**：若丢失一个 TCP 报文段，整个 TCP 连接的滑动窗口就会停滞并等待重传，在高丢包率下性能甚至弱于 HTTP/1.1。
- **HTTP/3 的改进**：使用 UDP + QUIC 协议。
- **QUIC**：
	1. QUIC 的每一个流都有独立的序号空间。当某个流的一个数据包丢失时，只有该流被阻塞等待重传，其他所有的流并行推进，不受任何干扰。
	2. 首次连接仅需 1 个 RTT，再次连接仅需 0 RTT
	3. TCP 连接由四元组(源 IP, 源端口, 目的 IP, 目的端口)确定，当网络切换时，将导致 TCP 断开连接，重新握手。QUIC 采用一个全局唯一的 64 位连接 ID 标识会话。
