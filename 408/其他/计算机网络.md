# 1 物理层
## 1.1 传输介质
* **双绞线**：通过将两根绝缘铜线**相互绞合**来抵御电磁干扰，是**成本最低**、布线方便，但传输距离较短。
	* 10Base-T
* **同轴电缆**：拥有良好的**屏蔽层**使其抗干扰能力较强，笨重且成本较高。
	* 10Base-5
	* 10Base-2
* **光纤**：具有**极高带宽**、超远传输距离和**完全抗电磁干扰**的特性。
	* 10Base-F
* **微波通信**：无需铺设物理线缆，利用**直线传播**的高频电磁波在空气中传输，实现了**移动通信**的便利性，但信号易受建筑物阻挡、衰减大且易受干扰。

## 1.2 暴露站
- 如 $A \leftarrow B \to C \to D$，C 无法覆盖到 A。
- 当 C 准备向 D 发送数据时，若 B 正在向 A 发送数据，C 误认为此时信道繁忙。

## 1.3 其他
- **信源**：产生和发送数据的源头
- **信宿**：接收数据的终点
- **信道**：信号的传输介质
- **信号**：数据的电气表现

# 2 数据链路层
## 2.1 静态划分信道

### 2.1.1 频分复用(FDM)
* **基本原理**：将整个传输频带划分为若干个频率范围不同的子信道，每个子信道分配给一对用户专用。为了防止子信道之间的干扰，相邻子信道之间需要设置**保护频带**。
* **特点**：所有用户在**同样的时间**占用**不同的带宽**资源。

### 2.1.2 时分复用(TDM)
* **基本原理**：将时间划分为一个个等长的时分复用帧，每个用户在每个TDM帧中占用固定序号的时隙。当用户无数据发送时，分配给他的时隙只能空闲，其他用户无法使用，导致信道资源浪费。
* **特点**：所有用户在**不同的时间**占用**同样的频带宽度**。
* **统计时分复用/异步时分复用(STDM)**：仅当用户有数据要发送时，才为其分配STDM帧的时隙。

### 2.1.3 波分复用(WDM)
* **定义**：即**光的频分复用**。
* **原理**：在光纤通信中，利用棱镜或光栅将不同频率（波长）的光信号合并在一根光纤上传输。
* **特点**：光信号在光纤中传输时损耗极小，适合长距离、大容量传输。

## 2.2 PPP
1. 封装
	- **标志**：用作帧标识帧的开始与结束。
		- **长度**：8 位，首位各一个。
	- **数据**：
		- **长度**：0 到 1500B。
	- **帧检验序列**：CRC 校验生成的冗余码。
2. 链路控制协议 / LCP：负责建立、配置、测试和关闭数据链路连接。
3. 网络控制协议 / NCP：负责配置不同的网络层协议。
- 仅支持全双工的点对点链路，不支持多点线路。
- PPPoE：将 PPP 帧封装在以太网帧中。
- 用于点对点链路，不需要知道对方的 MAC 地址。

## 2.3 MAC
- 地址第一个字节最低位为奇数时为广播/组播地址，为偶数时则为单播地址。

# 3 网络层
## 3.1 IPv6
与 IPv4 的主要不同点：
1. 移除首部校验和
2. 首部长度固定 40B
3. 移除分片
4. 移除选项

## 3.2 软件定义网络 SDN
网络层的核心任务是分组转发与路由选择。从功能架构上，网络层可逻辑划分为**数据平面**（负责执行分组转发）与**控制平面**（负责实现路由选择、生成并维护路由信息）。

| 维度         | 软件定义网络                                                      |
| :--------- | :---------------------------------------------------------- |
| **控制平面部署** | **集中式**部署，由逻辑集中的远程**控制器**掌握全局视图                             |
| **路由器功能**  | 仅保留**数据平面**功能，不运行路由选择软件                                     |
| **节点间交互**  | 路由器之间无须交互路由信息，由控制器统一下发**流表**                                |

| 维度     | 具体表现                                                                                                                                                |
| :----- | :-------------------------------------------------------------------------------------------------------------------------------------------------- |
| **优点** | 1. **集中控制与分布转发**：控制平面具备全局视图便于统一优化，数据平面分布执行保障高速转发性能。<br>2. **灵活可编程性**：通过标准化接口，开发者能以软件方式动态定义网络行为。<br>3. **降低成本**：控制与转发分离使硬件设备极度简化（仅需基础转发能力），有效降低组网成本。 |
| **缺点** | 1. **安全风险**：集中化的控制器易成为攻击靶点，存在**单点故障**风险，一旦崩溃将影响整个网络。<br>2. **性能瓶颈**：随着网络规模急剧扩大，控制器的处理能力可能成为整个网络性能的瓶颈。                                               |

## 3.3 组播地址冲突
- **原因**：IPv4 组播地址中，有 28 位为组播组标识，而 MAC 帧中仅 23 位有效组播地址。将 IPv4 组播地址的低 23 位填入以太网 MAC 地址的低 23 位中，因此将有 32 个不同的 IP 组播地址映射到同一个 MAC 组播地址上。
- **解决方式**：在网络层读取 IP 组播地址，非本组数据包丢弃。

## OSPF
1. 问候：用于发现邻居并维持邻接关系。
2. 数据库描述：向邻居发送自己的链路状态数据库(LSDB)。
3. 链路状态请求：向邻居请求某些链路状态的信息。
4. 链路状态更新：洪泛向全网发送链路状态通告(LSA)。
5. 链路状态确认：对链路更新的确认。

# 4 运输层
## 4.1 TCP
### 4.1.1 零窗口死锁
* **产生原因**：接收方向发送方发送了“零窗口”通知（`rwnd=0`）。发送方收到后暂停发送，等待新的窗口通知。接收方之后有了缓存空间，发送了一个“非零窗口”通知 ，但这个报文在传输中**丢失**了。
- **解决方法**：收到对方的“零窗口”通知，就启动计时器。若计时器到期仍未收到非零窗口通知，发送方会发送一个**零窗口探测报文**（消耗一个序号）。接收方收到探测报文后，必须确认 ACK，并在确认报文中给出当前的窗口值。
* **特别规定**：TCP 规定，即使接收窗口为0，接收方也必须接收以下三种报文：
    * 零窗口探测报文
    * 确认报文
    * 携带紧急数据的报文

### 4.1.2 糊涂窗口综合征
- **现象**：数据部分过短，而首部开销固定，导致利用率极低。
- **解决方法**：
	1. **接收方**：只要空闲空间未达到 MSS 的一半，或者不足以容纳一个 MSS，接收方就通告 `rwnd = 0`
	2. **发送方**：若发送方应用进程若逐字节写入数据，发送方先将第一个字节组成报文段立即发送出去。在等待该字节的确认 ACK 到达之前，发送端协议栈将后续到达的零散字节全部在本地缓存积攒起来。只有当收到了前一个报文段的确认 ACK 或本地缓存中积攒的数据量已经达到了一个 MSS时才允许发送下一个报文段。

### 4.1.3 选择确认
- SACK 用左边界和右边界指明已正确接收的帧。避免因中间部分帧缺失导致后续所有的帧需要重传。

# 5 应用层
## 5.1 HTTP
### 5.1.1 HTTP/2
- **HTTP/1.1 的缺陷**：由于 TCP 严格遵循 FIFO，导致后续请求可能被前一个请求阻塞，服务器不得不开 6 个 TCP 连接保证性能，浪费大量套接字。
- **HTTP/2 的改进**：
	1. 将数据切分为更小的帧，并附带序号。
	2. 仅建立一个 TCP 连接，将多个请求的帧在同一个 TCP 连接上传输，避免阻塞。
	3. 使用静态字典( 固定内容 )和动态字典(cookie 等)，减少首部内容。

### 5.1.2 HTTP/3
- **HTTP/2 的缺陷**：若丢失一个 TCP 报文段，整个 TCP 连接的滑动窗口就会停滞并等待重传，在高丢包率下性能甚至弱于 HTTP/1.1。
- **HTTP/3 的改进**：使用 UDP + QUIC 协议。
- **QUIC**：
	1. QUIC 的每一个流都有独立的序号空间。当某个流的一个数据包丢失时，只有该流被阻塞等待重传，其他所有的流并行推进，不受任何干扰。
	2. 首次连接仅需 1 个 RTT，再次连接仅需 0 RTT
	3. TCP 连接由四元组(源 IP, 源端口, 目的 IP, 目的端口)确定，当网络切换时，将导致 TCP 断开连接，需要重新握手。QUIC 采用一个全局唯一的 64 位连接 ID 标识会话。

## 5.2 FTP
1. **主动模式 (PORT 模式)**：
     - 客户端从随机非特权端口 $N$ 建立到服务器 21 端口的控制连接；
     - 客户端打开端口 $N+1$，并通过控制连接向服务器发送 `PORT N+1` 命令；
     - 服务器从其熟知数据端口 **20** 主动向客户端端口 $N+1$ 发起建立数据连接；
2. **被动模式 (PASV 模式)**：
     - 客户端通过控制连接向服务器发送 `PASV` 命令；
     - 服务器在本地开启随机非特权端口 $P$，并在响应中通告客户端；
     - 客户端主动从端口 $N+1$ 向服务器的端口 $P$ 发起建立数据连接；

## 5.3 电子邮件
### 5.3.1 格式
1. **首部**：
	1. **From**：发件人邮箱地址
	2. **To**：收件人邮箱地址
	3. **Subject**：主题
	4. **Date**：发送时间
	5. **Cc**：抄送人邮箱地址
	6. **Bcc**：密送人邮箱地址
	7. **Message-ID**：邮件的全局标识
2. **空行**：回车(CRLF)，用于分隔正文和首部
3. **正文**：
	1. 正文类型：如纯文本，网页，图片。
	2. 编码方式
	3. 附件

### 5.3.2 MIME
1. 将原数据的每 3B 均分为 4 组，每组 6bit，映射为一个 ASCII 字符。
2. 若原数据长度不足，用 `=`补齐。
3. 最终发送 4B 数据。

### 5.3.3 其他
- **基于 Web 的电子邮件服务**：
	- 用户与邮件服务器之间均通过 HTTP 完成。
	- 仅在不同邮件服务器之间传递邮件时才使用 SMTP。
- **IMAP**：比 POP3 的功能更强大，支持用户在服务器端创建文件夹，搜索，选择性获取邮件部分内容。

## 5.5 其他
- **URL**：<协议>://<主机>:<端口>/<路径>
- **代理服务器**：
	- 缓存近期请求与响应。
	- 可部署在客户端，服务端或网络中间节点。
	- 降低内网通往互联网的链路负载。
### 5.5.1 P2P
1. 将文件切分为固定大小的数据块
2. 优先请求全网中副本最少的数据块
3. 只向为自己提供上传速度前 4 的节点和 1 个随机其他节点提供上传带宽服务

# 6 其他
- **IXP**：允许两个不同 ISP 在本地通过高速交换机直接对等互联，就地交换本地分组，而无需将流量向上传送到主干 ISP。大幅降低端到端网络时延，减轻主干网带宽传输压力。
- 协议数据单元 PDU：对等实体间传输的数据单元。$PDU = PCI + SDU$。
- 服务数据单元 SDU：层与层之间传递的有效数据。
- 协议控制信息 PCI：本层添加的首部和尾部控制开销。
