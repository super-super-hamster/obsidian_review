# 1 物理层
## 1.1 编码
| 编码方式              | 数据表示方式                                                                                         | 优缺点                                                |
| :---------------- | :--------------------------------------------------------------------------------------------- | :------------------------------------------------- |
| **不归零(NRZ)编码**    | 正电平代表1，负电平代表0（或相反）。                                                                            | **优点**：编码效率最高。<br>**缺点**: 存在**同步问题**。需要额外时钟线。      |
| **归零(RZ)编码**      | 每个码元传输结束后信号都**归零**。                                                                            | **优点**: 自同步。<br>**缺点**: 编码效率低，大部分带宽浪费在归零上。         |
| **反向非归零(NRZI)编码** | 以码元起始处是否有跳变来表示数据。                                                                              | **优点**：兼具高效率和一定的辅助同步能力。                            |
| **曼彻斯特编码**        | 每个码元**中间时刻**发生跳变。<br>例如：负跳变表示<br>1，正跳变表示0。<br>中间的跳变既是**时钟**也是**数据**。                           | **优点**: 中间跳变既作为时钟信号（自同步），又表示数据。<br>**缺点**: 占用频带较宽。 |
| **差分曼彻斯特编码**      | 码元**中间时刻**仅表示时钟。<br>码元**开始处**电平是否跳变表示数据。<br>例如：开始处跳变表示0，不跳变表示1。<br>中间跳变是**时钟**，位开始处的跳变是**数据**。 | **优点**: 抗干扰能力强于曼彻斯特编码，自同步。                         |

# 2 网络层
## 2.1 移动 IP 通信过程
1. **本地通信**：当 A 位于其归属网络时，按传统的 TCP/IP 方式直接与外界通信。
2. **漫游与注册**：
   * 当 A 漫游到被访网络时，先向该网络中的**外地代理**登记，并获得一个临时的**转交地址**。
   * 外地代理将该转交地址注册至 A 的**归属代理**，完成位置更新。
3. **接收数据 ($B \rightarrow A$)**：
   * B 发给 A 的数据包（目的地址为 A 的永久地址）被 A 的**归属代理**截获。
   * 归属代理将原始 IP 分组封装在新的 IP 包中（构建**IP 隧道**），发往外地代理的转交地址。
   * **外地代理**收到后，解除隧道封装，还原出原始 IP 分组，并直接交付给 A。
4. **发送数据 ($A \rightarrow B$)**：
   * A 在被访网络向 B 发送数据时，依然使用其**永久地址**作为源地址。
   * 数据包直接通过被访网络的外地代理按常规路由转发给 B，**无须**绕行归属代理。

## 2.2 多播
- 多播地址范围为 `224.0.0.0 ~ 239.255.255.255`。
- 发送多播时，目的地址为多播地址。
- 主机通过 IGMP 协议加入/退出多播组，由路由器负责管理。

## 2.3 任播
- IPv6 新增类型，数据报交付给其中距离最近的一个接口（即**一址多用，就近交付**）。

# 3 运输层
## 3.1 UDP
### 3.1.1 检验和
**发送方**：
1. 添加 12B 的伪首部。
2. 若长度为奇数字节，尾部添加一个全零字节，用于计算。
3. 检验和字段置 0。
4. 每 16 位进行反码运算规则( 最高位进位加到最低位 )求和，将求和结果的反码填入检验和。

**接收方**：
1. 同发送方前 3 步。
2. 若最终结果为全 1，则说明无差错；否则，丢弃该数据报。

# 4 应用层
## 4.1 DHCP

| 步骤    | 报文名称                            | 发送方 | 接收方 | 源 IP 地址   | 目的 IP 地址          | 传输方式   | 关键动作与说明                                                                    |
| :---- | :------------------------------ | :-- | :-- | :-------- | :---------------- | :----- | :------------------------------------------------------------------------- |
| **1** | **DHCP发现报文**<br>(DHCP DISCOVER) | 客户  | 服务器 | `0.0.0.0` | `255.255.255.255` | **广播** | 主机没有 IP，故源 IP 为全0；不知道服务器在哪，故广播寻找。包含事务ID和客户MAC地址。                           |
| **2** | **DHCP提供报文**<br>(DHCP OFFER)    | 服务器 | 客户  | 服务器IP     | `255.255.255.255` | **广播** | 服务器收到发现报文后，查找数据库。如有配置信息，则发送提供报文。包含IP、掩码、租期等。**服务器发送前会用 ARP 检测该 IP 是否被占用。** |
| **3** | **DHCP请求报文**<br>(DHCP REQUEST)  | 客户  | 服务器 | `0.0.0.0` | `255.255.255.255` | **广播** | 客户从多个 Offer 中选择一个（通常是第一个），发送请求。**广播的目的是告知所有服务器它选择了哪一个，未被选中的服务器可收回 IP。**    |
| **4** | **DHCP确认报文**<br>(DHCP ACK)      | 服务器 | 客户  | 服务器IP     | `255.255.255.255` | **广播** | 服务器确认租约生效。**客户收到后，会使用 ARP 检测分配的 IP 是否已被网络中其他主机占用。**                        |

# 5 其他
## 5.1 地址变化
* **IP 地址**：在传输过程中**始终保持不变**，源IP是最初发送者，目的IP是最终接收者。
* **MAC 地址**：在传输过程中**逐跳（逐链路）改变**，源MAC是当前链路发送端，目的MAC是当前链路接收端。
