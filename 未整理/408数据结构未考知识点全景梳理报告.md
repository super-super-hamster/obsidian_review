## 第二部分 第1章 绪论：未考知识点全景精析

### 考点 1.1：数据结构四类基本逻辑结构形式化二元组 $(D, R)$ 定义
- **【考点定位】** 李冬梅《数据结构（第3版）》§1.2.2 数据结构（P4-P6）。
- **【核心数据结构与机制原理】**
  1. **数据结构的形式化严格定义**：
     - 数据结构（Data Structure）是一个二元组：
       $$B = (D, R)$$
       其中：
       - $D$ 是数据元素的有限集合；
       - $R$ 是定义在集合 $D$ 上的关系的有限集合。
     - 关系 $r \in R$ 是定义在 $D$ 上的序偶集合，若 $\langle x, y \rangle \in r$，则称 $x$ 是 $y$ 的直接前驱（Predecessor），$y$ 是 $x$ 的直接后继（Successor）。
  2. **四类基本逻辑结构的二元组拓扑约束**：
     - **集合结构（Set）**：
       - 关系 $R = \emptyset$（空集）。
       - 数据元素之间除“属于同一个集合”的外在归属外，**不存在任何前驱后继前置关联**。
     - **线性结构（Linear Structure）**：
       - 关系 $R = \{r\}$，若集合 $D$ 非空，则满足：
         ① 存在唯一的“第一个”元素，它无直接前驱；
         ② 存在唯一的“最后一个”元素，它无直接后继；
         ③ 除第一个和最后一个元素外，集合中的每个元素**有且仅有一个直接前驱，有且仅有一个直接后继**（严格的 $1:1$ 线性映射）。
     - **树形结构（Tree Structure）**：
       - 满足层次约束：
         ① 存在唯一的根结点（Root），无直接前驱（无双亲）；
         ② 除根结点外，树中每一个结点**有且仅有一个直接前驱（双亲）**，但可以有 **0 个或多个直接后继（孩子）**（严格的 $1:N$ 层次分支映射）。
     - **图状结构 / 网状结构（Graph Structure）**：
       - 拓扑约束完全放开：
         ① 任意两个元素之间都可能存在直接关系；
         ② 每一个元素可以有 **0 个、1 个或多个直接前驱**，同时可以有 **0 个、1 个或多个直接后继**（无约束的 $M:N$ 多对多网状映射）。

### 考点 1.2：抽象数据类型（ADT）三元组 $(D, S, P)$ 与前置/后置条件规范
- **【考点定位】** 李冬梅《数据结构（第3版）》§1.2.3 数据类型和抽象数据类型（P6-P7）及 §1.3 抽象数据类型的表示与实现（P7-P10）。
- **【核心数据结构与机制原理】**
  1. **抽象数据类型（Abstract Data Type, ADT）的数学三元组**：
     - 抽象数据类型是指一个数学模型以及定义在该模型上的一组操作。
     - 其严格的数学形式化定义为三元组：
       $$\text{ADT} = (D, S, P)$$
       其中：
       - $D$ 是数据对象（Data Object）；
       - $S$ 是 $D$ 上的关系集（Data Relations）；
       - $P$ 是对 $D$ 的基本操作集（Set of Basic Operations）。
  2. **ADT 形式化伪代码描述语法规范**：
     ```text
     ADT 抽象数据类型名 {
         数据对象: <数据对象的严格数学定义>
         数据关系: <数据关系的严格数学定义>
         基本操作:
             操作名称(参数列表)
                 初始条件 / 前置条件(Pre-condition): <描述操作执行前系统必须满足的状态>
                 操作结果 / 后置条件(Post-condition): <描述操作成功执行后系统呈现的状态与返回值>
     } ADT 抽象数据类型名
     ```
  3. **参数传递约定（值传递 vs 引用/指针传递）**：
     - 在严蔚敏/李冬梅教材的算法描述中：
       - 基本操作的参数若仅用于输入，采用普通变量（值传递）；
       - 若操作需要修改该参数并将结果带回调用处，采用**引用传递（C++ 引用 `&` 语法，或 C 语言指针传递 `*`）**。

### 考点 1.3：算法复杂度渐进符号体系（$O, \Omega, \Theta$）的严格数学定义
- **【考点定位】** 李冬梅《数据结构（第3版）》§1.4.3 算法的时间复杂度（P11-P15）。
- **【核心数据结构与机制原理】**
  1. **渐进上界符号 —— 大 $O$ 符号（Big-O）**：
     - **数学定义**：设 $f(n)$ 和 $g(n)$ 是定义在正整数集上的函数。若存在两个正常数 $c$ 和 $n_0$，使得对所有的 $n \ge n_0$，均满足：
       $$0 \le f(n) \le c \cdot g(n)$$
       则称 $f(n)$ 是 $g(n)$ 的渐进上界，记作 $f(n) = O(g(n))$。
     - **物理意义**：算法在问题规模 $n$ 趋于无穷大时的**最坏性能保证**，界定了运行时间的增长率上限。
  2. **渐进下界符号 —— 大 $\Omega$ 符号（Big-Omega）**：
     - **数学定义**：若存在正常数 $c$ 和 $n_0$，使得对所有的 $n \ge n_0$，均满足：
       $$0 \le c \cdot g(n) \le f(n)$$
       则称 $f(n)$ 是 $g(n)$ 的渐进下界，记作 $f(n) = \Omega(g(n))$。
     - **物理意义**：算法在任何情况下的**性能下限**，界定了解决该问题所需的最少计算代价。例如基于比较的内部排序算法的时间复杂度理论下界为 $\Omega(n \log_2 n)$。
  3. **紧确界符号 —— 大 $\Theta$ 符号（Big-Theta）**：
     - **数学定义**：若存在正常数 $c_1, c_2$ 和 $n_0$，使得对所有的 $n \ge n_0$，均满足：
       $$c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$$
       则称 $f(n)$ 与 $g(n)$ 同阶，记作 $f(n) = \Theta(g(n))$。
     - **充要条件**：$f(n) = \Theta(g(n)) \iff f(n) = O(g(n)) \land f(n) = \Omega(g(n))$。
  4. **极限运算法则（高阶判别）**：
     - 设 $L = \lim_{n \to \infty} \frac{f(n)}{g(n)}$：
       - 若 $L = 0$，则 $f(n) = O(g(n))$ 且 $f(n) \ne \Theta(g(n))$（$f$ 阶数严格低于 $g$）；
       - 若 $0 < L < \infty$，则 $f(n) = \Theta(g(n))$；
       - 若 $L = \infty$，则 $f(n) = \Omega(g(n))$ 且 $f(n) \ne \Theta(g(n))$。

### 考点 1.4：四类存储结构（顺序、链式、索引、散列）的底层时空性能对比
- **【考点定位】** 李冬梅《数据结构（第3版）》§1.2.2 数据结构（P5-P6）。
- **【核心数据结构与机制原理】**
  1. **顺序存储结构（Sequential Storage）**：
     - 把逻辑上相邻的元素存储在物理位置上也相邻的连续存储单元中。
     - **特性**：支持 $O(1)$ 随机存取（基地址 + 下标偏移）；存储密度为 1（无额外指针开销）；但插入与删除必须移动大量数据元素（平均时间复杂度 $O(n)$），且需要预先分配大块连续内存。
  2. **链式存储结构（Linked Storage）**：
     - 每个结点除了存储数据元素本身（数据域），还附加指针域存储逻辑前驱或后继的存储地址。
     - **特性**：物理地址无需连续；插入与删除只需修改指针（$O(1)$ 本地耗时）；但不支持随机存取（顺序存取 $O(n)$）；存储密度小于 1（指针域额外开销）。
  3. **索引存储结构（Indexed Storage）**：
     - 在存储元素信息的同时，建立附加的**索引表（Index Table）**。索引表中的每一项称为索引项，一般形式为“关键字 + 地址”。
     - **分类**：稠密索引（每个数据项都有一个索引项）与稀疏索引（一组数据项对应一个索引项，如分块查找）。
     - **特性**：检索速度快（索引表内可进行折半查找）；但占用额外的索引表存储空间；插入与删除时不仅要维护数据区，还要同步重构索引项。
  4. **散列存储结构（Hash Storage）**：
     - 根据数据元素的关键字，通过预设的**散列函数（Hash Function）**直接计算出该元素的存储物理地址。
     - **特性**：检索、插入与删除的理想平均时间复杂度达到 $O(1)$；但不保持原有的逻辑顺序关系，无法支持按关键字大小顺序遍历或范围查询；当发生冲突时需额外处理。

## 第三部分 第2章 线性表：未考知识点全景精析

### 考点 2.1：顺序表的动态分配扩容机制与内存重分配开销
- **【考点定位】** 李冬梅《数据结构（第3版）》§2.4.1 线性表的顺序表示（P23-P25）。
- **【核心数据结构与机制原理】**
  1. **动态顺序表 C 语言结构体定义**：
     ```c
     #define LIST_INIT_SIZE 100   // 线性表存储空间的初始分配量
     #define LIST_INCREMENT 10    // 线性表存储空间的分配增量
     typedef int ElemType;

     typedef struct {
         ElemType *elem;          // 存储空间基地址
         int length;              // 当前有效元素长度
         int listsize;            // 当前分配的存储容量（以 sizeof(ElemType) 为单位）
     } SqList;
     ```
  2. **动态扩容算法执行时序（`realloc` 机制）**：
     - 当插入元素导致 `L.length >= L.listsize` 时触发扩容：
       ```c
       ElemType *newbase = (ElemType *)realloc(L.elem, (L.listsize + LIST_INCREMENT) * sizeof(ElemType));
       if (!newbase) exit(OVERFLOW); // 存储分配失败
       L.elem = newbase;             // 更新新基地址
       L.listsize += LIST_INCREMENT; // 增加容量
       ```
  3. **底层的两种内存搬迁代价**：
     - **情况一（就地扩展）**：若原内存块之后有足够的连续空闲空间，`realloc` 直接在原地址末尾扩展，无需移动已有数据，开销为 $O(1)$。
     - **情况二（异地搬迁）**：若原内存块后方连续空间不足，操作系统在堆中寻找一片满足新容量的全新连续空间，将原有的 `L.length` 个元素完整拷贝到新空间，释放旧空间，返回新指针。单次扩容时间复杂度上升为 $O(n)$。

### 考点 2.2：一元多项式的顺序与链式代数表示及按指数升序相加算法
- **【考点定位】** 李冬梅《数据结构（第3版）》§2.7.2 有序表的合并及 §2.8 案例分析与实现（P45-P51）。
- **【核心数据结构与机制原理】**
  1. **一元多项式的数学模型**：
     $$P_n(x) = p_0 + p_1 x^{e_1} + p_2 x^{e_2} + \dots + p_m x^{e_m}$$
     每个单项式由**系数（Coefficient, $p_i$）**和**指数（Exponent, $e_i$）**唯一确定。
  2. **多项式单链表结点结构体定义**：
     ```c
     typedef struct PNode {
         float coef;          // 系数
         int expn;            // 指数
         struct PNode *next;  // 指向下一个单项式
     } PNode, *Polynomial;
     ```
  3. **按指数升序多项式相加算法（$P_A = P_A + P_B$）指针流转时序**：
     - 设指针 `p1` 指向多项式 $A$ 的当前项，`p2` 指向多项式 $B$ 的当前项，`pre` 指向 $A$ 中 `p1` 的前驱结点。
     - 算法循环执行直至 `p1` 或 `p2` 为空：
       - **分支 1（`p1->expn < p2->expn`）**：$A$ 中当前项指数较小，保留在结果中，指针后移：`pre = p1; p1 = p1->next;`
       - **分支 2（`p1->expn > p2->expn`）**：$B$ 中当前项指数较小，需将 `p2` 结点摘下插入到 `p1` 之前：
         ```c
         PNode *r = p2->next;
         p2->next = p1;
         pre->next = p2;
         pre = p2;
         p2 = r;
         ```
       - **分支 3（`p1->expn == p2->expn`）**：两项指数相同，系数相加 `sum = p1->coef + p2->coef`：
         - 若 `sum != 0`：修改 `p1->coef = sum; pre = p1;`，释放 `p2` 对应结点并后移；
         - 若 `sum == 0`：相加后项抵消，必须同时从链表 $A$ 中删除 `p1` 结点并释放，同时释放 `p2` 结点：
           ```c
           pre->next = p1->next;
           free(p1);
           p1 = pre->next;
           PNode *t = p2; p2 = p2->next; free(t);
           ```
     - 循环结束后，若 `p2` 仍非空，将剩余链表段直接挂接在 `pre->next`。
     - **时间复杂度**：设多项式 $A$ 项数为 $m$，$B$ 项数为 $n$，算法仅需单遍扫描，时间复杂度为 $O(m + n)$；空间复杂度为 $O(1)$（就地合并，仅复用已有结点）。

### 考点 2.3：双向循环链表对称性与四步指针修改原子时序
- **【考点定位】** 李冬梅《数据结构（第3版）》§2.5.4 双向链表（P41-P43）。
- **【核心数据结构与机制原理】**
  1. **双向循环链表的结构体定义**：
     ```c
     typedef struct DuLNode {
         ElemType data;
         struct DuLNode *prior; // 指向前驱
         struct DuLNode *next;  // 指向后继
     } DuLNode, *DuLinkList;
     ```
  2. **双向循环链表的对称不变性（Symmetry Invariant）**：
     - 对于链表中的任意非空结点 `p`，恒满足：
       ```c
       p->prior->next == p == p->next->prior;
       ```
     - 空表判定条件：带头结点 `L` 的双向循环链表为空时，`L->next == L && L->prior == L`。
  3. **在第 $i$ 个结点前插入新结点 $s$ 的四步原子时序**：
     - 设 `p` 指向第 $i$ 个元素结点：
       ```c
       s->data = e;
       s->prior = p->prior;      // 步骤 1: 新结点的 prior 指向原前驱
       p->prior->next = s;      // 步骤 2: 原前驱的 next 指向新结点
       s->next = p;             // 步骤 3: 新结点的 next 指向 p
       p->prior = s;            // 步骤 4: p 的 prior 指向新结点
       ```
  4. **删除结点 $p$ 的指针调整时序**：
     - 删除结点 `p` 仅需两步指针修改即可将其从链环中脱开：
       ```c
       p->prior->next = p->next; // 步骤 1: p 的前驱的 next 跳过 p 指向 p 的后继
       p->next->prior = p->prior; // 步骤 2: p 的后继的 prior 跳过 p 指向 p 的前驱
       free(p);                 // 步骤 3: 释放被删结点内存
       ```
     - 相比单链表必须找到前驱结点（$O(n)$ 时间），双向链表删除已知结点 `p` 的时间复杂度仅为 $O(1)$。

### 考点 2.4：线性表监视哨（哨兵）设置技巧与内层循环优化
- **【考点定位】** 李冬梅《数据结构（第3版）》§7.2.1 顺序查找（P213-P214）。
- **【核心数据结构与机制原理】**
  1. **普通无哨兵顺序查找的代码模式**：
     ```c
     int Search_Seq_Normal(int a[], int n, int key) {
         for (int i = 1; i <= n; i++) {
             if (a[i] == key) return i; // 每轮循环需进行两次判断: ① 越界检查 i <= n; ② 键值匹配 a[i] == key
         }
         return 0;
     }
     ```
  2. **引入监视哨（Sentinel）的顺序查找实现**：
     - 将数组的 `0` 号下标单元空出，专门用作“哨兵”。查找时将待查关键字存放在 `0` 号位置：
       ```c
       int Search_Seq_Sentinel(int a[], int n, int key) {
           a[0] = key; // 设置哨兵
           int i = n;
           while (a[i] != key) { // 循环体内仅需一次判断！
               i--;
           }
           return i; // 若返回 0 说明表中无此元素，查找失败
       }
       ```
  3. **算法性能优化分析**：
     - 当数据规模 $n$ 较大时，普通顺序查找在每一次循环中必须执行**下标越界判断（$i \le n$）**和**关键字相等判断（$a[i] == key$）**两道逻辑比较。
     - 引入哨兵后，因下标为 0 的位置必然等于 `key`，`while` 循环绝对不可能发生下标越界溢出，从而**彻底消除了每次循环的下标越界判定指令**，在底层汇编中减少了一条条件跳转指令（如 `JLE`），使平均比对与分支跳转开销降低近 50%。

## 第四部分 第3章 栈和队列：未考知识点全景精析

### 考点 3.1：两栈共享存储空间（双端栈）的实现机理与边界判断
- **【考点定位】** 李冬梅《数据结构（第3版）》§3.3.2 顺序栈的表示和实现（P65-P66）。
- **【核心数据结构与机制原理】**
  1. **双端栈（Shared Double Stack）的设计初衷**：
     - 若为两个独立的栈分别分配固定长度的数组，可能出现一个栈已溢出，而另一个栈却大量闲置的结构性浪费。
     - 利用两个栈的数据进出均在栈顶的特性，让它们共享同一片连续的向量存储空间 $V[0 \dots \text{MAXSIZE}-1]$，两个栈底分别固定在数组的两端，**两个栈顶向中间相对生长**。
  2. **数据结构定义**：
     ```c
     #define MAXSIZE 100
     typedef struct {
         ElemType data[MAXSIZE];
         int top[2]; // top[0] 为 0 号栈栈顶指针，top[1] 为 1 号栈栈顶指针
     } DblStack;
     ```
  3. **初始状态与边界判定条件**：
     - **栈空状态**：
       - 0 号栈为空：`top[0] == -1`；
       - 1 号栈为空：`top[1] == MAXSIZE`。
     - **栈满状态（临界条件）**：
       - 当两个栈顶指针在数组中间相遇相碰时，整个存储空间耗尽：
         ```c
         top[0] + 1 == top[1]  // 栈满
         ```
  4. **入栈与出栈操作实现**：
     - **入栈操作（`Push(DblStack *S, int i, ElemType x)`）**：
       - 检查是否栈满：`if (S->top[0] + 1 == S->top[1]) return OVERFLOW;`
       - 若 `i == 0`（0 号栈入栈）：先将 `top[0]` 加 1，再赋值：`S->data[++(S->top[0])] = x;`
       - 若 `i == 1`（1 号栈入栈）：先将 `top[1]` 减 1，再赋值：`S->data[--(S->top[1])] = x;`
     - **出栈操作（`Pop(DblStack *S, int i, ElemType *x)`）**：
       - 若 `i == 0`：检查 `if (S->top[0] == -1) return UNDERFLOW;`，取值后 `top[0]` 减 1：`*x = S->data[(S->top[0])--];`
       - 若 `i == 1`：检查 `if (S->top[1] == MAXSIZE) return UNDERFLOW;`，取值后 `top[1]` 加 1：`*x = S->data[(S->top[1])++];`
     - **时间复杂度**：两栈的入栈与出栈时间复杂度均为 $O(1)$，空间利用率达到理论最大化。

### 考点 3.2：利用显式工作栈将递归算法转换为非递归算法的状态机模型
- **【考点定位】** 李冬梅《数据结构（第3版）》§3.4 栈与递归（P70-P75）。
- **【核心数据结构与机制原理】**
  1. **递归执行的内核物理模型 —— 递归工作栈与活动记录**：
     - 当一个函数调用自身时，操作系统在调用栈（Call Stack）上开辟一个称为**活动记录（Activation Record / 栈帧 Stack Frame）**的内存块，其内容包含：
       ① 本层调用的**返回地址（Return Address）**；
       ② 调用时传递的**形式参数（Parameters）**；
       ③ 本层函数声明的**局部变量（Local Variables）**。
     - 递归深度的增加会导致栈帧线性累积，当深度过大时引发“栈溢出（Stack Overflow）”。
  2. **两类递归的非递归转换模式**：
     - **模式一：单向递归与尾递归（Tail Recursion）**：
       - 递归调用语句出现在函数的末尾，且之后无任何后续计算。
       - **转换策略**：**完全无需辅助栈**，直接使用一个 `while` 循环语句结合参数迭代更新即可原地替换（例如单链表遍历、求阶乘、斐波那契数列迭代）。
     - **模式二：多向分治与树形递归（如汉诺塔、二叉树后序遍历）**：
       - **转换策略**：必须建立显式自定义工作栈，模拟系统栈的压栈与弹栈。
  3. **手工转换算法的通用状态机模板**：
     - 构造栈元素结构体，记录递归现场：
       ```c
       typedef struct {
           int n;               // 问题规模参数
           int status;          // 执行进度状态机标志 (0: 初次调用, 1: 处理左子树返回, 2: 处理右子树返回)
           ElemType local_var;  // 局部变量缓存
       } StackNode;
       ```
     - 循环控制引擎：
       - 当栈非空时，取出栈顶任务，根据 `status` 状态字段跳转至对应的代码分支执行；
       - 若需要向下递归，修改当前节点状态并将子任务压入栈顶；
       - 若递归基（Base Case）触发或当前阶段任务完毕，执行出栈并把返回值带回上层栈帧。

### 考点 3.3：循环队列设置标志位 tag 或计数器 count 的区分机制
- **【考点定位】** 李冬梅《数据结构（第3版）》§3.5.2 顺序队的表示和实现（P77-P80）。
- **【核心数据结构与机制原理】**
  1. **循环队列队空与队满指针重合矛盾**：
     - 设循环队列基地址为 `Q.base`，容量为 `MAXQSIZE`，队头指针 `front` 指向队头元素，队尾指针 `rear` 指向队尾元素的下一个空闲位置。
     - 当队列为空时：`Q.front == Q.rear`；
     - 当队列入满时：`Q.front == Q.rear`；
     - 指针条件完全重合，无法仅凭两指针位置区分空满。
  2. **机制一：设置标志位 `tag`**：
     - 队列结构体增加布尔成员 `int tag;`（初值置为 0）。
     - **时序约定**：
       - 每次成功执行**入队操作**后，置 `tag = 1`（指示最近一次操作是由于插入导致的）；
       - 每次成功执行**出队操作**后，置 `tag = 0`（指示最近一次操作是由于删除导致的）。
     - **状态判定公式**：
       - **队空条件**：`Q.front == Q.rear && Q.tag == 0`
       - **队满条件**：`Q.front == Q.rear && Q.tag == 1`
  3. **机制二：设置元素计数器 `count`**：
     - 队列结构体增加整型成员 `int count;`（初值置为 0）。
     - **时序约定**：
       - 入队成功：`Q.rear = (Q.rear + 1) % MAXQSIZE; Q.count++;`
       - 出队成功：`Q.front = (Q.front + 1) % MAXQSIZE; Q.count--;`
     - **状态判定公式**：
       - **队空条件**：`Q.count == 0`
       - **队满条件**：`Q.count == MAXQSIZE`
     - **当前队列有效长度**：直接读取 `Q.count`，无需通过模运算 `(rear - front + MAXQSIZE) % MAXQSIZE` 计算。

### 考点 3.4：双端队列（Deque）受限排列性质推演
- **【考点定位】** 李冬梅《数据结构（第3版）》§3.5.1 队列的类型定义（P76）。
- **【核心数据结构与机制原理】**
  1. **双端队列（Deque, Double-ended Queue）基础定义**：
     - 允许在两端（端点 1 与端点 2）同时进行入队和出队操作的线性表。
  2. **两类受限双端队列分类**：
     - **输入受限的双端队列（Input-restricted Deque）**：
       - 仅允许在一端（如端点 1）进行插入操作，但允许在两端（端点 1 和端点 2）进行删除操作。
     - **输出受限的双端队列（Output-restricted Deque）**：
       - 仅允许在一端（如端点 1）进行删除操作，但允许在两端（端点 1 和端点 2）进行插入操作。
  3. **合法输出序列推演判定定理**：
     - **与普通栈序列的包含关系**：
       - 普通栈相当于只在一端进行插入与删除（输入与输出均受限于同一端）。
       - 任何对于普通栈合法的输出序列（满足卡特兰数 Catalan Number $C_n = \frac{1}{n+1}\binom{2n}{n}$），对于输入受限或输出受限双端队列**必定是合法的**。
     - **非法序列判定模型（以输入序列 1, 2, 3, 4 为例）**：
       - 对于输入受限双端队列：元素只能从一端进入，相当于在序列输入时只能挂接在队尾；从两端出队相当于可以在队头出，也可以在队尾“反悔”撤出。
       - 例如序列 `4, 2, 1, 3`：4 首先进入并立即从端点 1 出队；接着 2, 1, 3 顺序进入队列，若 2 出队，则 2 必须处于两端之一，若 2 夹在中间则必不可行。通过模拟双端指针进出状态即可严格判定合法性。

## 第五部分 第4章 串、数组和广义表：未考知识点全景精析

### 考点 4.1：串的块链存储结构与存储密度推导
- **【考点定位】** 李冬梅《数据结构（第3版）》§4.3.2 串的存储结构（P108-P109）。
- **【核心数据结构与机制原理】**
  1. **块链存储结构（Block Chain Storage）定义**：
     - 串属于线性表，也可以采用链式存储。若每个链表结点仅存放 1 个字符，由于一个指针通常占用 4 字节（或 8 字节），而一个字符仅占 1 字节，会导致指针域开销占比过大。
     - 因此采用**分块链表**结构：每个链表结点（称为“块 Block”）存放固定长度的**多个字符**，最后一个结点不足的部分用特殊字符（如 `#`）填充。
  2. **C 语言结构体定义**：
     ```c
     #define CHUNKSIZE 4 // 块大小（每个结点存放的字符数）
     typedef struct Chunk {
         char ch[CHUNKSIZE];
         struct Chunk *next;
     } Chunk;

     typedef struct {
         Chunk *head; // 头指针
         Chunk *tail; // 尾指针
         int curlen;  // 串的当前长度
     } LString;
     ```
  3. **存储密度（Storage Density）计算公式与权衡**：
     - 存储密度严格定义为：
       $$\text{存储密度} = \frac{\text{串值所占的存储位（字节数）}}{\text{实际分配的总存储位（字节数）}}$$
     - 设每个结点存放 $C$ 个字符，指针占 $P$ 字节。则单结点的存储密度为：
       $$\text{Density} = \frac{C \times 1}{C \times 1 + P} = \frac{C}{C + P}$$
     - **工程权衡**：
       - $C$ 越大（块越大），存储密度越高，空间利用率越好；但在进行串插入、删除、拼接操作时，可能引起大面积的跨块数据搬移；
       - $C$ 越小，插入删除灵活，但存储密度骤降，碎片与指针开销激增。

### 考点 4.2：KMP 模式匹配算法中 nextval 修正值数组推导与比对优化
- **【考点定位】** 李冬梅《数据结构（第3版）》§4.3.3 串的模式匹配算法（P113-P116）。
- **【核心数据结构与机制原理】**
  1. **经典 $next$ 数组的回退冗余缺陷**：
     - 在普通 KMP 算法中，若模式串在位置 $j$ 与主串字符失配（$S[i] \ne P[j]$），主串指针 $i$ 不回退，模式串指针回退至 $k = next[j]$ 继续比对 $S[i]$ 与 $P[k]$。
     - **冗余发生场景**：若模式串自身恰好满足 **$P[j] == P[next[j]]$**（即回退目标位置的字符与当前失配字符完全相同）：
       因已知 $S[i] \ne P[j]$，而 $P[k] == P[j]$，则 $S[i]$ 必然也绝不可能等于 $P[k]$！
       这意味着紧接着进行的比对 $S[i] == P[k]$ **注定失败**，是一次毫无意义的无效比对，随后指针还会被迫进一步回退到 $next[k]$。
  2. **$nextval$ 修正值数组的递归推导算法**：
     - 在求出基础 $next$ 数组的基础上，加入同字符前瞻判定：
       - ① 规定 $nextval[1] = 0$；
       - ② 对于 $j = 2, 3, \dots, m$：
         设基础回退位置为 $k = next[j]$：
         - 若 **$P[j] \ne P[k]$**：无需修正，保持原样：
           $$nextval[j] = next[j]$$
         - 若 **$P[j] == P[k]$**：产生冗余，直接继承其前驱的回退值：
           $$nextval[j] = nextval[k]$$
  3. **实战演算对照示例**：
     - 模式串：`a  a  a  a  b`
     - 下标 $j$：`1  2  3  4  5`
     - 字符 $P[j]$：`a  a  a  a  b`
     - $next[j]$：`0  1  2  3  4`
     - **$nextval$ 逐位推导**：
       - $j=1$：固定 $nextval[1] = 0$；
       - $j=2$：$next[2]=1$，$P[2]='a' == P[1]='a'$ $\implies nextval[2] = nextval[1] = 0$；
       - $j=3$：$next[3]=2$，$P[3]='a' == P[2]='a'$ $\implies nextval[3] = nextval[2] = 0$；
       - $j=4$：$next[4]=3$，$P[4]='a' == P[3]='a'$ $\implies nextval[4] = nextval[3] = 0$；
       - $j=5$：$next[5]=4$，$P[5]='b' \ne P[4]='a'$ $\implies nextval[5] = next[5] = 4$。
     - $nextval[j]$ 结果为：`0  0  0  0  4`。当模式串第 4 个字符 `'a'` 失配时，指针直接一步到位回退至 0，彻底消除了连续 3 次无效回退比对。

### 考点 4.3：多维数组行优先与列优先连续映射寻址通用多项式推导
- **【考点定位】** 李冬梅《数据结构（第3版）》§4.4.2 数组的顺序存储（P117-P119）。
- **【核心数据结构与机制原理】**
  1. **多维数组连续存储映射本质**：
     - 计算机内存是一维线性寻址空间，存储多维数组必须通过映射函数将其多维下标转换为一维内存相对位移。
  2. **以行优先（Row-Major Order）为主序的一般公式推导**：
     - 设 $n$ 维数组 $A[b_1 \dots e_1, b_2 \dots e_2, \dots, b_n \dots e_n]$，其中每一维下标的下界为 $b_k$，上界为 $e_k$。
     - 第 $k$ 维的维长（元素个数）为：$m_k = e_k - b_k + 1$。
     - 设基地址为 $\text{LOC}(A[b_1, b_2, \dots, b_n]) = \alpha$，每个元素占用 $L$ 个存储单元。
     - 任意元素 $A[i_1, i_2, \dots, i_n]$ 的内存物理起始地址映射为：
       $$\text{LOC}(A[i_1, i_2, \dots, i_n]) = \alpha + L \cdot \sum_{k=1}^n \left( (i_k - b_k) \cdot \prod_{j=k+1}^n m_j \right)$$
       特别地，对于最后一维 $k=n$，$\prod_{j=n+1}^n m_j = 1$。
  3. **三维数组特例推导（行优先）**：
     - 设三维数组 $A[0 \dots m-1, 0 \dots n-1, 0 \dots p-1]$（下标从 0 开始）：
       $$\text{LOC}(A[i, j, k]) = \alpha + L \cdot \big(i \cdot (n \cdot p) + j \cdot p + k\big)$$
  4. **列优先（Column-Major Order）主序映射公式**：
     - 优先按高维方向展平，三维数组列优先寻址公式为：
       $$\text{LOC}(A[i, j, k]) = \alpha + L \cdot \big(k \cdot (m \cdot n) + j \cdot m + i\big)$$

### 考点 4.4：稀疏矩阵的三元组顺序表及其快速转置算法
- **【考点定位】** 李冬梅《数据结构（第3版）》§4.4.3 特殊矩阵的压缩存储（P122-P125）。
- **【核心数据结构与机制原理】**
  1. **稀疏矩阵三元组顺序表（Triple Table）定义**：
     ```c
     #define MAXSIZE 12500 // 非零元的最大个数
     typedef struct {
         int i, j;         // 该非零元的行下标和列下标
         ElemType e;       // 该非零元的值
     } Triple;

     typedef struct {
         Triple data[MAXSIZE + 1]; // 非零元三元组表，data[0] 未用
         int mu, nu, tu;           // 矩阵的行数、列数和非零元个数
     } TSMatrix;
     ```
  2. **传统普通转置算法的性能缺陷**：
     - 按列号 $col = 1, 2, \dots, nu$ 重复扫描三元组表 $tu$ 次以保证转置后的行有序，时间复杂度为 $O(nu \cdot tu)$。若非零元个数 $tu$ 接近 $mu \cdot nu$，复杂度退化为 $O(mu \cdot nu^2)$。
  3. **快速转置算法（Fast Transpose）核心机制**：
     - 核心思想：**空间换时间，单遍扫描定位**。预先计算转置矩阵中每一行的非零元个数以及该行首个非零元在三元组中的准确物理位置。
     - **辅助向量设计**：
       - `num[col]`：统计原矩阵第 $col$ 列（即转置后第 $col$ 行）中非零元的总个数。
       - `cpot[col]`：指示原矩阵第 $col$ 列首个非零元在转置三元组表中的下标起始位置。
     - **递推关系**：
       - `cpot[1] = 1;`
       - `cpot[col] = cpot[col - 1] + num[col - 1]` （$2 \le col \le nu$）。
     - **转置循环核心代码**：
       ```c
       for (p = 1; p <= M.tu; ++p) {
           col = M.data[p].j;
           q = cpot[col];              // 直接取得转置后应存入的绝对位置
           T.data[q].i = M.data[p].j;
           T.data[q].j = M.data[p].i;
           T.data[q].e = M.data[p].e;
           ++cpot[col];                // 该行后续非零元的存储位置加 1
       }
       ```
     - **时间复杂度**：计算 `num` 耗时 $O(tu)$，计算 `cpot` 耗时 $O(nu)$，重排转置耗时 $O(tu)$。总时间复杂度严格降为 **$O(nu + tu)$**，在稀疏状态下逼近线性时间。

### 考点 4.5：稀疏矩阵的正交十字链表（Orthogonal List）结构
- **【考点定位】** 李冬梅《数据结构（第3版）》§4.4.3 特殊矩阵的压缩存储（P125-P127）。
- **【核心数据结构与机制原理】**
  1. **十字链表（Orthogonal List）产生的必要性**：
     - 三元组顺序表适用于静态矩阵运算；若矩阵频繁进行相加、相乘产生新的非零元，三元组表将面临大量数据元素的后移开销。十字链表采用链式指针交错存储，插入删除极其高效。
  2. **结点结构设计**：
     - **非零元结点（OLNode）**：包含 5 个域：
       ```c
       typedef struct OLNode {
           int i, j;                 // 非零元的行、列下标
           ElemType e;               // 非零元的值
           struct OLNode *right;     // 同一行中下一个非零元的右指针域
           struct OLNode *down;      // 同一列中下一个非零元的下指针域
       } OLNode, *OLink;
       ```
     - **十字链表表头结构（CrossList）**：
       ```c
       typedef struct {
           OLink *rhead;             // 行表头指针数组 (大小为 mu + 1)
           OLink *chead;             // 列表头指针数组 (大小为 nu + 1)
           int mu, nu, tu;           // 行数、列数、非零元个数
       } CrossList;
       ```
  3. **网状正交逻辑拓扑**：
     - 矩阵中的每一个非零元结点**同时处于两个单链表之中**：
       - 沿 `right` 指针看，它是第 $i$ 行非零元按列升序排列的行单链表中的一个结点；
       - 沿 `down` 指针看，它是第 $j$ 列非零元按行升序排列的列单链表中的一个结点。

### 考点 4.6：广义表（Generalized List）的表头与表尾运算规则
- **【考点定位】** 李冬梅《数据结构（第3版）》§4.5.1 广义表的定义（P127-P129）。
- **【核心数据结构与机制原理】**
  1. **广义表的递归数学定义**：
     - 广义表是 $n\ (n \ge 0)$ 个表元素 $a_1, a_2, \dots, a_n$ 的有限序列，记作：
       $$L = (a_1, a_2, \dots, a_n)$$
     - 元素 $a_i$ 可以是一个不可分割的**单元素（Atom，原子）**，也可以是**另一个广义表（Sublist，子表）**。
     - 若广义表非空，则 $a_1$ 称为 $L$ 的**表头（Head）**，其余元素构成的广义表 $(a_2, a_3, \dots, a_n)$ 称为 $L$ 的**表尾（Tail）**。
  2. **两大核心操作规则（数学铁律）**：
     - **`GetHead(L)`**：
       - 取出非空广义表的第一个元素。
       - **取值类型**：**既可以是一个原子，也可以是一个广义表子表**。
     - **`GetTail(L)`**：
       - 取出非空广义表除去表头元素外、**由剩余所有元素组成的广义表**！
       - **取值类型**：**表尾必然是一个广义表，绝对不可能是原子**！哪怕原表只有一个元素，其表尾也必然是空表 `()`。
  3. **复合嵌套提取典型示例推演**：
     - 设广义表 $L = (a, (b, c, d))$：
       - $\text{GetHead}(L) = a$；
       - $\text{GetTail}(L) = ((b, c, d))$；
       - $\text{GetHead}(\text{GetTail}(L)) = (b, c, d)$；
       - $\text{GetTail}(\text{GetHead}(\text{GetTail}(L))) = (c, d)$；
       - $\text{GetHead}(\text{GetTail}(\text{GetHead}(\text{GetTail}(L)))) = c$。

### 考点 4.7：广义表的深度和长度求解算法与双链存储结构
- **【考点定位】** 李冬梅《数据结构（第3版）》§4.5.2 广义表的存储结构（P129-P131）。
- **【核心数据结构与机制原理】**
  1. **广义表的长度（Length）与深度（Depth）定义**：
     - **长度**：广义表中由顶层最外层括号直接包含的元素（原子或子表）的个数。
     - **深度**：广义表中括号的最大嵌套重数（单原子的深度定义为 0，空表 `()` 的深度定义为 1）。
     - **深度递归计算公式**：
       $$\text{Depth}(L) = \begin{cases} 0, & \text{若 } L \text{ 为原子} \\ 1, & \text{若 } L \text{ 为空表 } () \\ 1 + \max_{1 \le i \le n}\{\text{Depth}(a_i)\}, & \text{若 } L = (a_1, \dots, a_n) \end{cases}$$
  2. **头尾链存储结构（Head-Tail Linked Storage）**：
     - 采用两类结点结构，通过标志域 `tag` 区分：
       - `tag == 0`（原子结点）：包含标志域 `tag` 与值域 `atom`；
       - `tag == 1`（表结点）：包含标志域 `tag`、表头指针域 `hp`（指向表头元素）与表尾指针域 `tp`（指向表尾广义表）。
     ```c
     typedef enum { ATOM, LIST } ElemTag;
     typedef struct GLNode {
         ElemTag tag;
         union {
             char atom;
             struct { struct GLNode *hp, *tp; } ptr;
         };
     } GLNode, *GList;
     ```
  3. **扩展线性链表存储结构**：
     - 所有结点均设置三个指针域：`tag`、`hp`（指向表头的指针或原子值）和 `tp`（指向同层下一个结点的指针）。

### 考点 5.1：三叉链表在寻找最近公共祖先（LCA）与向上回溯中的应用
- **【考点定位】** 李冬梅《数据结构（第3版）》§5.4.2 二叉树的存储结构（P144-P146）。
- **【核心数据结构与机制原理】**
  1. **三叉链表（Tri-tree Linked List）数据结构定义**：
     - 在普通二叉链表（左孩子 `lchild`、右孩子 `rchild`）的基础上，增加一个**指向其双亲结点的指针域 `parent`**：
     ```c
     typedef struct BiTPNode {
         ElemType data;
         struct BiTPNode *lchild; // 左孩子指针
         struct BiTPNode *rchild; // 右孩子指针
         struct BiTPNode *parent; // 双亲指针 (根结点的 parent 为 NULL)
     } BiTPNode, *BiPTree;
     ```
  2. **寻找任意两结点 $u$ 和 $v$ 的最近公共祖先（LCA, Lowest Common Ancestor）算法**：
     - 在普通二叉链表中寻找 LCA 必须通过根结点向下做递归树搜索（开销 $O(n)$ 且需维护复杂路径栈）。
     - 在三叉链表中，问题**等价转化为两个单链表相交求第一个交点**：
       - ① 从结点 $u$ 沿 `parent` 指针单向向上遍历至根结点，计算 $u$ 的深度 $d_u$；
       - ② 从结点 $v$ 沿 `parent` 指针单向向上遍历至根结点，计算 $v$ 的深度 $d_v$；
       - ③ 设两者深度差为 $\Delta d = |d_u - d_v|$，让较深者结点的指针先沿 `parent` 向上移动 $\Delta d$ 步，使两指针处于同一水平树高深度；
       - ④ 随后两个指针同时同步沿 `parent` 向上单步回溯：
         ```c
         while (p != q) {
             p = p->parent;
             q = q->parent;
         }
         return p; // 此时 p 即为最近公共祖先 LCA
         ```
     - **时空复杂度**：若树的高度为 $h$，寻找 LCA 的时间复杂度严格为 $O(h)$，辅助空间复杂度为 $O(1)$。

### 考点 5.2：二叉树后序非递归遍历单栈双向访问标记（r 辅助指针）算法
- **【考点定位】** 李冬梅《数据结构（第3版）》§5.5.1 遍历二叉树（P148-P150）。
- **【核心数据结构与机制原理】**
  1. **后序非递归遍历的特殊性与核心难点**：
     - 前序（根左右）与中序（左根右）非递归遍历中，结点出栈访问的时机明确；
     - 后序遍历（左右根）中，一个结点会被访问两次：从左子树返回时不能访问根，必须继续深入右子树；**只有从右子树处理返回时，才能真正访问根结点**。因此必须准确区分是从左子树返回还是从右子树返回。
  2. **单栈结合最近访问指针 $r$ 算法逻辑设计**：
     - 引入辅助指针 `r`（Recent），记录**最近刚刚访问并输出的结点**。
     - **标准算法执行时序**：
       ```c
       void PostOrder_NonRec(BiTree T) {
           InitStack(S);
           BiTree p = T;
           BiTree r = NULL; // r 指向最近访问过的结点
           while (p || !StackEmpty(S)) {
               if (p) {
                   Push(S, p);
                   p = p->lchild; // 一路向左将左子树全部压栈
               } else {
                   GetTop(S, p); // 读栈顶，暂不出栈
                   // 若右子树存在且未被访问过，转向右子树
                   if (p->rchild && p->rchild != r) {
                       p = p->rchild;
                   } else {
                       // 否则说明右子树为空，或右子树刚刚已经访问完毕返回
                       Pop(S, p);     // 弹出栈顶
                       visit(p);      // 访问结点
                       r = p;         // 标记当前结点为最近访问过的结点
                       p = NULL;      // 关键: 重置 p 为 NULL，防止下轮循环重复向左压栈
                   }
               }
           }
       }
       ```
  3. **祖先路径性质（核心衍生定理）**：
     - 在后序非递归遍历进行到任意时刻，**当前工作栈 $S$ 中从栈底到栈顶的所有结点序列，恰好构成从二叉树根结点到当前正被考察结点的唯一祖先路径**。可直接用于求解根到某结点的路径打印或两个结点的所有公共祖先。

### 考点 5.3：前序与后序线索二叉树找前驱/后继的不对称性与局限性
- **【考点定位】** 李冬梅《数据结构（第3版）》§5.5.2 线索二叉树（P150-P154）。
- **【核心数据结构与机制原理】**
  1. **线索化二叉树的标志位规范**：
     - `LTag = 0` 指向左孩子，`LTag = 1` 指向中序/前序/后序前驱；
     - `RTag = 0` 指向右孩子，`RTag = 1` 指向中序/前序/后序后继。
  2. **中序线索二叉树的对称优雅性**：
     - 中序遍历中，无论找前驱（`LTag == 1` 直接沿线索，`LTag == 0` 则为左子树最右下结点）还是找后继（`RTag == 1` 直接沿线索，`RTag == 0` 则为右子树最左下结点），均**具有对称可逆性，无需知道父结点即可完成**。
  3. **前序线索二叉树找前驱的结构性死局**：
     - **找后继**：若 `RTag == 1`，直接取 `rchild`；若 `RTag == 0`，若有左孩子后继就是左孩子，否则后继就是右孩子，十分简便。
     - **找前驱（致命缺陷）**：若 `LTag == 1`，直接取 `lchild`；
       但若 **`LTag == 0`**（左孩子存在），根据前序遍历规则（根 $\to$ 左 $\to$ 右），当前结点是其双亲的左孩子或右孩子，其前驱可能是双亲结点，也可能是双亲左子树中按前序遍历的最后一个结点。**在没有指向双亲指针（parent）的情况下，前序线索二叉树无法直接找到前驱结点**！
  4. **后序线索二叉树找后继的结构性死局**：
     - **找前驱**：若 `LTag == 1`，直接取 `lchild`；若 `LTag == 0`，若有右孩子前驱是右孩子，若无右孩子前驱是左孩子。
     - **找后继（致命缺陷）**：若 `RTag == 1`，直接取 `rchild`；
       但若 **`RTag == 0`**（右孩子存在），根据后序遍历规则（左 $\to$ 右 $\to$ 根），当前结点为其双亲结点的左孩子或右孩子。若当前结点是双亲的右孩子（或双亲无右孩子时为其左孩子），其后继即为双亲结点。**在没有双亲指针辅助的情况下，后序线索二叉树无法直接找到后继结点**！

### 考点 5.4：带头结点的线索二叉树双向闭环结构规范
- **【考点定位】** 李冬梅《数据结构（第3版）》§5.5.2 线索二叉树（P154-P156）。
- **【核心数据结构与机制原理】**
  1. **带头结点的线索二叉树拓扑结构**：
     - 为了使线索二叉树的遍历形式与双向循环链表保持统一，增设一个**头结点（Head Node）**。
     - 头结点的标志域强制规定为：`LTag = 0`，`RTag = 1`。
  2. **指针闭环绑定四大规则**：
     - **规则 1**：头结点的 `lchild` 指向二叉树的**根结点**；
     - **规则 2**：头结点的 `rchild` 指针**反向指向遍历序列中的最后一个结点**；
     - **规则 3**：二叉树遍历序列中的**第一个结点**，其原本悬空的 `lchild` 线索指针（`LTag = 1`）**反向指向头结点**；
     - **规则 4**：二叉树遍历序列中的**最后一个结点**，其原本悬空的 `rchild` 线索指针（`RTag = 1`）**直接指向头结点**。
  3. **空树特例状态**：
     - 当二叉树为空树时，头结点的 `lchild` 与 `rchild` 均指向头结点自身（`Thrt->lchild == Thrt && Thrt->rchild == Thrt`）。

### 考点 5.5：树的孩子链表表示法（带双亲结点的孩子链表）
- **【考点定位】** 李冬梅《数据结构（第3版）》§5.6.1 树的存储结构（P157-P158）。
- **【核心数据结构与机制原理】**
  1. **结构设计思想**：
     - 把树中每个结点的所有孩子结点排列起来，用单链表连接；
     - 树中全部 $n$ 个结点的孩子链表头指针组成一个连续的顺序表头数组。
  2. **C 语言两级结构体定义**：
     ```c
     // 孩子链表中的结点
     typedef struct CTNode {
         int child;             // 该孩子结点在表头数组中的下标
         struct CTNode *next;   // 指向下一个孩子结点的指针
     } *ChildPtr;

     // 表头数组元素定义
     typedef struct {
         TElemType data;        // 结点数据
         int parent;            // 双亲位置下标 (若增设此项，则为带双亲的孩子链表)
         ChildPtr firstchild;   // 指向该结点第一个孩子的孩子链表头指针
     } CTBox;

     // 树结构体
     typedef struct {
         CTBox nodes[MAX_TREE_SIZE]; // 结点数组
         int n, r;                   // 结点总数与根结点的下标位置
     } CTree;
     ```
  3. **操作性能分析**：
     - 查找一个结点的孩子非常容易，直接沿 `firstchild` 遍历单链表即可（耗时与出度成正比）；
     - 若未增设 `parent` 域，寻找双亲必须全表遍历所有单链表，耗时 $O(n)$；
     - 增设 `parent` 域后，成为“双亲孩子表示法”，兼顾了找孩子与找双亲的双重优势。

### 考点 5.6：并查集的按秩合并与路径压缩反阿克曼函数复杂度推导
- **【考点定位】** 李冬梅《数据结构（第3版）》§5.8 并查集及其应用（P165-P168）。
- **【核心数据结构与机制原理】**
  1. **朴素并查集的退化风险**：
     - 用树的双亲表示法维护集合。`parent[i]` 存储双亲下标，根结点的双亲为负数。
     - 若盲目将一棵树合并到另一棵树下，可能导致树退化为一条长链，单次 `Find` 操作的最坏时间复杂度退化至 $O(n)$。
  2. **优化机制一：按秩合并（Union by Rank）**：
     - 这里的“秩（Rank）”通常指定为**树的高度（Depth）**或**树中结点的总数（Size）**。
     - **合并规则**：**矮树合并到高树之下**（小树合并到大树之下）。
       - 只有当两棵树的秩相同（高度相同）时，合并后新树的秩才加 1；
       - 若两棵树秩不同，合并后总树高保持较大者的高度不变。
     - **效果**：保证包含 $n$ 个结点的并查集树的高度**严格不超过 $\lfloor \log_2 n \rfloor + 1$**。
  3. **优化机制二：路径压缩（Path Compression）**：
     - 在执行 `Find(x)` 寻找根结点的过程中，将查找路径上遇到的**所有沿途结点直接重新挂接在根结点之下**。
     - **递归实现代码**：
       ```c
       int Find(int parent[], int x) {
           if (parent[x] < 0) return x; // 找到根
           return parent[x] = Find(parent, parent[x]); // 路径压缩: 直接将父指针更新为根
       }
       ```
  4. **时间复杂度阿克曼函数极限推导**：
     - 同时采用按秩合并与路径压缩时，对于包含 $n$ 个元素的集合执行连续 $m$ 次 `Find` 和 `Union` 操作：
       其最坏时间复杂度为严格的：
       $$T(m, n) = O(m \cdot \alpha(n))$$
       其中 $\alpha(n)$ 为**反阿克曼函数（Inverse Ackermann Function）**。
     - 对于现实宇宙中任何可能出现的规模（$n < 10^{80}$），$\alpha(n) \le 4$。因此在工程上，并查集单次操作的平均摊还时间复杂度可以视为严格的 **$O(1)$ 常数时间**。

### 考点 6.1：有向图的十字链表（Orthogonal List）结构
- **【考点定位】** 李冬梅《数据结构（第3版）》§6.4.3 十字链表（P183-P185）。
- **【核心数据结构与机制原理】**
  1. **十字链表的设计背景**：
     - 邻接表求出度容易但求入度难（需扫描全表）；逆邻接表求入度容易但求出度难。
     - 十字链表将**邻接表与逆邻接表完美整合在一套链表体系中**，是专门针对**有向图**的高效链式存储结构。
  2. **两类结点的严格 C 语言定义**：
     ```c
     #define MAX_VERTEX_NUM 20

     // 弧结点 (ArcNode)
     typedef struct ArcBox {
         int tailvex;               // 弧尾顶点位置 (弧从 tailvex 出发)
         int headvex;               // 弧头顶点位置 (弧指向 headvex)
         struct ArcBox *hlink;      // 弧头相同的下一条弧链域 (入边链表指针)
         struct ArcBox *tlink;      // 弧尾相同的下一条弧链域 (出边链表指针)
         InfoType *info;            // 弧的相关信息 (如权值)
     } ArcBox;

     // 顶点结点 (VexNode)
     typedef struct VexNode {
         VertexType data;           // 顶点数据
         ArcBox *firstin;           // 指向以该顶点为弧头的第一个弧结点 (入边表头)
         ArcBox *firstout;          // 指向以该顶点为弧尾的第一个弧结点 (出边表头)
     } VexNode;

     // 十字链表有向图
     typedef struct {
         VexNode xlist[MAX_VERTEX_NUM]; // 顶点表头向量
         int vexnum, arcnum;            // 顶点数与弧数
     } OLGraph;
     ```
  3. **出度与入度快速求法**：
     - **求顶点 $i$ 的出度（$\text{OD}(v_i)$）**：从 `xlist[i].firstout` 出发，沿 `tlink` 指针链扫描，弧结点的个数即为出度；
     - **求顶点 $i$ 的入度（$\text{ID}(v_i)$）**：从 `xlist[i].firstin` 出发，沿 `hlink` 指针链扫描，弧结点的个数即为入度。两者时间复杂度均为 $O(\text{度数})$，无需全图遍历。

### 考点 6.2：基于 DFS 后序遍历实现有向无环图的逆拓扑排序
- **【考点定位】** 李冬梅《数据结构（第3版）》§6.6.3 拓扑排序（P194-P197）。
- **【核心数据结构与机制原理】**
  1. **逆拓扑排序的数学定义**：
     - 在一个有向无环图（DAG）中，若存在一条从 $u$ 到 $v$ 的路径，则在序列中 $v$ 必须排在 $u$ 的前面。
  2. **DFS 后序遍历产生逆拓扑序列的数学证明**：
     - 在图的深度优先搜索过程中，当访问到某个顶点 $u$ 时，它会递归地深入遍历 $u$ 的所有邻接后继顶点。
     - **递归返回时机**：只有当以 $u$ 为起点的**所有能够到达的子孙后代顶点全部被 DFS 访问完毕并退出递归时**，关于顶点 $u$ 的递归调用才会结束返回！
     - 此时将顶点 $u$ 输出（后序输出），则 $u$ 的所有后继节点必然已经在它之前输出。因此，**在 DFS 退出时输出顶点，得到的序列严格构成逆拓扑排序序列**。
  3. **基于 DFS 的拓扑排序算法模板**：
     ```c
     void DFS_Topo(Graph G, int v, int visited[], Stack &S) {
         visited[v] = 1;
         for (int w = FirstAdjVex(G, v); w >= 0; w = NextAdjVex(G, v, w)) {
             if (!visited[w]) {
                 DFS_Topo(G, w, visited, S);
             }
         }
         Push(S, v); // 递归退出时压入栈中 (栈底为最先退出的逆拓扑元素)
     }
     ```
     - 遍历结束后，将栈 $S$ 中的元素依次弹出，出栈序列即为标准的**拓扑排序序列**。

### 考点 6.3：图的关节点（割点 Cut Vertex）与重连通分量的 DFS 判定算法
- **【考点定位】** 严蔚敏《数据结构》§7.5 图的连通性问题（教材经典选学）。
- **【核心数据结构与机制原理】**
  1. **关节点（割点, Cut Vertex）定义**：
     - 在连通无向图 $G$ 中，若删除顶点 $v$ 以及与 $v$ 关联的所有边后，图 $G$ 被分割为至少两个连通分量，则称 $v$ 为图的关节点。没有关节点的图称为**重连通图（双连通图）**。
  2. **DFS 生成树中的边分类与辅助数组**：
     - 从某个顶点出发进行深度优先遍历，图中的边被分为**树边（Tree Edge）**与**回边（Back Edge，指向祖先的边）**。
     - **`dfn[u]` 数组**：记录在 DFS 遍历过程中访问顶点 $u$ 的绝对时间戳（次序编号）。
     - **`low[u]` 数组**：定义为顶点 $u$ 或以 $u$ 为根的子树中的顶点，通过**至多一条回边**能够回溯到的**最高祖先（`dfn` 最小的顶点）的 `dfn` 值**。
  3. **`low[u]` 的递推数学公式**：
     $$\text{low}[u] = \min \begin{cases} \text{dfn}[u] \\ \text{low}[v], & (u, v) \text{ 为树边} \\ \text{dfn}[w], & (u, w) \text{ 为回边，且 } w \ne \text{parent}[u] \end{cases}$$
  4. **割点判定充要条件定理**：
     - **条件一（针对 DFS 根结点）**：若 DFS 生成树的根结点拥有 **2 棵或 2 棵以上的子树**，则根结点必定是关节点。
     - **条件二（针对非根结点 $u$）**：若 $u$ 的某个孩子结点 $v$ 满足：
       $$\text{low}[v] \ge \text{dfn}[u]$$
       则 $u$ 必定是关节点。（物理意义：以 $v$ 为根的子树没有任何跨越 $u$ 向上回退到 $u$ 祖先的回边，一旦删去 $u$，以 $v$ 为首的子树将被彻底孤立）。

### 考点 6.4：非连通图的深度优先生成森林与四类边的判定特征
- **【考点定位】** 李冬梅《数据结构（第3版）》§6.5 图的遍历（P187-P189）。
- **【核心数据结构与机制原理】**
  1. **生成森林的构建**：
     - 若无向图包含 $c\ (c > 1)$ 个连通分量，从每个连通分量任选一个顶点调用一次 DFS，最终将产生 $c$ 棵互不相交的 DFS 生成树，共同构成该非连通图的**深度优先生成森林（DFS Spanning Forest）**。
  2. **有向图 DFS 生成森林中的四类边体系（Tarjan / CLRS 分类）**：
     - **树边（Tree Edge）**：从父结点指向未访问孩子结点的边，构成了 DFS 生成树的主干结构。
     - **反向边（Back Edge / 回边）**：指向自身或 DFS 生成树中**某个祖先结点**的边。有向图中**存在反向边是图包含有向环（Cycle）的充要条件**！
     - **前向边（Forward Edge）**：指向 DFS 树中**某个后代非直接子结点**的非树边。
     - **横叉边（Cross Edge）**：连接同一棵树中无祖先后代关系的两个分支结点，或连接不同生成树结点的边（必须满足：源结点的 `dfn` 大于目标结点的 `dfn`）。

### 考点 7.1：分块查找最优子块长度的严格微分极值推导
- **【考点定位】** 李冬梅《数据结构（第3版）》§7.2.3 分块查找（P216-P218）。
- **【核心数据结构与机制原理】**
  1. **分块查找（Blocking Search / 索引顺序查找）模型**：
     - 将长度为 $n$ 的主表划分为 $b$ 个子块，每块含有 $s$ 个元素（满足 $n = b \cdot s$）。
     - **组织特性**：**块间有序，块内无序**（即第 $i+1$ 块中所有元素的关键字均大于第 $i$ 块中所有元素的最大关键字）。
     - **两级查找过程**：先在索引表中查找到目标元素所在的子块，再在对应的子块内部进行顺序扫描。
  2. **平均查找长度（ASL）公式建立**：
     - 设索引表和子块内部均采用顺序查找，且各元素查找概率均等：
       $$\text{ASL} = L_I + L_S = \frac{b + 1}{2} + \frac{s + 1}{2} = \frac{b + s}{2} + 1$$
     - 将 $b = \frac{n}{s}$ 代入上式，得到关于单块长度 $s$ 的连续函数：
       $$\text{ASL}(s) = \frac{\frac{n}{s} + s}{2} + 1$$
  3. **基于微分极值与基本不等式的最优块长证明**：
     - **方法一（均值不等式法）**：
       根据算术-几何均值不等式，当且仅当 $\frac{n}{s} = s$ 即 $s^2 = n$ 时，式中和项取得最小值：
       $$s = \sqrt{n}$$
     - **方法二（求导极值法）**：
       对 $\text{ASL}(s)$ 关于 $s$ 求一阶导数：
       $$\frac{d\ \text{ASL}}{ds} = \frac{1}{2} \left( -\frac{n}{s^2} + 1 \right)$$
       令导数等于零：$-\frac{n}{s^2} + 1 = 0 \implies s^2 = n \implies s = \sqrt{n}$。
     - **结论定理**：当每个子块的最优长度取 **$s = \sqrt{n}$**（即子块数 $b = \sqrt{n}$）时，分块查找的平均查找长度取得理论全局极小值：
       $$\text{ASL}_{\min} = \frac{\sqrt{n} + \sqrt{n}}{2} + 1 = \sqrt{n} + 1$$
     - 相比纯顺序查找的 $\frac{n+1}{2}$，查找效率实现平方根级别的巨大性能跃升。

### 考点 7.2：红黑树删除结点的平衡调整全景（双黑缺陷与 4 种旋转变色）
- **【考点定位】** 李冬梅《数据结构（第3版）》§7.3.3 红黑树（P229-P233）。
- **【核心数据结构与机制原理】**
  1. **待删结点的标准转化（转化为删除叶子/单子树结点）**：
     - 若待删结点有两个非空孩子，利用二叉排序树常规法则，用其**中序前驱（左子树最大值）**或**中序后继（右子树最小值）**的键值替代该结点，问题转化为删除前驱或后继结点（该结点最多只有 1 个孩子）。
  2. **双黑缺陷（Double Black）成因**：
     - 若被删除的结点为红色：直接删除，树中黑高不变，性质完全满足；
     - 若被删除的结点为黑色且有一个红孩子：用红孩子顶替并将其直接染黑即可；
     - **若被删除的结点为黑色叶子结点**：删除后导致该路径上的**黑高严格减少了 1**，破坏了红黑树性质 5（黑高平衡）。此时将该位置虚设为一个附加了黑色标记的空结点，称为**双黑结点（$x$）**。
  3. **消除双黑缺陷的 4 类兄弟子情况流转算法**：
     - **情况 1：$x$ 的兄弟结点 $w$ 为红色**：
       - **动作**：改变兄弟 $w$ 与父结点 $p$ 的颜色（$w$ 变黑，$p$ 变红），以父结点 $p$ 为支点做一次单旋转（左旋或右旋），将情况 1 转化为情况 2、3 或 4 继续处理。
     - **情况 2：$x$ 的兄弟结点 $w$ 为黑色，且 $w$ 的两个孩子全为黑色**：
       - **动作**：将兄弟 $w$ 染为红色，将双黑标记向上抽离转移给父结点 $p$（父结点吸收一层黑色）；若父结点原本为红，直接染黑结束；若父结点原本为黑，父结点成为新的双黑结点向上迭代。
     - **情况 3：$x$ 的兄弟结点 $w$ 为黑色，$w$ 的远端侄子为黑，近端侄子为红**：
       - **动作**：改变近侄子与兄弟 $w$ 的颜色（近侄子变黑，$w$ 变红），以 $w$ 为支点做反向单旋转，将情况 3 转化为情况 4。
     - **情况 4：$x$ 的兄弟结点 $w$ 为黑色，$w$ 的远端侄子为红色**：
       - **动作**：将兄弟 $w$ 染为父结点 $p$ 的原色，父结点 $p$ 染黑，远端侄子染黑；以父结点 $p$ 为支点做同向单旋转。**双黑标记彻底消解，调整成功终止**！

### 考点 7.3：二次探测法双向跳跃公式与覆盖半数散列地址充要条件
- **【考点定位】** 李冬梅《数据结构（第3版）》§7.4.3 处理冲突的方法（P237-P238）。
- **【核心数据结构与机制原理】**
  1. **二次探测法（平方探测法，Quadratic Probing）地址计算公式**：
     - 开放定址法中，发生冲突时的增量序列 $d_i$ 采用平方项双向跳跃：
       $$H_i = (H(\text{key}) + d_i) \bmod m$$
       其中增量序列严格规定为：
       $$d_i = 1^2, -1^2, 2^2, -2^2, \dots, q^2, -q^2 \quad (q \le \lfloor m/2 \rfloor)$$
     - **优势**：跳跃式跨步探测有效避免了线性探测法容易产生的“堆积/聚集（Clustering）”现象。
  2. **覆盖半数散列地址定理（数学充要条件）**：
     - **定理表述**：若散列表的长度 $m$ 是一个形如 **$4k + 3$ 的质数（素数）**（例如 $m = 7, 11, 19, 23, 31$ 等），则平方探测法计算出的前 $m - 1$ 个探测地址：
       $$(H(\text{key}) + 1^2) \bmod m,\ (H(\text{key}) - 1^2) \bmod m,\ \dots,\ (H(\text{key}) + q^2) \bmod m,\ (H(\text{key}) - q^2) \bmod m$$
       **互不相同，并且恰好能够遍历表中整整一半（严格等于 $\frac{m+1}{2}$ 个）不同的散列地址**。
     - **数学证明核心**：利用初等数论中二次剩余（Quadratic Residues）性质，当 $m \equiv 3 \pmod 4$ 时，$-1$ 是模 $m$ 的二次非剩余，确保正负平方项在模 $m$ 意义下绝不发生重合碰撞。

### 考点 7.4：再散列法（双重散列法 Double Hashing）探测序列计算公式
- **【考点定位】** 李冬梅《数据结构（第3版）》§7.4.3 处理冲突的方法（P238）。
- **【核心数据结构与机制原理】**
  1. **双重散列法（Double Hashing）的机制原理**：
     - 线性探测的步长固定为 1，二次探测的步长与关键字无关；而双重散列法**引入第二个辅助散列函数 $H_2(\text{key})$ 来动态决定每次冲突时的跳跃步长**。
  2. **探测序列严格计算公式**：
     $$H_i = \big(H_1(\text{key}) + i \cdot H_2(\text{key})\big) \bmod m \quad (i = 0, 1, 2, \dots, m-1)$$
     其中：
     - $H_1(\text{key})$ 是首选散列函数；
     - $H_2(\text{key})$ 是用于计算探测步长的辅助散列函数；
     - $i$ 是冲突碰撞次数。
  3. **辅助散列函数 $H_2(\text{key})$ 必须满足的两大数学铁律**：
     - **铁律一**：对任何关键字，**$H_2(\text{key})$ 的返回值绝不能为 0**（若步长为 0，公式变为 $H_i = H_1(\text{key}) \bmod m$，算法将陷入无限自旋死循环）。
     - **铁律二**：**$H_2(\text{key})$ 的返回值必须与散列表长度 $m$ 互质（$\gcd(H_2(\text{key}), m) = 1$）**。
       - *数学依据*：若不互质，生成的剩余系无法遍历模 $m$ 的全排列，探测点将退化并在极小的子环内死循环，无法探测到全表的空闲槽位。
       - *常用构造形式*：取 $m$ 为质数，定义 $H_2(\text{key}) = R - (\text{key} \bmod R)$，其中 $R < m$ 为略小于 $m$ 的质数。

### 考点 7.5：B+ 树双重查找路径与磁盘 I/O 差异机制
- **【考点定位】** 李冬梅《数据结构（第3版）》§7.3.5 B+ 树（P235-P237）。
- **【核心数据结构与机制原理】**
  1. **B+ 树的核心物理组织规范**：
     - **非叶结点（内部索引结点）**：**只存储关键字和子树指针，绝不存储任何实际记录数据或数据磁盘物理地址**。
     - **叶子结点**：**集中存放全部关键字及指向记录的指针**，且所有叶子结点按关键字升序排布，通过**双向链表首尾指针相互串联**。
  2. **双重查找路径实现**：
     - **路径一：从根向下多路分支查找（单点检索）**：
       - 从根结点出发，逐层在内部结点中通过折半或顺序比对确定子树分支指针向下递进，直到达到叶子结点；
       - 无论查找成功还是失败，单点检索**必须一路走到最底层的叶子结点层才能判定**（B 树若在根或高层内部结点匹配成功可提前退出，B+ 树则必须走完完整树高 $h$ 层）；
       - 磁盘 I/O 次数严格固定等于树的高度 $h$。
     - **路径二：沿叶结点双向链表顺序扫描（范围查找 Range Query）**：
       - 当执行范围查询（如查找关键字在 $[K_1, K_2]$ 之间的所有记录）时：
         ① 仅利用路径一从根向下检索一次，**精确定位到 $K_1$ 所在的第一个叶子结点**；
         ② 此后**完全不需要再回溯访问任何高层非叶结点**，直接**沿着叶子结点的双向链表横向顺序向右单向扫描遍历**，直至遇到大于 $K_2$ 的记录为止。
       - 大幅减少磁盘臂机械寻道与旋转延迟，这是现代数据库索引（如 MySQL InnoDB）全面采用 B+ 树而非 B 树的根本技术基石。

### 考点 8.1：树形选择排序（锦标赛排序 Tournament Sort）算法与空间开销
- **【考点定位】** 李冬梅《数据结构（第3版）》§8.4.2 树形选择排序（P299-P301）。
- **【核心数据结构与机制原理】**
  1. **简单选择排序的性能瓶颈**：
     - 简单选择排序每一趟通过 $n-1$ 次比较选出最小值，但第二趟又把之前的比较结果全部丢弃重新比较，包含了大量冗余比较，时间复杂度被锁死在 $O(n^2)$。
  2. **锦标赛排序的满二叉树模型**：
     - 借鉴体育比赛锦标赛胜者晋级思想。
     - 将待排序的 $n$ 个记录作为一棵满二叉树的**叶子结点**。
     - 两两进行关键字比较，较小者（胜者）上升一层作为父结点；反复两两对决，直到根结点产生出全局最小关键字。
  3. **胜者重构循环算法时序**：
     - 取得根结点的最小值输出到有序序列中；
     - 将该最小值对应的**叶子结点的关键字修改为正无穷大（$\infty$）**；
     - 仅需**沿着该叶子结点到根结点的唯一祖先路径**，重新进行 $\lceil \log_2 n \rceil$ 次两两对决比较，即可快速更新产生次小值。
     - 重复此过程 $n-1$ 次，完成全部排序。
  4. **时间与空间复杂度推导**：
     - **时间复杂度**：建树耗时 $O(n)$，后续每次选拔耗时 $O(\log_2 n)$，总时间复杂度为严格的 **$O(n \log_2 n)$**。
     - **空间复杂度（致命缺陷）**：为了维护这棵完整的竞赛二叉树，必须额外开辟包含叶子与内部结点的数组空间，所需辅助存储空间为 **$O(n)$**（严格为 $2n - 1$ 个单元），同时与无穷大 $\infty$ 的比较增加了算法常数开销。正因这一空间缺陷，后续演化出了在原数组原地调整、辅助空间 $O(1)$ 的堆排序。

### 考点 8.2：链式基数排序的静态链表指针分配与收集时序
- **【考点定位】** 李冬梅《数据结构（第3版）》§8.6.2 链式基数排序（P305-P308）。
- **【核心数据结构与机制原理】**
  1. **存储结构设计**：
     - 待排记录采用**静态单链表（带 `next` 指针游标的数组）**存储，彻底避免排序过程中发生任何实际数据记录的物理移动，全部通过指针连接完成。
  2. **队列辅助指针数组**：
     - 设基数为 $r$（十进制数 $r = 10$，字符 $r = 26$）。
     - 设置两个指针数组：
       - `head[0 ... r-1]`：指示各个桶队列的**队头结点**；
       - `tail[0 ... r-1]`：指示各个桶队列的**队尾结点**。
  3. **低位优先（LSD）分配与收集指针变换全流程**：
     - 对关键字由低位向高位进行 $d$ 趟迭代：
       - **第一阶段：分配（Distribution）**：
         从静态链表首结点出发扫描，取出记录当前位数字 $k$：
         - 若 `head[k] == NULL`（桶空）：则 `head[k] = p; tail[k] = p;`
         - 若 `head[k] != NULL`：挂接在队尾并更新指针：`tail[k]->next = p; tail[k] = p;`
       - **第二阶段：收集（Collection）**：
         将 $r$ 个桶队列按 $0 \dots r-1$ 的顺序重新串联成一条单一的长链表：
         - 寻找第一个非空的桶队列 $j$，使整个链表的表头指向 `head[j]`；
         - 遍历后续桶：只要遇到下一个非空桶 $k$，将前一个非空桶的队尾与当前桶队头相连：
           ```c
           tail[prev]->next = head[k];
           prev = k;
           ```
         - 最后一个非空桶的队尾指针置空：`tail[last]->next = NULL;`
     - **时空复杂度**：每一趟分配耗时 $O(n)$，收集耗时 $O(r)$，总共经历 $d$ 趟。总时间复杂度严格为 **$O(d(n + r))$**；辅助空间仅需 $2r$ 个队列头尾指针，空间复杂度为 **$O(r)$**。

### 考点 8.3：外部排序中败者树（Loser Tree）重构算法与父结点败者存储
- **【考点定位】** 李冬梅《数据结构（第3版）》§8.7.2 多路平衡归并的实现（P310-P314）。
- **【核心数据结构与机制原理】**
  1. **胜者树与败者树的结构差异**：
     - 在 $k$ 路平衡归并中，为了在 $k$ 个输入归并段的首元素中挑选出最小者，采用完全二叉树进行竞赛。
     - **胜者树**：每个非叶内部结点记录的是该场对决的“胜利者（较小者）”。重构时，新选手的比较必须与其兄弟结点进行，必须跨指针寻找兄弟结点，寻址路径不便。
     - **败者树（Loser Tree）**：**非叶内部结点记录的是该场对决的“失败者（较大者）”的段号；而胜利者则继续向上前进，去与上一层的父结点中保存的历史记录进行下一轮比赛**！
  2. **败者树的数据结构定义**：
     - `b[0 ... k-1]`：叶子结点数组，存储 $k$ 个归并段当前待比较的记录关键字；
     - `ls[0 ... k-1]`：非叶内部结点数组，其中 **`ls[1 ... k-1]` 存储败者的归并段号**；
     - 特别地，**`ls[0]` 专门用于存储整棵树的全局最终冠军（绝对胜者）**。
  3. **败者树重构算法执行时序**：
     - 设当前全局最小记录出自段号 $s$（即 `ls[0] == s`），该记录输出至外部存储；
     - 从段 $s$ 读取下一个新记录填入 `b[s]`。此时只需要对段 $s$ 这一路进行向上重构：
       ```c
       void Adjust(int ls[], int b[], int s, int k) {
           int t = (s + k) / 2; // t 指向当前叶子结点的双亲结点在 ls 中的下标
           while (t > 0) {
               // 将当前胜者 b[s] 与父结点记录的历史败者 b[ls[t]] 比较
               if (b[s] > b[ls[t]]) {
                   // 若当前选手变大成为败者，交换两者角标: 当前段留下作为败者，原败者变为胜者继续向上冲
                   int temp = s;
                   s = ls[t];
                   ls[t] = temp;
               }
               t = t / 2; // 沿父结点指针单向直奔根部
           }
           ls[0] = s; // 最终胜者存入 ls[0]
       }
       ```
     - **比较次数优化定理**：败者树重构时，指针始终单向沿直线上升，无需访问任何兄弟结点，每次替换一个元素选出全局最小值**严格只需要进行 $\lceil \log_2 k \rceil$ 次比较**。

### 考点 8.4：最佳归并树添加虚段的判定准则公式推导
- **【考点定位】** 李冬梅《数据结构（第3版）》§8.7.4 最佳归并树（P316-P319）。
- **【核心数据结构与机制原理】**
  1. **最佳归并树（Optimal Merge Tree）的数学本质**：
     - 外部排序中，若有 $r$ 个初始归并段，进行 $k$ 路平衡归并。为了使全过程外存 I/O 读写总量达到最小，应将归并过程组织为一棵**带权路径长度 WPL 最小的 $k$ 叉哈夫曼树**。
  2. **严格 $k$ 叉树的度数平衡方程**：
     - 设一棵严格的 $k$ 叉树包含 $n_0$ 个叶子结点（即初始归并段数 $r$），$n_k$ 个度为 $k$ 的分支结点，其余分支度结点个数为 0。
     - 根据树的结点总数与分支度数守恒定律：
       $$\text{总度数} = k \cdot n_k = \text{总结点数} - 1 = (n_0 + n_k) - 1$$
       化简移项得：
       $$(k - 1) \cdot n_k = n_0 - 1 = r - 1$$
       从而得出整除约束定理：
       $$n_k = \frac{r - 1}{k - 1}$$
     - **物理约束**：因为内部度为 $k$ 的分支结点数 $n_k$ 必须是正整数，所以**归并段数量 $r$ 必须满足：$(r - 1) \bmod (k - 1) == 0$**！
  3. **虚段（Dummy Run）添加准则公式**：
     - 若给定的初始归并段数 $r$ 不满足整除条件，即 **$(r - 1) \bmod (k - 1) \ne 0$**：
       说明归并的第一趟无法凑满 $k$ 个有效分支，会导致最后一趟归并产生不充分分支，严重恶化总 I/O 开销。
     - **补虚段规则**：必须在初始输入中人为**补充长度（权值）为 0 的虚归并段**，将其充当叶子结点参与哈夫曼建树。
     - **补充虚段个数的严格计算公式**：
       $$\text{虚段数 } m = (k - 1) - \big((r - 1) \bmod (k - 1)\big)$$
     - **实战示例演算**：
       设进行 3 路平衡归并（$k = 3$），初始归并段数 $r = 8$：
       计算模数：$(8 - 1) \bmod (3 - 1) = 7 \bmod 2 = 1 \ne 0$。
       代入公式：需补充虚段数为 $(3 - 1) - 1 = 1$ 个。
       补入 1 个权值为 0 的虚段后，有效归并段数变为 $8 + 1 = 9$ 个，满足 $(9 - 1) \bmod 2 = 0$，第一趟取最小的两个段和 1 个虚段合并，构造出严格最优的 3 叉最佳归并树。
